## cpp-q-214
ticket: cpp-t-022 · level: L1
Скомпилируется ли код? Что будет вызвано через `B&`?
```cpp
#include <iostream>
struct B { virtual void f() const { std::cout << "B"; } };
struct D : B { void f() override { std::cout << "D"; } };
int main() { D d; B& b = d; b.f(); }
```
### Эталон
- Код не компилируется: `D::f()` без `const` не переопределяет `B::f() const`, поэтому `override` некорректен.
- Для переопределения cv-квалификаторы функции должны совпадать; при удалении `const` из `D::f` вызов через `B&` напечатает `D`.
- Виртуальный вызов выбирает переопределение по динамическому типу объекта, если сигнатура действительно переопределена.

## cpp-q-215
ticket: cpp-t-023 · level: L0
Что такое чисто виртуальная функция и абстрактный класс?
### Эталон
- Чисто виртуальную функцию объявляют с `= 0`, например `virtual void f() = 0;`.
- Класс абстрактен, если хотя бы одна виртуальная функция имеет чистый final overrider; такой переопределитель может быть унаследован.
- Нельзя создать объект абстрактного класса, но можно объявлять указатели и ссылки на него.
- Виртуальный деструктор базового класса нужен для корректного удаления производного объекта через указатель на базовый класс.

## cpp-q-216
ticket: cpp-t-023 · level: L1
Скомпилируется ли `B b`? Скомпилируется ли создание `D`?
```cpp
struct B { virtual void f() = 0; };
struct D : B { void f() override {} };
int main() { D d; }
```
### Эталон
- `B b` не компилировалось бы: `B` абстрактен из-за чисто виртуальной `f`.
- Код компилируется, поскольку `D` переопределяет `f` и становится конкретным классом.
- Можно создать объект `D`; его вызов `f()` использует `D::f`.

## cpp-q-217
ticket: cpp-t-024 · level: L0
Что делают `throw` и `try`/`catch`? Что означает раскрутка стека?
### Эталон
- `throw` начинает поиск обработчика для брошенного объекта исключения.
- `try` задаёт блок, исключения из которого могут обрабатываться следующими подходящими обработчиками `catch`.
- При раскрутке стека уничтожаются полностью сконструированные автоматические объекты покидаемых областей в обратном порядке их завершённой инициализации.
- Если подходящий обработчик не найден, вызывается `std::terminate`.

## cpp-q-218
ticket: cpp-t-025 · level: L0
Что означает совместное владение ресурсом в `std::shared_ptr` и когда полезен `std::weak_ptr`?
### Эталон
- Копии `std::shared_ptr<T>` разделяют владение одним объектом и учитываются общим счётчиком владельцев.
- Объект уничтожается, когда уничтожен или сброшен последний владеющий `shared_ptr`.
- `std::weak_ptr<T>` наблюдает за объектом, управляемым `shared_ptr`, но не увеличивает число владельцев; через `lock()` можно получить `shared_ptr`, если объект ещё жив.
- `weak_ptr` подходит для невладеющих ссылок и разрыва циклов совместного владения.
