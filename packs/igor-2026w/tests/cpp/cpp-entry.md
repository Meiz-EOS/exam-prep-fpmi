## cpp-q-003
ticket: cpp-t-004 · level: L0
Что напечатает программа? Объясните значение `&&` и короткое замыкание.
```cpp
#include <iostream>
int main() {
    int x = 0;
    if (x != 0 && 10 / x > 1) std::cout << "yes";
    else std::cout << "no";
}
```
### Эталон
- Вывод: `no`.
- `&&` сначала вычисляет левый операнд.
- При ложном левом операнде правый операнд не вычисляется, деления на ноль нет.

## cpp-q-002
ticket: cpp-t-006 · level: L0
Различите CE, RE и UB. К какому случаю относится выход за границы массива?
### Эталон
- CE — программа не проходит проверку языка/компиляцию.
- RE — ошибка во время выполнения с определённым поведением программы/среды (аварийное завершение).
- UB — стандарт C++ не задаёт требований к поведению программы; выход за границы встроенного массива — именно UB, а не гарантированная ошибка.

## cpp-q-033
ticket: cpp-t-003 · level: L1
В программе из одного файла функция объявлена, но нигде не определена. На какой стадии сборки возникнет ошибка и почему?
```cpp
void f();
int main() { f(); }
```
### Эталон
- Компиляция проходит: для вызова достаточно объявления (компилятору нужна только сигнатура).
- Ошибка на стадии компоновки: `undefined reference to f()`.
- Определение (тело функции) должно быть ровно одно во всей программе; здесь его нет ни в одном объектном файле.

## cpp-q-005
ticket: cpp-t-009 · level: L0
Определите, скомпилируется ли код и что он печатает.
```cpp
#include <iostream>
int main() {
    int a[] = {4, 7, 9};
    int* p = a;
    std::cout << 1[a] << ' ' << *(p + 2);
}
```
### Эталон
- Код компилируется.
- Вывод: `7 9`.
- Индексация `x[y]` определена как `*(x + y)`, поэтому `1[a]` эквивалентно `a[1]`.

## cpp-q-034
ticket: cpp-t-008 · level: L1
Что не так с этой программой?
```cpp
#include <iostream>
int* make() {
    int x = 42;
    return &x;
}
int main() {
    int* p = make();
    std::cout << *p;
}
```
### Эталон
- `x` — автоматическая (стековая) переменная: её время жизни кончается при выходе из `make`.
- `p` — висячий указатель; разыменование `*p` — UB (код при этом компилируется, максимум с предупреждением).
- Исправление: вернуть значение, либо использовать статическую или динамическую память.

## cpp-q-035
ticket: cpp-t-012 · level: L0
Какие из помеченных строк не скомпилируются и почему?
```cpp
int a = 1, b = 2;
const int* p = &a;
*p = 5;   // (1)
p = &b;   // (2)
int* const q = &a;
*q = 5;   // (3)
q = &b;   // (4)
```
### Эталон
- Не компилируются (1) и (4).
- `const int* p` — указатель на константу: нельзя менять объект через `p`, но сам `p` можно перенаправить.
- `int* const q` — константный указатель: объект менять можно, перенаправить `q` нельзя.

## cpp-q-036
ticket: cpp-t-015 · level: L1
Какое из трёх объявлений в `main` не скомпилируется и почему?
```cpp
struct P {
    int x;
    P(int v) : x(v) {}
};
int main() {
    P a;
    P b(1);
    P c = 2;
}
```
### Эталон
- Не компилируется `P a;`: нужен конструктор по умолчанию, а его нет.
- Компилятор не генерирует конструктор по умолчанию, если в классе объявлен хотя бы один пользовательский конструктор.
- `P b(1)` и `P c = 2` корректны: оба вызывают `P(int)` (во втором случае — как неявное преобразование, так как конструктор не `explicit`).

## cpp-q-037
ticket: cpp-t-017 · level: L0
Какой из двух вызовов не скомпилируется и почему?
```cpp
struct S {
    int x;
    int get() const { return x; }
    void set(int v) { x = v; }
};
int main() {
    const S s{1};
    s.get();
    s.set(2);
}
```
### Эталон
- Не компилируется `s.set(2)`: у константного объекта можно вызывать только константные методы.
- `const` после списка параметров делает `this` указателем на `const S`, поэтому `get` менять поля не может и разрешён для `const`-объекта.
- `set` не помечен `const` (и меняет поле), поэтому для `const S` недоступен.

## cpp-q-010
ticket: cpp-t-016 · level: L1
Скомпилируется ли код? Какое значение получает `b.p`?
```cpp
struct Box {
    int* p;
    Box(int x) : p(new int(x)) {}
    ~Box() { delete p; }
};
int main() {
    Box a(1);
    Box b = a;
}
```
### Эталон
- Код компилируется: неявный конструктор копирования копирует указатель.
- `a.p` и `b.p` указывают на один объект `int`.
- При выходе из области оба деструктора удалят один адрес — это UB (двойное освобождение); по правилу трёх нужны свои конструктор копирования и оператор присваивания (или их запрет).

## cpp-q-022
ticket: cpp-t-038 · level: L1
Что напечатает программа и зачем `operator+=` возвращает `Box&`?
```cpp
#include <iostream>
struct Box {
    int value;
    Box& operator+=(int x) { value += x; return *this; }
};
int main() {
    Box b{1};
    (b += 2) += 3;
    std::cout << b.value;
}
```
### Эталон
- Вывод: `6`.
- `b += 2` — вызов перегруженного оператора `b.operator+=(2)`: он меняет `value` и возвращает ссылку на сам объект `*this`.
- Благодаря возврату по ссылке второе `+=` применяется к тому же `b`; при возврате по значению изменилась бы временная копия, и вывелось бы `3`.

## cpp-q-021
ticket: cpp-t-034 · level: L1
Определите, есть ли UB, и укажите правильную пару освобождения.
```cpp
int main() {
    int* p = new int[3];
    delete p;
}
```
### Эталон
- Есть UB: память массива выделена выражением `new[]`, а освобождается одиночным `delete`.
- Следует использовать `delete[] p`.
- Для одиночного `new T` используется `delete`.

## cpp-q-039

Что напечатает программа?
```cpp
#include <iostream>
struct B {
    B() { std::cout << "B"; }
    ~B() { std::cout << "~B"; }
};
struct D : B {
    D() { std::cout << "D"; }

int main() { D d; }
```
### Эталон
- Вывод: `BD~D~B`.

## cpp-q-040
ticket: cpp-t-041 · level: L1
Что напечатает программа и почему?
```cpp
#include <iostream>
struct B { void f(int) { std::cout << "B"; } };
struct D : B { void f(double) { std::cout << "D"; } };
int main() { D d; d.f(1); }
```
### Эталон
- Вывод: `D`.
- Имя `f` в наследнике скрывает все одноимённые методы родителя: поиск имени останавливается в `D`, и перегрузка выбирается только среди `D::f`.
- Чтобы участвовала и `B::f(int)`, нужно `using B::f;` в `D` или явный вызов `d.B::f(1)`.

## cpp-q-041
ticket: cpp-t-020 · level: L1
Скомпилируется ли вызов? Если нет — почему и как исправить?
```cpp
template<class T>
T max_of(T a, T b) { return a < b ? b : a; }
int main() { max_of(1, 2.5); }
```
### Эталон
- Не компилируется: по первому аргументу выводится `T = int`, по второму — `T = double`, вывод противоречив.
- При выводе аргументов шаблона неявные преобразования (`int` в `double`) не применяются.
- Исправление: указать аргумент явно — `max_of<double>(1, 2.5)` — или привести аргументы к одному типу.

## cpp-q-042
ticket: cpp-t-043 · level: L1
Скомпилируется ли код? Если нет — в чём причина?
```cpp
struct A { int x; };

struct D : B, C {};

```
### Эталон
- Не компилируется: обращение `d.x` неоднозначно.

- Исправление: уточнить путь (`d.B::x`) либо наследовать `A` виртуально в `B` и `C`, тогда подобъект `A` один.

## cpp-q-043

```cpp
struct A { A(int v) { std::cout << v; } };
```

## cpp-q-044
ticket: cpp-t-026 · level: L0
Сравните `std::vector` и `std::list` по двум операциям: доступ к элементу по индексу и вставка в середину по уже имеющемуся итератору.
### Эталон
- `vector` — непрерывный динамический массив: доступ по индексу за $O(1)$, вставка в середину за $O(n)$ (сдвиг хвоста).
- `list` — двусвязный список: вставка по итератору за $O(1)$.
- У `list` нет `operator[]`: до $i$-го элемента нужно идти за $O(n)$.

## cpp-q-045
ticket: cpp-t-027 · level: L1
Скомпилируется ли код? Если нет — почему?
```cpp
#include <algorithm>
#include <list>
int main() {
    std::list<int> l{3, 1, 2};
    std::sort(l.begin(), l.end());
}
```
### Эталон
- Не компилируется.

- Для списка есть собственный метод `l.sort()`.

## cpp-q-046
ticket: cpp-t-030 · level: L0
Что напечатает программа и почему?
```cpp
#include <iostream>
int main() {
    int n = 1;
    auto a = [n] { return n; };
    auto b = [&n] { return n; };
    n = 5;
    std::cout << a() << b();
}
```
### Эталон
- Вывод: `15`.
- `[n]` — захват по значению: копия `n` делается в момент создания лямбды, поэтому `a()` возвращает `1`.
- `[&n]` — захват по ссылке: лямбда видит текущее значение `n`, поэтому `b()` возвращает `5`.

## cpp-q-047

Скомпилируется ли вторая строка? Если нет — почему и как передать владение?

- Не компилируется (3): инициализатор `constexpr`-переменной должен быть константным выражением, а `n` известно только во время выполнения.
- (1) корректна: `sq(3)` вычисляется при компиляции.
- (2) корректна: `constexpr`-функцию можно вызывать и с обычными аргументами — тогда она выполняется во время выполнения.

## cpp-q-051
ticket: cpp-t-055 · level: L1
Что не так с этим кодом? Считайте, что перед `push_back` выполнено `v.capacity() == v.size()`.

```cpp
#include <iostream>
#include <vector>
```

## cpp-q-052
ticket: cpp-t-065 · level: L1
Почему при реаллокации `std::vector` перемещает элементы, только если их перемещающий конструктор `noexcept`, а иначе копирует?
### Эталон
- `push_back` даёт строгую гарантию безопасности: при исключении вектор остаётся в исходном состоянии.

## cpp-q-055
ticket: cpp-t-060 · level: L0
Зачем контейнеру аллокатор, если в языке уже есть `new` и `delete`?
### Эталон
- `new` и `delete` склеивают выделение памяти с созданием объекта; аллокатор разделяет их: `allocate`/`deallocate` — сырая память, `construct`/`destroy` — объекты.
- Контейнеру это необходимо: например, `vector::reserve` держит память под `capacity`, в которой объектов ещё нет.
- Аллокатор — параметр шаблона контейнера, поэтому стратегию памяти можно заменить (пул, стек) без изменения контейнера.

## cpp-q-056
ticket: cpp-t-084 · level: L1
Что по шагам делает выражение `new T(args)` и чем оно отличается от функции `operator new`?
### Эталон
- Сначала вызывается функция `operator new(sizeof(T))`: она только выделяет сырую память (именно её можно перегрузить).
- Затем в этой памяти вызывается конструктор `T(args)`; результат — указатель `T*`.
- Если конструктор бросил исключение, память освобождается соответствующим `operator delete`, и исключение летит дальше.

## cpp-q-057
ticket: cpp-t-092 · level: L1
Как `std::any`, не будучи шаблоном, хранит значение произвольного типа? Опишите идею type erasure.
### Эталон
- Внутри `any` — указатель на нешаблонный базовый класс с виртуальными функциями (уничтожить, скопировать, узнать тип).

## cpp-q-058
ticket: cpp-t-093 · level: L1
Что напечатает программа и почему, хотя деструктор `B` не виртуальный?
```cpp
#include <iostream>
#include <memory>
struct B { ~B() { std::cout << "~B"; } };
struct D : B { ~D() { std::cout << "~D"; } };
int main() { std::shared_ptr<B> p = std::make_shared<D>(); }
```
### Эталон
- Вывод: `~D~B`.
- Способ удаления запоминается в блоке управления в момент создания, когда настоящий тип `D` ещё известен (type erasure делетера).

ticket: cpp-t-068 · level: L1
Что напечатает программа и почему нет ошибки компиляции?
```cpp
#include <iostream>
template<class T>
auto f(T t) -> decltype(t.size()) { return t.size(); }
int f(...) { return -1; }
int main() { std::cout << f(5); }
```
### Эталон
- Вывод: `-1`.

## cpp-q-060

Как устроен `std::enable_if<B, T>` и за счёт чего он «выключает» перегрузку шаблонной функции?
### Эталон

Какой из вызовов `f(1)` и `f(1.5)` скомпилируется (C++20)? Объясните проверку ограничения.
```cpp

template<class T>
    requires std::integral<T>
int f(T) { return 1; }
```
### Эталон

## cpp-q-061
ticket: cpp-t-099 · level: L1
Какой из двух вызовов не скомпилируется и почему?
```cpp
template<class T>
concept Addable = requires(T a, T b) { a + b; };
template<Addable T>
T sum(T a, T b) { return a + b; }
struct S {};
int main() {
    sum(1, 2);
    sum(S{}, S{});
}
```
### Эталон
- Не компилируется `sum(S{}, S{})`: `S` не удовлетворяет концепту `Addable`.
- `requires`-выражение проверяет только корректность `a + b` (ничего не вычисляя); для `S` оператора `+` нет, значит концепт ложен.
- Функция с невыполненным ограничением не участвует в перегрузке: ошибка возникает в точке вызова, а не внутри тела `sum`.

## cpp-q-063
ticket: cpp-t-089 · level: L1
Что обозначает `[k, v]` в цикле и изменится ли `m` после него?
```cpp
#include <map>
#include <string>
int main() {
    std::map<int, std::string> m{{1, "a"}, {2, "b"}};
    for (auto& [k, v] : m) v += "!";
}
```
### Эталон
- Это structured binding (C++17): элемент `std::pair<const int, std::string>` раскладывается на имена `k` (`first`) и `v` (`second`).
- Из-за `auto&` имена относятся к самому элементу контейнера, поэтому значения в `m` изменятся (`"a!"`, `"b!"`).
- Ключ `k` имеет тип `const int` — изменить его нельзя.
