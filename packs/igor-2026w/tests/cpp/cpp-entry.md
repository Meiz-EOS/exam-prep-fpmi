## cpp-q-001
ticket: cpp-t-001 · level: L0
Перечислите стадии сборки C++ программы и укажите, что получается после каждой.
### Эталон
- Препроцессор обрабатывает директивы и включения заголовков.
- Компилятор переводит единицу трансляции в объектный файл.
- Ассемблер обычно входит в компиляцию и получает машинный код объекта.
- Компоновщик связывает объектные файлы и библиотеки в исполняемый файл.

## cpp-q-002
ticket: cpp-t-006 · level: L0
Различите CE, RE и UB. К какому случаю относится выход за границы массива?
### Эталон
- CE — программа не проходит проверку языка/компиляцию.
- RE — ошибка во время выполнения с определённым поведением программы/среды.
- UB — стандарт C++ не задаёт требований к поведению программы.
- Выход за границы встроенного массива при чтении — UB, а не гарантированная ошибка.

## cpp-q-003
ticket: cpp-t-004 · level: L0
Что напечатает программа? Объясните значение `&&` и короткое замыкание.
```cpp
#include <iostream>
int main() {
    int x = 0;
    if (x != 0 && 10 / x > 1) std::cout << "yes";
    else std::cout << "no";
}
```
### Эталон
- Вывод: `no`.
- `&&` сначала вычисляет левый операнд.
- При ложном левом операнде правый операнд не вычисляется, деления на ноль нет.

## cpp-q-004
ticket: cpp-t-007 · level: L0
Что выведет программа и почему разность указателей допустима?
```cpp
#include <iostream>
int main() {
    int a[4]{};
    int* p = &a[1];
    int* q = &a[3];
    std::cout << q - p;
}
```
### Эталон
- Вывод: `2`.
- Разность указателей на элементы одного массива измеряется в элементах, а не байтах.
- Указатели принадлежат одному массиву; результат имеет тип `std::ptrdiff_t`.

## cpp-q-005
ticket: cpp-t-009 · level: L0
Определите, скомпилируется ли код и что он печатает.
```cpp
#include <iostream>
int main() {
    int a[] = {4, 7, 9};
    int* p = a;
    std::cout << 1[a] << ' ' << *(p + 2);
}
```
### Эталон
- Код компилируется.
- Вывод: `7 9`.
- Индексация `x[y]` определена как `*(x + y)`, поэтому `1[a]` эквивалентно `a[1]`.

```cpp
#include <iostream>
```

## cpp-q-008
ticket: cpp-t-013 · level: L1
Скомпилируется ли код? Если нет, укажите причину.
```cpp
int main() {
    const int x = 1;
    int* p = const_cast<int*>(&x);
    *p = 2;
}
```
### Эталон
- Код компилируется.
- Изменение объекта, который изначально объявлен `const`, через снятую константность даёт UB.
- `const_cast` сам по себе не делает изменение допустимым.

## cpp-q-009
ticket: cpp-t-015 · level: L1
Укажите порядок вывода и объясните порядок инициализации членов.
```cpp
#include <iostream>
struct A {
    int x;
    int y;
    A() : y(2), x(y + 1) { std::cout << x << ' ' << y; }
};
int main() { A a; }
```
### Эталон
- Порядок инициализации задаётся порядком объявления: сначала `x`, затем `y`.
- При вычислении `x(y + 1)` поле `y` ещё не инициализировано.
- Использование неинициализированного `y` здесь даёт неопределённое поведение; численный вывод не определён.

## cpp-q-010
ticket: cpp-t-016 · level: L1
Скомпилируется ли код? Какое значение получает `b.p`?
```cpp
struct Box {
    int* p;
    Box(int x) : p(new int(x)) {}
    ~Box() { delete p; }
};
int main() {
    Box a(1);
    Box b = a;
}
```
### Эталон
- Код компилируется: неявный конструктор копирования копирует указатель.
- `a.p` и `b.p` указывают на один объект `int`.
- При выходе из области оба деструктора удалят один адрес — это UB (двойное освобождение).
- Нужна собственная семантика копирования либо запрет копирования/владение умным указателем.

## cpp-q-011
ticket: cpp-t-018 · level: L1
Что будет напечатано? Почему вызов виртуальной функции из конструктора имеет такой результат?
```cpp
#include <iostream>
struct B {
    B() { f(); }
    virtual void f() { std::cout << "B"; }
};
struct D : B {
    void f() override { std::cout << "D"; }
};
int main() { D d; }
```
### Эталон
- Вывод: `B`.
- Во время выполнения конструктора `B` виртуальный вызов диспетчеризуется в пределах уже конструируемой части `B`.
- Переопределение `D::f` не вызывается из конструктора базового класса.

## cpp-q-012
ticket: cpp-t-022 · level: L0
Что напечатает программа при вызове через ссылку на базовый класс?
```cpp
#include <iostream>
struct B { virtual void f() { std::cout << "B"; } };
struct D : B { void f() override { std::cout << "D"; } };
int main() { D d; B& b = d; b.f(); }
```
### Эталон
- Вывод: `D`.
- `f` — виртуальная функция.
- Выбор переопределения происходит по динамическому типу объекта (`D`), а не статическому типу ссылки (`B&`).

## cpp-q-013
ticket: cpp-t-024 · level: L1
Какой обработчик выполнится и какие локальные объекты будут уничтожены?
```cpp
#include <iostream>
struct G { ~G() { std::cout << "G"; } };
int main() {
    try { G g; throw 1; }
    catch (double) { std::cout << "D"; }
    catch (int) { std::cout << "I"; }
}
```
### Эталон
- Вывод: `GI`.
- При раскрутке стека уничтожается локальный `g`, поэтому печатается `G`.
- Выбирается обработчик `catch (int)`, соответствующий типу брошенного значения.

## cpp-q-014

Почему этот код безопасен при исключении из `work`? Назовите механизм.
```cpp
#include <memory>
void work();
int main() {
    auto p = std::make_unique<int>(42);
    work();
}
```
### Эталон
- `p` владеет выделенным объектом через `std::unique_ptr`.
- При нормальном выходе или раскрутке стека деструктор `p` освобождает объект.
- Это RAII: ресурс привязан к времени жизни автоматического объекта.

## cpp-q-017


- Перегрузка `X(X&&)` выбирается как наиболее подходящая для полученного xvalue.

## cpp-q-019
ticket: cpp-t-030 · level: L1
Скомпилируется ли код и что напечатает второй вызов лямбды?
```cpp
#include <iostream>
int main() {
    int n = 1;
    auto f = [n]() mutable { std::cout << ++n; };
    f(); f();
    std::cout << ' ' << n;
}
```
### Эталон
- Код компилируется; вывод: `23 1`.
- Захват `[n]` хранит копию `n` внутри замыкания.
- `mutable` разрешает менять захваченную копию; внешняя переменная остаётся равной `1`.

## cpp-q-021
ticket: cpp-t-034 · level: L1
Определите, есть ли UB, и укажите правильную пару освобождения.
```cpp
int main() {
    int* p = new int[3];
    delete p;
}
```
### Эталон
- Есть UB: память массива выделена выражением `new[]`, а освобождается одиночным `delete`.
- Следует использовать `delete[] p`.
- Для одиночного `new T` используется `delete`.

## cpp-q-022
ticket: cpp-t-038 · level: L1
Скомпилируется ли выражение `b + 2`? Какой оператор вызывается?
```cpp
struct Box {
    int value;
    Box& operator+=(int x) { value += x; return *this; }
};
int main() { Box b{1}; b += 2; }
```
### Эталон

- Выражение `b + 2` не компилировалось бы без отдельной перегрузки `operator+` или подходящего преобразования.

## cpp-q-023

## cpp-q-029
ticket: cpp-t-063 · level: L1
Какой тип `T` выводится для каждого вызова? Что будет напечатано?
```cpp
#include <iostream>
#include <type_traits>
template<class T> void f(T&&) {
    std::cout << std::is_lvalue_reference_v<T>;
}
int main() {
    int x = 0;
    f(x);
    f(0);
}
```
### Эталон

- При `f(0)` выводится `T = int` и параметр имеет тип `int&&`.
- Вывод будет `10`.

## cpp-q-032

```cpp
int f(T) { return 1; }
```
