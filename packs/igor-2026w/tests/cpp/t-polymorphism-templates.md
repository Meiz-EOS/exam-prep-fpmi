## cpp-q-409
ticket: cpp-t-043 · level: L0
Что такое неоднозначность ромбовидного наследования и как виртуальное наследование меняет общую базовую часть?
### Эталон
- В ромбе два промежуточных базовых класса наследуются от одной базы, а конечный класс наследуется от обоих промежуточных классов.
- Без виртуального наследования конечный объект содержит две отдельные базовые подобъектные части; обращение к их одноимённому члену может быть неоднозначным.
- Виртуальное наследование даёт одну общую виртуальную базовую подобъектную часть наиболее производного объекта.
- Наиболее производный класс отвечает за инициализацию виртуальной базы.

## cpp-q-410
ticket: cpp-t-043 · level: L1
Какое значение выведет программа? Почему указатель `part` может иметь адрес, отличный от адреса целого `Most`?
```cpp
#include <iostream>
struct Left { int l = 1; };
struct Base { int b = 2; };
struct Right : Base { int r = 3; };
struct Most : Left, Right {};
int main() {
    Most m;
    Most* whole = &m;
    Base* part = &m;
    (void)whole;
    std::cout << part->b;
}
```
### Эталон
- Вывод: `2`.
- `Base` является подобъектом внутри `Most`; преобразование корректирует указатель к адресу этого подобъекта.
- Стандарт не предписывает конкретную раскладку подобъектов и численное смещение.
- Поэтому `part->b` равно `2`, независимо от конкретного смещения базового подобъекта.

## cpp-q-411
ticket: cpp-t-044 · level: L0
Что такое RTTI и какое условие нужно для применения `dynamic_cast` к указателю или ссылке на базовый класс?
### Эталон
- RTTI — механизм получения информации о динамическом типе полиморфного объекта во время выполнения.
- Для проверяемого нисходящего или поперечного `dynamic_cast` исходный статический тип должен быть указателем/ссылкой на полиморфный класс.
- Неудачный `dynamic_cast` к указателю возвращает `nullptr`; к ссылке — выбрасывает `std::bad_cast`.
- Для `dynamic_cast` от указателя/ссылки на `void` к полиморфному типу результат указывает на наиболее производный объект.

## cpp-q-412
ticket: cpp-t-045 · level: L0
Что обычно называют vtable и vptr и что стандарт C++ гарантирует о размещении виртуальных функций в памяти?
### Эталон
- Vtable — распространённая реализационная таблица адресов или иных данных для динамической диспетчеризации виртуальных функций.
- Vptr — распространённый указатель в полиморфном объекте на такую таблицу или соответствующую структуру.
- Стандарт C++ задаёт наблюдаемое поведение виртуальных вызовов, но не требует наличия vtable/vptr и не определяет их физическую раскладку.
- Пустой класс имеет ненулевой размер; стандарт не задаёт конкретную прибавку размера за виртуальность.

## cpp-q-413
ticket: cpp-t-045 · level: L1
Что напечатает программа при вызове через `Base&`? Какое правило выбора функции это демонстрирует?
```cpp
#include <iostream>
struct Base {
    virtual void show() const { std::cout << "B"; }
    virtual ~Base() = default;
};
struct Derived : Base {
    void show() const override { std::cout << "D"; }
};
int main() {
    Derived object;
    Base& view = object;
    view.show();
}
```
### Эталон
- Вывод: `D`.
- Для виртуального вызова выбирается final overrider динамического типа объекта, здесь `Derived::show`.
- Статический тип выражения `view` — `Base&`, но он не определяет реализацию виртуального вызова.
- Виртуальный деструктор позволяет корректно уничтожать `Derived` через указатель на `Base`.

## cpp-q-414
ticket: cpp-t-046 · level: L0
Как в общих чертах выбирается перегрузка шаблонной функции, если есть специализация, точное совпадение и вариант с преобразованием?
### Эталон
- Сначала формируется набор кандидатов, затем для каждого проверяются вывод шаблонных аргументов и допустимость вызова.
- Выбирается лучшая viable-функция по качеству последовательностей преобразования; точное совпадение предпочтительнее преобразования.
- При равном качестве некоторые tie-break правила предпочитают более специализированный шаблон, а затем нетемплейтную функцию при прочих равных.
- Явная специализация не является отдельным кандидатом overload resolution: она задаёт реализацию выбранной специализации первичного шаблона.
