## cpp-q-809
ticket: cpp-t-093 · level: L0
Какую роль в `std::shared_ptr` играют пользовательский deleter и allocator?
### Эталон
- Пользовательский deleter задаёт действие при уничтожении управляемого объекта.
- Тип deleter не входит в тип `shared_ptr<T>`; сведения о нём хранятся в управляющем блоке.
- Allocator задаёт выделение и освобождение памяти управляющего блока в соответствующих конструкторах `shared_ptr`.

## cpp-q-810
ticket: cpp-t-093 · level: L1
Сколько раз вызовется deleter и что он получит?
```cpp
#include <iostream>
#include <memory>
int main() {
    int calls = 0;
    {
        std::shared_ptr<int> p(new int(5), [&calls](int* q) {
            ++calls;
            delete q;
        });
        auto r = p;
        p.reset();
        std::cout << calls << ' ';
    }
    std::cout << calls;
}
```
### Эталон
- Вывод: `0 1`.
- Копия `r` сохраняет сильное владение после `p.reset()`, поэтому deleter ещё не вызван в первой точке печати.
- При уничтожении последнего владельца deleter вызывается один раз с исходным указателем.

## cpp-q-811
ticket: cpp-t-094 · level: L0
Что такое лямбда-выражение с точки зрения функциональных объектов?
### Эталон
- Лямбда-выражение создаёт объект уникального безымянного типа замыкания.
- Захваты становятся состоянием объекта замыкания; тело лямбды задаёт его вызов `operator()`.
- У лямбды без захватов тип замыкания в C++20 имеет конструктор по умолчанию; у лямбды с захватом его нет.

## cpp-q-812
ticket: cpp-t-094 · level: L1
Что выведет программа? Как захват и `mutable` влияют на значения?
```cpp
#include <iostream>
int main() {
    int n = 3;
    auto f = [n]() mutable { ++n; return n; };
    std::cout << f() << ' ' << f() << ' ' << n;
}
```
### Эталон
- Вывод: `4 5 3`.
- Захват `[n]` сохраняет копию `n` в объекте замыкания.
- `mutable` разрешает менять эту копию; исходная переменная остаётся равной `3`.

## cpp-q-813
ticket: cpp-t-095 · level: L0
Что представляет `std::function` и как он вызывает указатель на метод?
### Эталон
- `std::function<R(Args...)>` — копируемая обёртка для вызываемого объекта, совместимого с сигнатурой.
- Для вызова хранимого объекта используется семантика `std::invoke`, включая указатели на функции-члены.
- Хранимый целевой объект должен быть копируемым; `std::function` в C++20 не поддерживает move-only цель.

## cpp-q-814
ticket: cpp-t-095 · level: L1
Скомпилируется ли программа и что она выведет?
```cpp
#include <functional>
#include <iostream>
struct X { int value = 6; int get() const { return value; } };
int main() {
    X x;
    std::function<int(const X&)> f = &X::get;
    std::cout << f(x);
}
```
### Эталон
- Программа компилируется в C++20 и выводит `6`.
- Указатель на метод вызывается с объектом, к которому применяется метод; здесь это `x`.
- `std::function` принимает вызываемый объект, совместимый с `int(const X&)`.

## cpp-q-815
ticket: cpp-t-096 · level: L0
Что проверяет `std::is_class` и что означает SFINAE?
### Эталон
- `std::is_class<T>` возвращает `true`, если `T` — тип класса, не являющийся union; для union результат `false`.
- SFINAE означает, что ошибка подстановки типа или выражения в непосредственном контексте шаблона исключает кандидата, а не обязательно делает программу некорректной.

## cpp-q-816
ticket: cpp-t-096 · level: L1
Что напечатает программа? Почему проверка указателя на член помогает отличить класс от скалярного типа?
```cpp
#include <iostream>
template<class T> char probe(int T::*);
template<class> long probe(...);
template<class T> constexpr bool is_class_v = sizeof(probe<T>(nullptr)) == sizeof(char);
struct S {};
int main() {
    std::cout << is_class_v<S> << is_class_v<int>;
}
```
### Эталон
- Вывод: `10`.
- Для `S` тип `int S::*` корректен, поэтому выбирается первая перегрузка и результат имеет тип `char`.
- Для `int` указатель на член такого типа сформировать нельзя; подстановка исключает первую перегрузку, выбирается `...`.
