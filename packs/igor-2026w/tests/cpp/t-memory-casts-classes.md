## cpp-q-311
ticket: cpp-t-034 · level: L0
Назовите основные различия между `new`/`delete` и `malloc`/`free` в C++.
### Эталон
- `new T` выделяет память и создаёт объект `T` (выполняет инициализацию); `delete` вызывает деструктор объекта и освобождает память.
- `malloc` выделяет сырую память без вызова конструктора; `free` освобождает память без вызова деструктора.
- Пары должны соответствовать: `new` с `delete`, `new[]` с `delete[]`, `malloc` с `free`.
- Несоответствие этих пар приводит к неопределённому поведению.

## cpp-q-312
ticket: cpp-t-035 · level: L0
Каково назначение `reinterpret_cast` и `const_cast`? Что происходит при снятии `const` и последующем изменении объекта?
### Эталон
- `reinterpret_cast` выполняет явно запрошенное преобразование между некоторыми типами указателей, ссылок и целочисленных типов; сам по себе не гарантирует допустимость последующего доступа к объекту.
- `const_cast` меняет cv-квалификацию указателя или ссылки; он не преобразует представление объекта и не делает исходно константный объект изменяемым.
- Изменение объекта, первоначально объявленного `const`, через снятую константность даёт неопределённое поведение.
- Если исходный объект не был объявлен `const`, изменение через неконстантный доступ после снятия добавленной квалификации может быть допустимо.

## cpp-q-313
ticket: cpp-t-035 · level: L1
Скомпилируется ли код, и каково значение `*p` после присваивания?
```cpp
int main() {
    int x = 4;
    const int* cp = &x;
    int* p = const_cast<int*>(cp);
    *p = 7;
    return x;
}
```
### Эталон
- Код компилируется.
- `x` изначально не объявлен константным; `const` был добавлен только к типу указателя `cp`.
- Снятие этой квалификации и запись через `p` допустимы; после записи `*p` и `x` равны `7`.
- Возвращаемое значение `main` — `7`.

## cpp-q-314
ticket: cpp-t-036 · level: L0
Какие условия агрегатной инициализации и designated initializers для класса в C++20?
### Эталон
- Агрегат можно инициализировать списком значений в порядке его агрегатных элементов.
- В C++20 агрегат не имеет пользовательских или унаследованных конструкторов, виртуальных функций и виртуальных базовых классов. Все прямые базовые классы должны быть публичными, невиртуальными и сами агрегатами; ни одно нестатическое поле, объявленное в классе или структуре, не может быть `private` или `protected`.
- Designated initializer указывает имя поля, например `S{.x = 1}`; обозначения следуют порядку объявления полей.
- C++20 не разрешает пропускать промежуточное поле с последующим обозначением более позднего поля в произвольном порядке; синтаксис C++20 не допускает designated initializers для базовых классов.

## cpp-q-315
ticket: cpp-t-036 · level: L1
Корректен ли этот код в C++20? Что будет в `p.x` и `p.y`?
```cpp
struct P { int x; int y; };
int main() {
    P p{.x = 4, .y = 6};
    return p.x + p.y;
}
```
### Эталон
- Код корректен в C++20: `P` — агрегат, а designated initializers соответствуют порядку полей.
- `p.x == 4`, `p.y == 6`.
- Выражение возврата равно `10`.

## cpp-q-316
ticket: cpp-t-037 · level: L0
Что такое делегирующий конструктор и какие правила действуют при явном создании объекта в уже выделенной памяти?
### Эталон
- Делегирующий конструктор вызывает другой конструктор того же класса в списке инициализации, например `C() : C(0) {}`.
- Делегирующий вызов должен быть единственным mem-initializer в этом списке.
- Для создания объекта в предоставленной выровненной памяти применяют placement new, например `new (ptr) T(args...)`; он вызывает конструктор, но сам не выделяет эту память.
- После окончания времени жизни такого объекта его деструктор вызывают явно; освобождение самой памяти выполняют отдельно согласно её источнику.

## cpp-q-317
ticket: cpp-t-037 · level: L1
Скомпилируется ли код? Сколько раз будет вызван деструктор `X` и почему?
```cpp
struct X {
    X() = default;
    X(int) : X() {}
    ~X() = default;
};
int main() { X x(1); }
```
### Эталон
- Код корректен: `X(int)` делегирует конструктору `X()`.
- Создаётся один объект `x`, а не отдельный временный объект-делегат.
- Деструктор для `x` вызывается один раз при выходе из `main`.

## cpp-q-318
ticket: cpp-t-038 · level: L0
Какие общие рекомендации применяются при перегрузке бинарных арифметических операторов и префиксного/постфиксного `++`?
### Эталон
- Бинарный арифметический оператор обычно не меняет операнды и возвращает результат; его можно реализовать свободной функцией, например `operator+(int, X)`, если хотя бы один параметр имеет классный или перечислимый тип.
- Постфиксный `operator++(int)` отличается фиктивным параметром `int`, возвращает старое значение по значению, а префиксный `operator++()` меняет объект и обычно возвращает ссылку на него.
- Для перегружаемого оператора хотя бы один операнд должен иметь классный или перечислимый тип; классный тип может быть и у правого операнда.
- Перегрузка не меняет приоритет, ассоциативность или число операндов оператора.
