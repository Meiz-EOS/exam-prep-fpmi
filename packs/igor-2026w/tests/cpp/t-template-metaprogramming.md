## cpp-q-415
ticket: cpp-t-047 · level: L0
Различите специализацию и перегрузку шаблонной функции. Что означает полная или частичная специализация шаблона класса?
### Эталон
- Явная специализация задаёт реализацию шаблона для конкретного случая; полная задаёт конкретные аргументы для всех параметров, а частичная задаёт подходящий шаблонный образец аргументов, например `A<T*, T>`.
- Частичная специализация разрешена для шаблонов классов и переменных, но не для шаблонов функций.
- Для функций вместо частичной специализации используют перегрузку.
- Выбор специализации класса зависит от наиболее специализированного подходящего шаблона; неоднозначный выбор является ошибкой.

## cpp-q-416
ticket: cpp-t-047 · level: L1
Для `f(1)` какая функция будет выбрана и почему специализация `f<int>` не конкурирует с перегрузкой как отдельный кандидат?
```cpp
#include <iostream>
template<class T> void f(T) { std::cout << "general"; }
template<> void f<int>(int) { std::cout << "specialization"; }
void f(int) { std::cout << "overload"; }
int main() { f(1); }
```
### Эталон
- Вывод: `overload`.
- Сначала разрешается перегрузка между обычной функцией и шаблонными кандидатами; при одинаковом качестве преобразований предпочтительна нетемплейтная функция.
- Явная специализация не участвует в выборе перегрузки как самостоятельный кандидат; она задаёт реализацию выбранной специализации шаблона.
- Если бы `void f(int)` не было, для шаблонного кандидата `f<int>` применялась бы явная специализация.

## cpp-q-417
ticket: cpp-t-048 · level: L0
Что означает вычисление на этапе компиляции с помощью рекурсивного шаблона и какова базовая форма вычисления Фибоначчи?
### Эталон
- Шаблонные аргументы и инстанцирование могут кодировать рекуррентное вычисление, результат которого доступен как константа времени компиляции.
- Для чисел Фибоначчи с `F(0)=0`, `F(1)=1` рекуррентность имеет вид `F(n)=F(n-1)+F(n-2)` при `n≥2`.
- Рекурсивная метафункция нуждается в базовых случаях, например `F<0>::value=0` и `F<1>::value=1`.
- Глубина инстанцирования ограничена реализацией; конкретное допустимое значение не фиксировано стандартом.

## cpp-q-418
ticket: cpp-t-048 · level: L1
Какое значение имеет `Fib<6>::value`? Покажите рекуррентный расчёт по двум предыдущим значениям.
```cpp
template<unsigned N>
struct Fib {
    static constexpr unsigned value = Fib<N - 1>::value + Fib<N - 2>::value;
};
template<> struct Fib<0> { static constexpr unsigned value = 0; };
template<> struct Fib<1> { static constexpr unsigned value = 1; };
static_assert(Fib<6>::value == 8);
```
### Эталон
- `Fib<6>::value` равно `8`.
- Расчёт: `F(2)=1`, `F(3)=2`, `F(4)=3`, `F(5)=5`, `F(6)=8`.
- Специализации `Fib<0>` и `Fib<1>` останавливают рекурсию.
- `static_assert` проверяет результат во время компиляции; неверное значение делает программу некорректной.

## cpp-q-419
ticket: cpp-t-049 · level: L0
Что проверяет `std::is_same` и чем проверка типов во время компиляции отличается от сравнения `typeid`?
### Эталон
- `std::is_same<T, U>` — метафункция, сообщающая во время компиляции, являются ли типы `T` и `U` одним и тем же типом.
- В C++20 удобная форма `std::is_same_v<T, U>` имеет тип `bool` и является константным выражением.
- `typeid` — оператор RTTI; для выражения полиморфного типа он может сообщать динамический тип во время выполнения.

## cpp-q-420
ticket: cpp-t-050 · level: L0
Что такое пакет параметров шаблона, как его раскрывают и что возвращает оператор `sizeof...`?
### Эталон
- Пакет параметров шаблона представляет ноль или более аргументов одного параметра-пакета.
- Раскрытие пакета подставляет его элементы в шаблонный шаблонный фрагмент; свёртка применяет оператор к элементам пакета.
- `sizeof...(Pack)` — константное выражение типа `std::size_t`, равное числу элементов пакета.
- Пакет может быть пустым; допустимость и значение свёртки для пустого пакета зависят от оператора и формы свёртки.
