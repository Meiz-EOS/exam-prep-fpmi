## cpp-q-401
ticket: cpp-t-039 · level: L0
Что означает `const` у нестатического метода класса и какие поля допускается менять в таком методе?
### Эталон
- `const`-метод имеет cv-квалифицированный тип функции-члена; внутри него `this` указывает на `const`-объект.
- Он не может менять обычные нестатические поля объекта.
- Поле, объявленное `mutable`, можно менять и в `const`-методе.
- Через поле-указатель можно менять объект, на который оно указывает; само поле-указатель менять нельзя.
- Через ссылочное поле можно менять связанный объект; саму ссылку переназначить нельзя.

## cpp-q-402
ticket: cpp-t-039 · level: L1
Что напечатает код? Почему `ref` не переназначает ссылку на `b`, а `p` не меняет значение `b`?
```cpp
#include <iostream>
struct S {
    int* p;
    int& ref;
    mutable int calls = 0;
    S(int& x, int& y) : p(&x), ref(y) {}
    void inspect() const { ++calls; *p += 1; }
};
int main() {
    int a = 1, b = 4;
    const S s(a, b);
    s.inspect();
    s.ref = 9;
    std::cout << a << ' ' << b << ' ' << s.calls;
}
```
### Эталон
- Вывод: `2 9 1`.
- В `const`-методе нельзя переназначить поле `p` или `ref`; `calls` изменяемо из-за `mutable`.
- `*p += 1` меняет объект `a`, на который указывает указатель; константность `s` не делает объект `a` константным.
- `s.ref = 9` присваивает значение уже связанного объекта `b`; ссылки не переназначаются.

## cpp-q-403
ticket: cpp-t-040 · level: L0
Что такое пользовательская функция преобразования типа и для чего у неё указывают `explicit`?
### Эталон
- Функция преобразования объявляется как `operator T() const` (возможны cv/ref-квалификаторы); тип результата входит в имя, возвращаемый тип не пишут.
- Она задаёт преобразование объекта класса в `T`.
- `explicit` запрещает использовать такое преобразование в неявных преобразованиях и копирующей инициализации.
- Явное приведение может вызвать `explicit`-функцию преобразования; контекстное преобразование в `bool` также учитывает её.

## cpp-q-404
ticket: cpp-t-040 · level: L1
Что напечатает программа? Объясните выбор преобразования в `if` и почему для `int n = f` выбирается `operator int()`, а `explicit operator bool()` не участвует.
```cpp
#include <iostream>
struct Flag {
    explicit operator bool() const { return true; }
    operator int() const { return 7; }
};
int main() {
    Flag f;
    if (f) std::cout << "yes";
    int n = f;
    std::cout << ' ' << n;
}
```
### Эталон
- Вывод: `yes 7`.
- Условие `if` использует контекстное преобразование к `bool`, где допустим `explicit operator bool()`.
- Для копирующей инициализации `int n = f` явный `operator bool()` не рассматривается; используется неявный `operator int()`.
- `explicit` не делает функцию преобразования недоступной при явном вызове/приведении, но ограничивает её применение в неявных преобразованиях.

## cpp-q-405
ticket: cpp-t-041 · level: L0
Различите видимость имени и доступность члена при наследовании.
### Эталон
- Видимость относится к тому, какие объявления находятся поиском имени в данном контексте.
- Доступность — проверка правил `public`, `protected`, `private` после поиска имени.
- Объявление в производном классе с тем же именем может скрыть одноимённые объявления базового класса, даже если наборы параметров отличаются.
- `using Base::name;` вводит найденные объявления базового класса в область видимости производного класса; права доступа проверяются отдельно.

## cpp-q-406
ticket: cpp-t-041 · level: L1
Что выведет `d.f(1)`? Почему вызов `d.secret()` не скомпилируется, хотя имя найдено?
```cpp
#include <iostream>
struct Base {
    void f(double) { std::cout << "Base"; }
    void secret() {}
};
struct Derived : Base {
    using Base::f;
    void f(int) { std::cout << "Derived"; }
private:
    using Base::secret;
};
int main() {
    Derived d;
    d.f(1);
    // d.secret();
}
```
### Эталон
- Вывод `d.f(1)` — `Derived`: обе перегрузки видимы благодаря `using`, а `f(int)` имеет точное соответствие.
- Без `using Base::f` объявление `Derived::f(int)` скрыло бы одноимённую функцию `Base::f(double)` при поиске через `Derived`.
- `d.secret()` является ошибкой доступа: поиск находит введённое объявление, но оно объявлено `private` в `Derived`.

## cpp-q-407
ticket: cpp-t-042 · level: L0
Как различаются публичное и приватное наследование класса и структуры по умолчанию?
### Эталон
- `class D : B` эквивалентно `class D : private B`; `struct D : B` эквивалентно `struct D : public B`.
- При публичном наследовании публичные и защищённые члены базы сохраняют соответственно `public` и `protected` доступ в производном классе.
- При приватном наследовании публичные и защищённые члены базы доступны членам `D` как `private`-наследованные; закрытые члены базы напрямую недоступны.
- Наследование не передаёт производному классу дружбу базового класса.

## cpp-q-408
ticket: cpp-t-042 · level: L1
Какие из трёх помеченных преобразований допустимы? Объясните, почему `static_cast` и неявное преобразование ведут себя по-разному.
```cpp
struct Base {};
struct Pub : public Base {};
struct Priv : private Base {};
int main() {
    Pub p;
    Base* a = &p;                         // 1
    Priv q;
    // Base* b = &q;                      // 2
    // Base* c = static_cast<Base*>(&q);   // 3
}
```
### Эталон
- Преобразование 1 допустимо: публичная производная связь разрешает неявное преобразование `Pub*` в `Base*`.
- Преобразование 2 недопустимо вне членов/друзей `Priv`: базовая часть недоступна из-за приватного наследования.
- Преобразование 3 также недопустимо в этом контексте: `static_cast` не отменяет проверку доступности базовой части.
- `reinterpret_cast` может преобразовать значение указателя, но не выполняет корректную коррекцию к адресу подобъекта `Base` и не заменяет безопасное преобразование по иерархии.
