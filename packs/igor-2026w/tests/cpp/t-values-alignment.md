## cpp-q-719
ticket: cpp-t-085 · level: L0
Что задают `alignof(T)` и `alignas`, и что означает требование выравнивания типа?
### Эталон
- `alignof(T)` даёт требование выравнивания типа `T` в байтах.
- `alignas` задаёт выравнивание переменной, члена или типа; указанное выравнивание не должно быть меньше естественного выравнивания объекта и должно быть допустимым.
- Объект должен размещаться по адресу, кратному требуемому выравниванию; нарушение требований к выравниванию при доступе может приводить к неопределённому поведению.

## cpp-q-720
ticket: cpp-t-085 · level: L1
Гарантирует ли этот код корректную запись `int` на любой платформе, если `alignof(int) == 4`? Объясните роль выравнивания и времени жизни объекта.
```cpp
char buf[sizeof(int) + 1];
int* p = reinterpret_cast<int*>(buf + 1);
*p = 42;
```
### Эталон
- Нет. Сам массив `buf` не обязан иметь выравнивание `int`, а `buf + 1` смещён на один байт от его начала, поэтому адрес `p` не гарантированно выровнен для `int`.
- Кроме того, приведение указателя само по себе не начинает время жизни объекта `int`; перед записью нужно корректно начать его время жизни в подходящем хранилище.
- Для размещения объекта нужны достаточный размер, подходящее выравнивание (например, `alignas(int)`) и корректное начало времени жизни.

## cpp-q-721
ticket: cpp-t-086 · level: L0
Какую задачу решает `std::forward<T>` и почему у него есть две перегрузки?
### Эталон
- `std::forward<T>(x)` восстанавливает категорию значения аргумента согласно deduced `T` в forwarding reference.
- Для lvalue-аргумента выводится `T = U&`, и свёртка ссылок даёт lvalue-ссылку; для rvalue выводится `T = U`, результатом становится rvalue-ссылка `U&&`.
- Перегрузки принимают соответственно `remove_reference_t<T>&` и `remove_reference_t<T>&&` и возвращают `T&&` (после свёртки ссылок либо как результат `static_cast<T&&>`).
- Вторая перегрузка недопустима, если `T` — lvalue-ссылка: иначе она позволила бы передать lvalue и получить rvalue-ссылку на него.

## cpp-q-722
ticket: cpp-t-086 · level: L1
Что выведет код? Почему `std::forward` нельзя заменить безусловным `std::move`?
```cpp
template<class T> decltype(auto) pass(T&& x) { return std::forward<T>(x); }
int a = 0;
static_assert(std::is_lvalue_reference_v<decltype(pass(a))>);
static_assert(std::is_rvalue_reference_v<decltype(pass(0))>);
```
### Эталон
- Программа корректна; оба `static_assert` истинны.
- Для `pass(a)` выводится `T = int&`, параметр после свёртки — `int&`, а `forward<T>` возвращает lvalue-ссылку.
- Для `pass(0)` выводится `T = int`, параметр — `int&&`, `forward<T>` возвращает rvalue-ссылку.
- Безусловный `std::move(x)` превратил бы и исходный lvalue в xvalue, теряя категорию аргумента.

## cpp-q-723
ticket: cpp-t-087 · level: L0
Определите категории glvalue, lvalue, xvalue и prvalue; укажите, когда copy elision гарантирован в C++20.
### Эталон
- glvalue обозначает объект или функцию, чья идентичность можно определить; lvalue и xvalue — категории glvalue.
- lvalue не является xvalue; xvalue обозначает объект, ресурсы которого могут быть переиспользованы.
- prvalue вычисляет значение операнда; если у него есть объект-результат, prvalue инициализирует этот объект. prvalue не является glvalue.
- В C++17 и далее гарантировано отсутствие промежуточного копирования/перемещения при инициализации объекта prvalue того же типа (с учётом cv) в целевой объект; NRVO для именованного локального объекта остаётся необязательным.

## cpp-q-724
ticket: cpp-t-087 · level: L1
Сколько конструкторов копирования/перемещения вызывается в C++20?
```cpp
struct X { X(); X(X const&); X(X&&); };
X make() { return X{}; }
int main() { X x = make(); }
```
### Эталон
- Вызывается 0 конструкторов копирования/перемещения: prvalue `X{}` и результат вызова `make()` непосредственно инициализируют объекты-результаты, включая `x`.
- `make` возвращает prvalue того же типа, который непосредственно инициализирует результат вызова и затем `x`.
- NRVO здесь не требуется для объяснения результата; NRVO касается возврата именованного локального объекта и остаётся разрешённой оптимизацией.

## cpp-q-725
ticket: cpp-t-088 · level: L0
Что такое CTAD и какова роль deduction guide?
### Эталон
- Class template argument deduction (CTAD) выводит аргументы шаблона класса из типа инициализатора при объявлении объекта без явных аргументов шаблона.
- Неявные guides формируются из конструкторов; пользовательский deduction guide задаёт дополнительное правило вывода типа класса.
- Deduction guide влияет на выбор специализации и не является конструктором; объект затем инициализируется соответствующим конструктором.

## cpp-q-726
ticket: cpp-t-088 · level: L1
Какой тип имеют `a` и `b` после CTAD в C++20?
```cpp
std::pair a{1, 2.0};
std::vector b{1, 2, 3};
```
### Эталон
- `a` имеет тип `std::pair<int, double>`: аргументы пары выводятся независимо.
- `b` имеет тип `std::vector<int>`: deduction guide `vector(initializer_list<T>, Allocator = Allocator()) -> vector<T>` выводит `T = int` из элементов списка.
- В обоих объявлениях тип шаблона выведен; это не означает, что CTAD применим к каждому списку аргументов независимо от доступных constructors/guides.
