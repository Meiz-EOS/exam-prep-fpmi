## cpp-q-114
ticket: cpp-t-010 · level: L0
Когда две функции с одинаковым именем образуют перегрузку? Считаются ли возвращаемые типы достаточным различием?
### Эталон
- Перегрузка — несколько функций с одним именем в одной области, различающихся списком параметров (типами/числом/порядком параметров).
- Различие только возвращаемых типов не образует допустимой перегрузки.
- При вызове выбирается лучшая подходящая функция по правилам разрешения перегрузки; при отсутствии единственной лучшей вызов неоднозначен.

## cpp-q-115
ticket: cpp-t-011 · level: L1
Какое значение выведет программа и почему ссылка остаётся корректной после завершения оператора объявления?
```cpp
#include <iostream>
int main() {
    const int& r = 42;
    std::cout << r;
}
```
### Эталон
- Вывод: `42`.
- Привязка `const`-ссылки к временному объекту продлевает время жизни этого объекта до времени жизни ссылки.
- Здесь временный объект, материализованный из литерала `42`, живёт до завершения блока `main`.

## cpp-q-116
ticket: cpp-t-012 · level: L0
Объясните разницу между `const int* p` и `int* const p`: что именно запрещено менять?
### Эталон
- `const int* p` — изменяемый указатель на константный через него `int`: переназначить `p` можно, писать в `*p` нельзя.
- `int* const p` — константный указатель на изменяемый `int`: переназначить `p` нельзя, менять `*p` можно.
- `const` относится к ближайшему слева типу, а при отсутствии типа слева — к ближайшему справа.

## cpp-q-117
ticket: cpp-t-012 · level: L1
Что выведет код и почему `const` не делает сам указатель константным?
```cpp
#include <iostream>
int main() {
    int x = 1, y = 2;
    const int* p = &x;
    p = &y;
    std::cout << *p;
}
```
### Эталон
- Код компилируется, вывод: `2`.
- `const int*` — изменяемый указатель на объект, который нельзя менять через этот указатель.
- Переназначение `p` с `&x` на `&y` допустимо; запрещено было бы `*p = 3`.

## cpp-q-118
ticket: cpp-t-013 · level: L0
Какое свойство `static_cast` отличает его от C-style cast? Скомпилируется ли преобразование `void*` обратно в `int*`?
### Эталон
- `static_cast` задаёт ограниченный набор преобразований, проверяемых правилами языка; C-style cast может применять более широкий набор механизмов приведения.
- `void*` можно явно преобразовать через `static_cast<int*>` обратно к указателю на исходный объектный тип.
- Такое приведение само не проверяет, что адрес действительно указывает на объект нужного типа; использовать неверный тип небезопасно.
