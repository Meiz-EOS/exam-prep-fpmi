## cpp-q-517
ticket: cpp-t-060 · level: L0
Зачем контейнерам нужны аллокаторы и какова роль `std::allocator_traits`?
### Эталон
- Аллокатор отделяет управление хранилищем элементов от логики контейнера и позволяет настраивать получение/освобождение памяти.
- Аллокатор — параметр типа контейнера, предоставляющий модель получения хранилища для объектов заданного типа.
- `std::allocator<T>` — стандартный аллокатор для `T`; он предоставляет контейнерам стандартный механизм управления хранилищем.
- `std::allocator_traits<A>` — адаптационный интерфейс к аллокатору `A`: контейнеры используют его типы и функции для выделения/освобождения хранилища, конструирования/уничтожения элементов и свойств распространения аллокатора.

## cpp-q-518
ticket: cpp-t-060 · level: L1
Почему `reserve` не должен присваивать в ещё не созданные элементы? Какой порядок действий нужен при переносе `vector` на новое хранилище?
### Эталон
- Выделенное аллокатором хранилище ещё не содержит объектов `T`; время жизни каждого элемента начинается только после его конструирования.
- Сначала запрашивают новое хранилище через `allocator_traits<A>::allocate`, затем в нём конструируют элементы через `allocator_traits<A>::construct`.
- Если конструирование завершается исключением, уже созданные новые элементы уничтожают в обратном порядке и новое хранилище освобождают.
- После успешного переноса уничтожают старые элементы и освобождают старое хранилище; реализация должна учитывать, что стандартная гарантия `reserve` имеет исключения при бросающем move-конструкторе не копируемого типа.

## cpp-q-519
ticket: cpp-t-061 · level: L1
Какие из следующих присваиваний корректны? Обоснуйте категории выражений и укажите результат присваивания.
```cpp
int main() {
    int a = 1;
    const int c = 2;
    (a + 1) = 4;
    // c = 3;
}
```
### Эталон
- `a + 1` — prvalue типа `int`; в C++20 это выражение нельзя использовать как левый операнд встроенного присваивания, поэтому строка не компилируется.
- `c` — lvalue типа `const int`; присваивание `c = 3` также некорректно, потому что объект константен.
- Выражение `a` — modifiable lvalue типа `int`, поэтому `a = 4` было бы корректно.
- Категории glvalue/prvalue/xvalue характеризуют выражения; lvalue и xvalue являются glvalue, а xvalue и prvalue — rvalue.

## cpp-q-520
ticket: cpp-t-062 · level: L0
Что такое rvalue-ссылка и чем её инициализация отличается от инициализации обычной lvalue-ссылки?
### Эталон
- `T&&` — ссылка на rvalue типа `T`; rvalue-ссылка на неконстантный тип не связывается с обычным lvalue этого типа.
- `T&` связывается с lvalue; локальная `const T&` может также связываться с rvalue и при прямой инициализации продлевает время жизни временного до конца времени жизни ссылки. Временный, привязанный к параметру-ссылке, живёт только до конца полного выражения с вызовом.
- Именованное выражение, обозначающее rvalue-ссылку, само является lvalue.
- Ссылки нельзя переназначить после инициализации; присваивание через ссылку меняет обозначаемый объект.

## cpp-q-521
ticket: cpp-t-062 · level: L1
Скомпилируется ли код? Что напечатает программа?
```cpp
#include <iostream>
int main() {
    int x = 1;
    int&& r = 2;
    int& l = x;
    r = 3;
    std::cout << x << ' ' << r;
    // int&& bad = x;
}
```
### Эталон
- Код без закомментированной строки компилируется; вывод: `1 3`.
- Именованное выражение `r` является lvalue, поэтому `r = 3` присваивает значение объекту, на который ссылается `r`.
- `x` остаётся равным `1`; `int&& bad = x` не компилируется, потому что `x` — lvalue.
- Привязка rvalue-ссылки к временному `2` продлевает время жизни этого временного до времени жизни локальной ссылки `r`.

## cpp-q-522
ticket: cpp-t-063 · level: L0
Что называют forwarding reference и какова роль `std::forward` при perfect forwarding?
### Эталон
- В шаблоне функции `template<class T> void f(T&&)` параметр `T&&` является forwarding reference; `const T&&` таким не является.
- При передаче lvalue в `f` тип `T` выводится как lvalue-ссылка, а при передаче rvalue — как тип без ссылки; сворачивание ссылок даёт соответственно `U&` и `U&&`.
- `std::forward<T>(x)` восстанавливает категорию аргумента согласно выведенному `T`: lvalue остаётся lvalue, rvalue передаётся как rvalue.
- При выводе типа переменной `auto&& x = expr` действует аналогичное правило: для lvalue `auto` выводится как lvalue-ссылка, для rvalue — как тип без ссылки.
