## cpp-q-501
ticket: cpp-t-051 · level: L0
Что такое объект исключения и что происходит при выходе из блока `throw` до подходящего обработчика?
### Эталон
- Выражение `throw` инициализирует объект исключения; его хранилище выделяется способом, не определённым стандартом, но не глобальными функциями выделения памяти.
- Управление ищет подходящий `catch` вверх по стеку вызовов.
- При раскрутке стека уничтожаются уже созданные автоматические объекты в обратном порядке завершения их конструкторов.
- Если обработчик не найден, вызывается `std::terminate`; выполнение `main` не гарантирует раскрутки стека.

## cpp-q-502
ticket: cpp-t-051 · level: L1
Что напечатает программа? Почему `throw;` отличается от `throw e;`?
```cpp
#include <iostream>
struct B { virtual ~B() = default; };
struct D : B {};
int main() {
    try { throw D{}; }
    catch (const B& e) {
        try { throw; }
        catch (const D&) { std::cout << "D"; }
    }
    try { throw D{}; }
    catch (const B& e) {
        try { throw e; }
        catch (const B&) { std::cout << "B"; }
    }
}
```
### Эталон
- Вывод: `DB`.
- `throw;` повторно передаёт тот же объект исключения; его динамический тип остаётся `D`.
- `throw e;` создаёт новое исключение из статического типа выражения `e` (`const B` без верхнеуровневого `const` у объекта исключения), поэтому производная часть теряется.
- Обработчики сравниваются по порядку; ссылка на базовый класс может связаться с исключением производного типа.
- При перехвате по значению инициализируется параметр обработчика; стандарт допускает элизию копирования объекта исключения и параметра, поэтому число фактических копирований нельзя считать фиксированным.

## cpp-q-503
ticket: cpp-t-052 · level: L0
Что происходит с объектом и его подобъектами, если конструктор завершился исключением?
### Эталон
- Сам объект, чей конструктор не завершился, считается не сконструированным; его деструктор не вызывается.
- Полностью сконструированные базовые классы и нестатические члены уничтожаются в обратном порядке завершения их конструкторов.
- Если исключение выходит из конструктора, вызванного выражением `new`, для соответствующего хранилища вызывается функция освобождения, если она найдена.
- Function-try-блок конструктора может перехватить исключение из списка инициализации и тела; после его обработчиков исключение нельзя поглотить — выход из обработчика конструктора повторно выбрасывает его.

## cpp-q-504
ticket: cpp-t-052 · level: L1
Какой будет вывод? Уничтожается ли `A` и что случится, если деструктор `B` тоже выбросит исключение?
```cpp
#include <iostream>
struct A { ~A() { std::cout << "A"; } };
struct B { B() { throw 1; } ~B() { std::cout << "B"; } };
struct X { A a; B b; ~X() { std::cout << "X"; } };
int main() {
    try { X x; }
    catch (...) { std::cout << "C"; }
}
```
### Эталон
- Вывод: `AC`.
- `A` успел полностью сконструироваться, поэтому при провале конструктора `X` его деструктор вызывается.
- Конструктор `B` не завершился, поэтому `B::~B` не вызывается; деструктор `X` также не вызывается.
- Если деструктор, вызванный раскруткой стека, выбросит исключение наружу, вызывается `std::terminate`.

## cpp-q-505
ticket: cpp-t-053 · level: L0
Сформулируйте basic и strong exception guarantee. Что означает условная спецификация `noexcept(condition)` и что проверяет оператор `noexcept(expr)`?
### Эталон
- Basic guarantee: после исключения сохраняются инварианты объекта и не происходит утечки ресурсов, но состояние может измениться.
- Strong guarantee: при исключении состояние программы остаётся таким, каким было непосредственно перед вызовом (эффект «всё или ничего»).
- Условная спецификация `noexcept(condition)` объявляет функцию не выбрасывающей, если `condition` истинно, и потенциально выбрасывающей, если ложно; условие должно быть константным выражением типа `bool`.
- Оператор `noexcept(expr)` даёт `true`, если выражение не может выбросить исключение согласно правилам языка и спецификациям вызываемых функций, иначе `false`; сам операнд не вычисляется.

## cpp-q-506
ticket: cpp-t-054 · level: L0
Что задают `iterator_traits` и `reverse_iterator`? Назовите назначение константного итератора.
### Эталон
- `std::iterator_traits<I>` предоставляет стандартные сведения о типе итератора, включая `value_type`, `difference_type`, `pointer`, `reference` и `iterator_category` (для поддерживаемого типа итератора).
- `std::reverse_iterator<I>` оборачивает двунаправленный или более сильный итератор и проходит диапазон в обратном направлении.
- Базовый итератор reverse-итератора указывает на элемент, следующий за тем, который возвращает разыменование.
- Константный итератор позволяет читать элемент, не предоставляя через него возможность изменить этот элемент.

## cpp-q-507
ticket: cpp-t-054 · level: L1
Каковы результаты `*r` и `r.base()`, если `r` построен из `v.begin() + 3`? Почему `std::distance` нельзя считать постоянным временем для любого итератора?
```cpp
#include <iterator>
#include <vector>
int main() {
    std::vector<int> v{10, 20, 30, 40};
    auto r = std::make_reverse_iterator(v.begin() + 3);
    // *r == ?; r.base() == ?
}
```
### Эталон
- `r.base() == v.begin() + 3`, то есть базовый итератор указывает на `40`.
- `*r == 30`: reverse-итератор разыменовывает элемент перед базовым итератором.
- `std::distance(first, last)` работает за постоянное время для итераторов с произвольным доступом, а для однонаправленных/двунаправленных проходит диапазон и требует линейного числа инкрементов.
- `std::advance` аналогично использует арифметику за постоянное время для итераторов с произвольным доступом и последовательные инкременты для более слабых категорий.
