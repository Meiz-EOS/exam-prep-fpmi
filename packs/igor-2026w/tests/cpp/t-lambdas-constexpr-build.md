## cpp-q-305
ticket: cpp-t-030 · level: L0
Что такое лямбда-выражение и замыкание в C++? Как захватываются переменные по значению и по ссылке?
### Эталон
- Лямбда-выражение создаёт объект замыкания с уникальным безымянным типом, у которого есть оператор вызова.
- Захват по значению сохраняет копию захваченного объекта в замыкании.
- Захват по ссылке связывает замыкание с исходным объектом; его время жизни должно покрывать обращения через замыкание.
- Изменять захваченные копии в неконстантном операторе вызова позволяет спецификатор `mutable`; он не делает изменяемым исходный объект.

## cpp-q-306
ticket: cpp-t-031 · level: L1
Скомпилируется ли код в C++20? Если да, что вернёт `f(3)` и почему отброшенная ветка `if constexpr` не мешает вызову `f(3)`?
```cpp
constexpr int twice(int x) { return x * 2; }
template<class T>
constexpr int f(T x) {
    if constexpr (sizeof(T) == 1) {
        return 1;
    } else {
        return twice(static_cast<int>(x));
    }
}
int main() { return f(char{3}); }
```
### Эталон
- Код корректен в C++17 и C++20.
- Для `T = char` условие `sizeof(T) == 1` истинно, поэтому `if constexpr` выбирает первую ветку и отбрасывает вторую.
- `f(char{3})` возвращает `1`.
- `constexpr` позволяет вычислить вызов во время компиляции, если аргументы и контекст это допускают; само объявление не требует такого вычисления при каждом вызове.

## cpp-q-307
ticket: cpp-t-032 · level: L0
Чем предупреждение компилятора отличается от ошибки? Что меняют параметры `-Wall`, `-Wextra` и `-Werror` в GCC/Clang?
### Эталон
- Ошибка означает, что компилятор не может успешно перевести программу в выбранном режиме; предупреждение сообщает о подозрительной конструкции, но само по себе обычно не запрещает компиляцию.
- `-Wall` и `-Wextra` включают дополнительные группы предупреждений; название `-Wall` не означает буквально все предупреждения.
- `-Werror` превращает выдаваемые предупреждения в ошибки компиляции.
- Эти флаги — параметры конкретных компиляторов, а не требования стандарта C++.

## cpp-q-308
ticket: cpp-t-032 · level: L1
Что произойдёт при компиляции командой `g++ -std=c++20 -Wall -Werror`? Объясните роль каждого флага.
```cpp
int main() {
    int value = 1;
}
```
### Эталон
- GCC выдаёт предупреждение о неиспользуемой локальной переменной `value` при `-Wall`.
- `-Werror` превращает это предупреждение в ошибку, поэтому компиляция завершается неуспешно.
- `-std=c++20` выбирает режим языка C++20; это флаг GCC, не часть исходной программы.
- Набор диагностик может зависеть от версии компилятора и параметров сборки.

## cpp-q-309
ticket: cpp-t-033 · level: L1
Что напечатает программа? Для каждого из трёх выражений `value`, `::value` и `N::value` укажите, какое значение выводится.
```cpp
#include <iostream>
int value = 1;
namespace N { int value = 2; }
int main() {
    using namespace N;
    int value = 3;
    std::cout << value << ' ' << ::value << ' ' << N::value;
}
```
### Эталон
- Вывод: `3 1 2`.
- `value` обозначает локальную переменную и даёт `3`.
- `::value` обозначает переменную глобального пространства имён и даёт `1`.
- `N::value` обозначает переменную пространства имён `N` и даёт `2`.

## cpp-q-310
ticket: cpp-t-033 · level: L0
Определите qualified-id и unqualified-id. Что делает `using namespace N;` и как оно влияет на поиск неквалифицированных имён?
### Эталон
- Unqualified-id — имя без квалифицирующего префикса, например `value`.
- Qualified-id — имя с квалификатором области видимости, например `N::value` или `::value`.
- `using namespace N;` делает имена пространства `N` доступными при поиске неквалифицированных имён в точке действия директивы; само по себе оно не создаёт локальных объявлений.
- Если поиск неквалифицированного имени находит несколько неоднозначных подходящих объявлений из-за директивы, программа некорректна; сама директива не задаёт приоритет имён.
