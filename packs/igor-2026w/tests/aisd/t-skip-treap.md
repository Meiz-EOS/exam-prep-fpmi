## aisd-q-601
ticket: aisd-t-068 · level: L0
Что такое Skip List и какие операции она поддерживает?
### Эталон
- Skip List — упорядоченная структура из связанных списков нескольких уровней.
- Каждый следующий уровень содержит подмножество элементов предыдущего; верхние уровни позволяют пропускать участки при поиске.
- `find` ищет ключ, `insert` добавляет его, `erase` удаляет его.
- При случайном выборе уровней ожидаемое время каждой из этих операций — $O(\log n)$; худшее может быть $O(n)$.

## aisd-q-602
ticket: aisd-t-068 · level: L1
Опишите поиск в Skip List и объясните, почему он возвращает ключ, если тот присутствует.
### Эталон
- Поиск начинает с верхнего уровня и идёт вправо, пока следующий ключ меньше искомого; затем спускается на уровень ниже.
- На каждом уровне сохраняется инвариант: текущий узел не больше искомого ключа, а следующий узел либо больше него, либо отсутствует.
- Поиск начинает с верхнего уровня и на каждом уровне останавливается перед первым ключом, не меньшим искомого.
- При спуске текущий узел сохраняется, а порядок ключей на каждом уровне гарантирует, что пропущенный участок не содержит искомого ключа.
- Дойдя до нижнего уровня, поиск проверяет следующий узел на равенство искомому ключу.
- `insert` и `erase` сначала находят позиции обновления и меняют ссылки на случайно выбранном числе уровней.

## aisd-q-603
ticket: aisd-t-069 · level: L0
Определите декартово дерево и сформулируйте его ожидаемую оценку глубины при случайных приоритетах.
### Эталон
- Декартово дерево одновременно является деревом поиска по ключам и кучей по приоритетам.
- Порядок ключей задаёт симметричный обход, а приоритеты родителей не хуже приоритетов детей.
- Для различных ключей и случайной перестановки приоритетов ожидаемая глубина узла равна $O(\log n)$; ожидаемая высота дерева также $O(\log n)$.
- Это ожидаемая оценка по случайным приоритетам, а не гарантия для каждого их набора.

## aisd-q-604
ticket: aisd-t-069 · level: L1
Докажите, что для набора пар (ключ, приоритет) с попарно различными ключами и попарно различными приоритетами декартово дерево существует и единственно.
### Эталон
- Корнем обязана быть пара с наибольшим (для max-кучи) приоритетом: она должна быть выше всех по свойству кучи.
- Все пары с ключом меньше ключа корня обязаны лежать в левом поддереве, с большим — в правом (свойство дерева поиска).
- Левое и правое поддеревья — декартовы деревья своих наборов; по индукции по числу пар каждое существует и единственно.
- Значит, и всё дерево существует (собираем рекурсивно) и единственно.

## aisd-q-605
ticket: aisd-t-070 · level: L0
Каковы предусловия и результаты операций `split` и `merge` в декартовом дереве?
### Эталон
- `split(T, x)` делит дерево $T$ на два дерева с ключами соответственно $<x$ и $\ge x$.
- `merge(A, B)` объединяет деревья при условии, что каждый ключ $A$ меньше каждого ключа $B$.
- Результаты обеих операций сохраняют порядок поиска по ключам и свойство кучи по приоритетам.

## aisd-q-606
ticket: aisd-t-070 · level: L1
Опишите рекурсивные шаги `split` и `merge` в декартовом дереве и укажите, почему сохраняются его инварианты.
### Эталон
- При `split(T,x)`, если ключ корня меньше $x$, рекурсивно делят правое поддерево; результат с ключами $<x$ присоединяют к корню справа.
- Если ключ корня не меньше $x$, рекурсивно делят левое поддерево; результат с ключами $\ge x$ присоединяют к корню слева.
- При `merge(A,B)` с упорядоченными диапазонами корнем становится корень с лучшим приоритетом; рекурсивно объединяется только его граничное поддерево.
- Порядок ключей следует из предусловия и разбиения по ключу, свойство кучи — из выбора лучшего приоритета корня.
- Время пропорционально длине изменяемого пути; при случайных приоритетах ожидаемое время $O(\log n)$.

## aisd-q-607
ticket: aisd-t-071 · level: L0
Как выражаются операции `insert` и `erase` в декартовом дереве через `split` и `merge`?
### Эталон
- При вставке ключа дерево разделяют по этому ключу, затем объединяют левую часть, новый узел и правую часть.
- При удалении ключ отделяют двумя разбиениями, удаляют узел с этим ключом и объединяют оставшиеся части.
- Приоритет нового узла выбирается по той же схеме, что и при построении дерева.

## aisd-q-608
ticket: aisd-t-071 · level: L1
Объясните реализацию `insert` и `erase` через `split` и `merge`; почему сохраняются порядок поиска и свойство кучи?
### Эталон
- Для `insert(x)` сначала получают части с ключами $<x$ и $\ge x$, затем объединяют их с новым узлом в порядке ключей.
- Для уникальных ключей при `erase(x)` сначала отделяют ключи $<x$, затем из остатка — ключи $\le x$; средняя часть содержит удаляемый ключ, если он существовал.
- После удаления объединяют оставшиеся части, поскольку все ключи левой части меньше ключей правой.
- Каждый `split` и `merge` сохраняет оба инварианта декартова дерева; итоговые ожидаемые времена — $O(\log n)$ при случайных приоритетах.
