## aisd-q-508
ticket: aisd-t-061 · level: L0
Как дерево поиска по неявному ключу находит элемент по его позиции?
### Эталон
- Позиции считаются относительно всей последовательности, а не как ключи, хранящиеся в вершинах.
- При спуске от корня сравнивают искомую позицию с размером левого поддерева; если идут вправо, вычитают размер левого поддерева и саму текущую вершину.
- Повторяя шаг, находят вершину, занимающую заданную позицию; операция занимает время, пропорциональное высоте дерева.

## aisd-q-509
ticket: aisd-t-062 · level: L0
Определите коллизию, универсальное семейство и $k$-независимость семейства хеш-функций.
### Эталон
- Коллизия — равенство хешей двух различных ключей.
- Семейство $\mathcal H$ универсально, если для любых различных $x,y$ вероятность $h(x)=h(y)$ при равномерном выборе $h\in\mathcal H$ не превосходит $1/m$ для $m$ ячеек.
- Семейство $k$-независимо, если для любого набора из не более чем $k$ различных ключей их хеши совместно равномерно распределены по всем наборам значений в соответствующей степени $m$.
- Универсальность соответствует ограничению парных коллизий; $k$-независимость задаёт совместное распределение до $k$ значений.

## aisd-q-510
ticket: aisd-t-063 · level: L0
Как устроена хеш-таблица с цепочками и что делает `rehash`?
### Эталон
- Массив ячеек хранит цепочки ключей с одинаковым индексом хеша.
- `find` просматривает цепочку, `insert` добавляет ключ в неё, `erase` удаляет найденный ключ.
- `rehash` создаёт массив нового размера и заново помещает в него все ключи согласно новому диапазону хешей.
- При коэффициенте заполнения $n/m=O(1)$ и равномерном распределении ключей ожидаемая длина цепочки ограничена, поэтому операции ожидаемо $O(1)$; в худшем случае они занимают $O(n)$.

## aisd-q-511
ticket: aisd-t-063 · level: L1
Опишите поиск, вставку и удаление в таблице с цепочками; почему изменение размера требует повторного хеширования?
### Эталон
- Индекс цепочки вычисляется хеш-функцией; поиск сравнивает ключ со всеми элементами этой цепочки.
- Для семантики множества вставка сначала проверяет отсутствие дубликата, затем добавляет ключ в соответствующую цепочку; удаление исключает найденный узел. Для мультимножества реализация может хранить повторы и не выполнять такую проверку.
- При смене числа ячеек меняется отображение хешей в индексы, поэтому ключи нужно распределить по новым цепочкам заново.
- При коэффициенте заполнения $n/m=O(1)$ и равномерном распределении ожидаемая длина цепочки $O(1)$; худшее время — $O(n)$.

## aisd-q-512
ticket: aisd-t-064 · level: L1
Как строится двухуровневое совершенное хеширование для статического множества и почему суммарный объём вторых таблиц ожидаемо линеен?
### Эталон
- На первом уровне универсальной функцией распределяют ключи по $n$ корзинам. Для пустой корзины вторичную таблицу не выделяют; для непустой корзины размера $b_i$ выделяют $b_i^2$ ячеек (в частности, одну ячейку при $b_i=1$).
- Вторичную функцию выбирают из универсального семейства, пока в корзине не исчезнут коллизии.
- Для универсального хеширования вероятность коллизии пары не более $1/n$, поэтому ожидаемое число коллидирующих пар корзины пропорционально $b_i(b_i-1)/n$.
- Сумма размеров вторичных таблиц $\sum_i b_i^2=n+2\sum_i {b_i\choose2}$ (включая нулевой размер пустой корзины) имеет ожидание $O(n)$.

## aisd-q-517
ticket: aisd-t-065 · level: L0
Как открытая адресация разрешает коллизии и как выполняются поиск, вставка и удаление?
### Эталон
- Все ключи хранятся непосредственно в массиве; при коллизии пробирование перебирает последовательность ячеек.
- Поиск следует той же последовательности до ключа или действительно пустой ячейки; вставка помещает ключ в первую доступную позицию.
- Для удаления используют метку tombstone, чтобы не прервать поиск ключей, вставленных позже в той же последовательности.
- При изменении размера таблицы живые ключи вставляют заново; при коэффициенте заполнения, ограниченном константой меньше единицы, операции ожидаемо занимают $O(1)$ при подходящих предположениях о хешировании, а в худшем случае — $O(n)$.
