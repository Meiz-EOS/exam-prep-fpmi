## aisd-q-301
ticket: aisd-t-028 · level: L0
Какова асимптотическая сложность построения кучи из массива снизу вверх с помощью `heapify`?
### Эталон
- Построение двоичной кучи снизу вверх с помощью `heapify` выполняется за $O(n)$ времени.
- Это асимптотически лучше, чем $O(n\log n)$ при последовательных вставках.

## aisd-q-302
ticket: aisd-t-029 · level: L0
Опишите Heap Sort на массиве с max-heap и укажите порядок результата, временную сложность и дополнительную память.
### Эталон
- Из массива строится max-heap, затем максимум последовательно меняется местами с последним элементом активной части; сортировка выполняется на месте.
- После каждого обмена куча восстанавливается на укороченной части массива.
- Итоговый массив упорядочен по возрастанию.
- Время — $O(n\log n)$ в худшем случае; дополнительная память — $O(1)$ при сортировке на месте.

## aisd-q-303
ticket: aisd-t-030 · level: L0
Как удалить элемент из бинарной кучи по указателю, позволяющему получить его индекс?
### Эталон
- Элемент на позиции $i$ заменяют последним элементом кучи и уменьшают размер на один.
- Если удалённый элемент был последним, просеивание не требуется; иначе для восстановления свойства кучи выполняют sift-up или sift-down из позиции $i$.
- Время — $O(\log n)$, если индекс известен.

## aisd-q-304
ticket: aisd-t-030 · level: L1
Почему после замены удаляемого элемента последним достаточно выбрать одно направление просеивания?
### Эталон
- Для min-heap, если новый элемент меньше родителя, нарушено только отношение с родителем; sift-up восстанавливает путь к корню.
- Иначе отношение с родителем выполнено, а возможное нарушение находится среди детей; sift-down восстанавливает путь к листу. Для max-heap рассуждение симметрично с обратными сравнениями.
- Все остальные связи кучи не затронуты заменой.

## aisd-q-305
ticket: aisd-t-031 · level: L0
Какова сложность удаления одного найденного вхождения заданного значения из обычной двоичной кучи без дополнительного индекса, если значения могут повторяться?
### Эталон
- Сначала требуется найти одно вхождение элемента; в обычном массивном представлении без дополнительного индекса поиск занимает $O(n)$ даже при наличии дубликатов.
- После нахождения его удаляют заменой последним элементом и просеиванием за $O(\log n)$.
- Общая сложность — $O(n)$.

## aisd-q-306
ticket: aisd-t-031 · level: L1
Почему удаление по значению в обычной двоичной куче не имеет гарантии $O(\log n)$?
### Эталон
- Свойство кучи ограничивает родителя и детей, но не задаёт полного порядка между узлами.
- Поэтому значение может находиться в любой части массива, и в худшем случае проверяются все $n$ элементов.
- После поиска исправление кучи занимает не более $O(\log n)$.

## aisd-q-307
ticket: aisd-t-032 · level: L0
Дайте определения биномиального дерева и биномиальной кучи.
### Эталон
- Биномиальное дерево $B_0$ состоит из одного узла; $B_k$ получают соединением двух деревьев $B_{k-1}$, делая корень одного ребёнком корня другого.
- Дерево $B_k$ имеет $2^k$ узлов, а корень имеет степень $k$.
- Биномиальная куча — лес биномиальных деревьев с heap-порядком и не более чем одним деревом каждого ранга.
- Слияние удобно выполнять по разрядам размеров лесов, как сложение двоичных чисел.

## aisd-q-308
ticket: aisd-t-032 · level: L1
В чём преимущество биномиальной кучи перед двоичной при слиянии двух куч?
### Эталон
- В лесу биномиальной кучи ранги деревьев соответствуют единичным битам числа узлов.
- Равные по рангу деревья связываются в дерево следующего ранга, подобно переносу при сложении.
- Слияние требует $O(\log n)$ времени; у обычной двоичной кучи слияние в общем случае требует линейного времени.

## aisd-q-309
ticket: aisd-t-033 · level: L0
Укажите временные оценки операций биномиальной кучи из билета.
### Эталон
- `merge` и `insert` — $O(\log n)$ в худшем случае.
- `getMin` — $O(\log n)$ при поиске минимума среди корней леса без отдельного указателя на минимальный корень; при наличии такого указателя операция занимает $O(1)$.
- `extractMin` и `decreaseKey` — $O(\log n)$ в худшем случае.
