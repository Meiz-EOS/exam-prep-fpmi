## aisd-c-0301 · aisd-t-031
Как удалить из бинарной кучи элемент по значению, если указателя на него нет?
---
Нужна `erase(x)` — удалить число $x$ (оно обязано быть в куче). Найти $x$ быстро нельзя: куча упорядочена слабо, пришлось бы обойти всё дерево. Трюк с двумя кучами: $A$ — все добавленные, $D$ — «удалённые».
- `insert(x)`: вставить в $A$; `erase(x)`: вставить в $D$, из $A$ не удаляем;
- перед `getMin` и `extractMin`: пока минимумы $A$ и $D$ совпадают, извлекаем минимум из обеих.
Время: $N$ операций — суммарно $O(N\log N)$, в среднем на операцию $O(\log N)$, хотя один `getMin` может выбросить много элементов.
Идея: пока минимум $A$ не удалён, удалённые глубже не мешают; если удалён — он совпадёт с минимумом $D$ и выбросится. Каждый удалённый выбрасывается ровно один раз.
Подвох: `erase` числа, которого нет в куче, ломает структуру.
См.: конспект, «Лекция 4, По значению»

## aisd-c-0327 · aisd-t-031
Каковы учётные стоимости операций кучи с удалением по значению (две кучи $A$ и $D$) и как их доказать?
---
$A$ — все вставленные, $D$ — удалённые; `getMin` и `extractMin` сначала выбрасывают совпадающие минимумы. Учётные стоимости ($N$ — число запросов): `insert` — $O^*(\log N)$; `erase`, `getMin`, `extractMin` — $O^*(1)$. В худшем случае `insert` и `erase` — $O(\log N)$, отдельный `getMin` может работать долго.
Идея доказательства:
1. Пусть $k$ вставок. Каждый элемент участвует не более чем в 4 операциях с кучами по $O(\log N)$: вставка в $A$, в $D$, извлечения из $A$ и $D$ (включая выбрасывания в `getMin`).
2. Остальная работа — $O(1)$ на запрос.
3. Итого $O(k\log N+N)=O(k\log N+(N-k)\cdot1)$ — сумма учётных стоимостей.
Подвох: долгий `getMin` оплачен прошлыми вставками выбрасываемых элементов.
См.: конспект, «Лекция 5, Пример: куча с удалением по значению»

## aisd-c-0302 · aisd-t-032
Что такое биномиальное дерево порядка $k$?
---
Биномиальное дерево порядка (в конспекте — ранга) $k$, $T_k$: $T_0$ — одна вершина; $T_{k+1}$ — из двух $T_k$: корень одного подвешивается ребёнком к корню другого. Выполнено требование кучи: ребёнок не меньше родителя.
Свойства (индукция по $k$):
- $2^k$ вершин: $2^{k+1}=2^k+2^k$;
- глубина $k$: подвешивание добавляет 1;
- у корня ровно $k$ детей — корни $T_0,\dots,T_{k-1}$ (у корня $T_{k+1}$ дети корня $T_k$ плюс корень второй копии).
Подвох: дерево не бинарное; после удаления корня $T_k$ остаются деревья попарно различных рангов — на этом основан `extractMin`.
См.: конспект, «Лекция 5, Биномиальные деревья и биномиальная куча»

## aisd-c-0303 · aisd-t-032
Что такое биномиальная куча и в чём её преимущество перед двоичной?
---
Биномиальная куча — набор биномиальных деревьев попарно различных рангов ($T_1,T_3,T_4$ — можно, $T_3,T_5,T_5$ — нет).
При $n$ элементах $n=\sum2^k$ по рангам — это двоичная запись $n$: $T_k$ есть тогда и только тогда, когда $k$-й разряд $n$ равен 1 ($11=1011_2$: $T_3,T_1,T_0$). Деревьев $\le\lfloor\log_2n\rfloor+1$, глубина каждого $\le\log_2n$.
Хранятся массив корней по рангам и указатель на минимальный корень; у вершины — указатель на родителя (для `decreaseKey`).
Преимущество: `merge` двух куч за $O(\log n)$; двоичной куче пришлось бы перекладывать элементы по одному — время пропорционально размеру. Остальные операции $O(\log n)$, `getMin` — $O(1)$.
Подвох: минимум — наименьший из корней, а не единственный корень.
См.: конспект, «Лекция 5, Биномиальные деревья и биномиальная куча»

## aisd-c-0304 · aisd-t-033
Как выполняются merge и insert в биномиальной куче?
---
`merge(H1, H2)` — сложение двоичных чисел столбиком. Склейка двух $T_k$ за $O(1)$: дерево с большим корнем подвешиваем к меньшему — получаем $T_{k+1}$.
Идём по рангам $k=0,1,\dots$ с «переносом». В разряде 0–3 дерева (из $H_1$, $H_2$, перенос): 0 — пусто; 1 — в результат; 2 — склеиваем в перенос ($1+1=10_2$); 3 — одно в результат, два в перенос ($1+1+1=11_2$). В конце проходом по корням ищем минимум.
`insert(x)`: куча из одного $T_0$ сливается с основной.
Время обеих $O(\log n)$, $n=n_1+n_2$: $O(\log n)$ разрядов по $O(1)$.
Идея корректности: новое ребро — от меньшего корня к большему, требование кучи сохранено; ранги различны, как разряды суммы.
Подвох: склеивать можно только деревья одного ранга.
См.: конспект, «Лекция 5, Операции»

## aisd-c-0305 · aisd-t-033
Каковы времена `getMin`, `extractMin` и `decreaseKey` в биномиальной куче?
---
Хранятся массив корней (по рангам) и указатель на минимальный корень.
- `getMin` — $O(1)$: минимум дерева в корне, указатель хранится (прочие операции пересчитывают его проходом по корням за $O(\log n)$).
- `extractMin` — $O(\log n)$: удаляем минимальный корень $T_k$; его дети — корни $T_0,\dots,T_{k-1}$, корректная куча $H_2$; остальные деревья — $H_1$; ответ `merge(H1, H2)`.
- `decreaseKey(p, delta)` — $O(\log n)$: уменьшаем число и, пока оно меньше родительского, меняем местами (нужен указатель на родителя); глубина $O(\log n)$. Изменился корень — сравниваем с минимумом.
Подвох: `decreaseKey` меняет числа, а не вершины — сохранённый указатель может указывать уже на другое число.
См.: конспект, «Лекция 5, Операции»

## aisd-c-0306 · aisd-t-034
Что такое амортизационный анализ и учётное время работы?
---
Амортизационный анализ оценивает суммарное время серии операций, а не каждую отдельно.
Определение. Структура поддерживает $M$ типов запросов. Функции $a_1(n),\dots,a_M(n)$ — учётные (амортизированные) стоимости, если для любого $N$ и любой последовательности из $N$ запросов типов $t_1,\dots,t_N$ суммарное время есть $O(a_{t_1}+\dots+a_{t_N})$. Обозначение: $O^*(\log n)$.
Примеры: операция за $O(f)$ в худшем случае имеет учётную стоимость $f$ (у двоичной кучи всё $O^*(\log n)$); куча с удалением по значению: `insert` — $O^*(\log N)$, остальное — $O^*(1)$.
Подвох: это не «в среднем» по случайности — гарантия для любой последовательности; отдельная операция может быть намного дольше учётной стоимости.
См.: конспект, «Лекция 5, Амортизационный анализ»

## aisd-c-0307 · aisd-t-035
Как метод монеток объясняет амортизированную сложность очереди на двух стеках?
---
Очередь: стек $A$ — хвост, $D$ — голова. `push(x)` кладёт в $A$; `pop`, `front` работают с $D$, а если $D$ пуст — перекладывают в него всё из $A$ (наверху $D$ оказывается самый старый). Все операции — учётное $O(1)$; один `pop` в худшем случае $\Theta(n)$.
Монетки [не по конспекту]: `push` кладёт на элемент 2 монетки — на снятие с $A$ и кладку в $D$; перекладка $k$ элементов ($2k$ действий) оплачена ими, банк не в минусе. Учётно `push` — $1+2$, `pop` и `front` — $O(1)$.
В конспекте — подсчётом: каждый элемент один раз кладётся в $A$, снимается с $A$, кладётся в $D$ и снимается с $D$ — не больше $4n$ операций со стеками на $n$ добавленных.
Подвох: перекладывать только при пустом $D$, иначе нарушится порядок.
См.: конспект, «Лекция 7, Задача 3: минимум в скользящем окне»

## aisd-c-0328 · aisd-t-035
В чём состоит метод монеток (бухгалтерского учёта) и почему он даёт учётные стоимости?
---
Идея: размазать стоимость редких тяжёлых операций по частым лёгким. Ведём счёт; монета оплачивает $O(1)$ действий. $t_i$ — реальное время $i$-го запроса; при нём кладём $d_i\ge0$ монет и снимаем $w_i\ge0$.
Теорема. Если баланс всегда неотрицателен (не снимаем ещё не положенного), то $a_i=t_i+d_i-w_i$ — учётные стоимости.
Доказательство: $$\sum a_i=\sum t_i+\Big(\sum d_i-\sum w_i\Big),$$ в скобках — итоговый баланс, он $\ge0$. Значит $\sum t_i\le\sum a_i$, то есть $\sum t_i=O(\sum a_i)$.
Смысл: лёгкая операция откладывает на будущее (учётно $t_i+d_i$), тяжёлая платит накопленным (при $w_i=t_i$ учётно 0).
Подвох: баланс должен быть $\ge0$ в любой момент любой последовательности; в коде монет нет.
См.: конспект, «Лекция 6, Почему метод бухучёта корректен»

## aisd-c-0308 · aisd-t-036
Как устроен вектор на динамическом массиве и какова амортизированная стоимость `push_back`?
---
Динамический массив (`std::vector`): `a[i]`, `push_back(x)`, `pop_back()`. Выделено $C$ ячеек (capacity), заняты первые $S$ (size); элементы подряд, поэтому `a[i]` — $O(1)$.
`push_back(x)`: если $S<C$, пишем в ячейку $S$ и увеличиваем $S$ — $O(1)$. Если $S=C$: выделяем массив $2C$, перекладываем $S$ элементов, освобождаем старый, кладём $x$ — $\Theta(C)$.
Итого `push_back` — учётное $O^*(1)$, в худшем случае $\Theta(n)$.
Идея: вместимость растёт степенями двойки, расширения экспоненциально реже (после расширения до 32 следующее через 16 вставок, после 64 — через 32).
Подвох: при $S=C$ писать дальше нельзя — следующая ячейка может быть чужой; при $C=0$ новая вместимость 1.
См.: конспект, «Лекция 5, Динамический массив»

## aisd-c-0309 · aisd-t-036
Каковы затраты динамического вектора на доступ и вставки?
---
Выделено $C$ ячеек, занято $S$; при заполнении вместимость удваивается, при $S<\frac C4$ после удаления — уменьшается вдвое.
- `a[i]` — $O(1)$ в худшем случае;
- `push_back` — учётное $O^*(1)$, в худшем случае $\Theta(C)$;
- `pop_back` — учётное $O^*(1)$: уменьшаем $S$; при $S<\frac C4$ выделяем $\frac C2$ ячеек, перекладываем, освобождаем старое;
- память: $C\le4S$ (кроме малых $S$) — линейна.
Почему порог $\frac14$: после любого перевыделения массив заполнен ровно наполовину, до следующего нужно много операций; при пороге $\frac12$ чередование `push_back`/`pop_back` на границе перевыделяло бы каждый раз.
Подвох: `std::vector` при `pop_back` память не освобождает; сжатие нужно ради линейной памяти.
См.: конспект, «Лекция 5, Динамический массив»

## aisd-c-0329 · aisd-t-036
Как методом монеток доказать, что `push_back` и `pop_back` в динамическом массиве работают за учётное $O(1)$?
---
Теорема. При удвоении и сжатии вдвое (при заполненности меньше четверти) `push_back` и `pop_back` — учётное $O^*(1)$.
Идея доказательства: перевыделение вместимости $C$ стоит $\le4C$ действий; каждая `push_back`/`pop_back` кладёт в банк 10 монет. После перевыделения вместимость $C'$, элементов $\frac{C'}{2}$.
1. До расширения нужно $\ge\frac{C'}{2}$ операций — $\ge5C'$ монет; расширение стоит $4C'$ с небольшим.
2. До сжатия размер падает ниже $\frac{C'}{4}$: $\ge\frac{C'}{4}$ операций — $\ge\frac{5C'}{2}$ монет; сжатие $\le\frac{C'}{2}+\frac{C'}{4}+C'<2C'$.
Каждое перевыделение оплачено монетами, накопленными после предыдущего; банк не в минусе.
Подвох: ключ — половинная заполненность после перевыделения (отсюда порог $\frac14$); $\pm1$ и малые $C$ меняют только константу.
См.: конспект, «Лекция 5, Анализ динамического массива»

## aisd-c-0310 · aisd-t-037
Для какой задачи подходит Sparse Table и как она устроена?
---
Задача (RMQ): неизменяемый массив $a$ длины $n$; запросы — $\min(a_l,\dots,a_r)$ для произвольных $l\le r$.
Храним минимумы на отрезках длины степени двойки: $sp[k][i]=\min(a_i,\dots,a_{i+2^k-1})$.
Построение: на лекции строку $k$ считали как минимумы в окне длины $2^k$ (очередь с минимумом) за $O(n)$; проще рекуррентно: $sp[0][i]=a_i$, $sp[k][i]=\min(sp[k-1][i],\ sp[k-1][i+2^{k-1}])$. Строк около $\log_2n$ — время и память $O(n\log n)$; запрос $O(1)$.
Применимость: массив статический; операция терпит повторный учёт (минимум, максимум, НОД), сумма — нет.
Подвох: в строке $k$ только $n-2^k+1$ значений; при изменении элемента пересчитывать всё — нужно дерево отрезков.
См.: конспект, «Лекция 7, Sparse Table: минимум на отрезке»

## aisd-c-0311 · aisd-t-037
Как ответить на запрос минимума на отрезке за $O(1)$ с помощью Sparse Table?
---
Предподсчитаны $sp[k][i]=\min(a_i,\dots,a_{i+2^k-1})$. Для $[l,r]$: $m=r-l+1$, $k$ — максимальное с $2^k\le m$. Отрезки $[l,\,l+2^k-1]$ и $[r-2^k+1,\,r]$ (возможно, пересекаются) покрывают $[l,r]$; ответ $\min(sp[k][l],\ sp[k][r-2^k+1])$ — $O(1)$ в худшем случае.
Идея доказательства: оба внутри $[l,r]$, так как $2^k\le m$; если бы не покрыли, то $2^{k+1}\le m$ — противоречие с максимальностью $k$. Дважды учтённые числа минимум не меняют.
$k$ за $O(1)$: заранее `lg[1] = 0`, `lg[m] = lg[m / 2] + 1` для всех $m\le n$ — $O(n)$.
Пример: $a=(5,2,4,7,1,3,6,8)$, $[1,6]$: $m=6$, $k=2$, $\min(sp[2][1],sp[2][3])=1$.
Подвох: для суммы перекрытие не годится; логарифм циклом на каждом запросе — уже не $O(1)$.
См.: конспект, «Лекция 7, Sparse Table: минимум на отрезке»

## aisd-c-0312 · aisd-t-038
Какова модельная задача для дерева отрезков и его инвариант?
---
Задача: массив $a_0,\dots,a_{n-1}$; `update(pos, val)`: $a_{pos}$ += $val$; `getSum(l, r)`: $a_l+\dots+a_r$. Префиксные суммы не годятся: одно изменение меняет $\Theta(n)$ из них.
Над массивом бинарное дерево, в листьях $a_i$. Инвариант: вершина контролирует отрезок (листья своего поддерева) и хранит сумму на нём.
Нумерация как в куче: корень 1 — $[0,n-1]$; у $v$ с $[l,r]$, $l<r$, при $m=\lfloor(l+r)/2\rfloor$ левый сын $2v$ — $[l,m]$, правый $2v+1$ — $[m+1,r]$; $l=r$ — лист.
Идея: `update` меняет суммы только на пути корень–лист; запрос разбивается на несколько вершин с готовыми суммами. Обе операции $O(\log n)$, массив размера $4n$.
Подвох: в отличие от Sparse Table, массив может меняться; хранить можно не только сумму.
См.: конспект, «Лекция 8, Задача и устройство дерева отрезков»

## aisd-c-0313 · aisd-t-038
Каковы времена построения и операций дерева отрезков?
---
Вершина $v$ контролирует $[tl,tr]$, хранит сумму `t[v]`, дети $2v$ и $2v+1$.
- `update(pos, val)` — $O(\log n)$: один спуск без ветвлений, на пути `t[v] += val`.
- `getSum(l, r)` — $O(\log n)$ (примерно не больше $4\log_2n$ вершин).
- Память: массив размера $4n$; построение по массиву $O(n)$ [не по конспекту].
```cpp
long long getSum(int v, int tl, int tr, int l, int r) {
    if (l <= tl && tr <= r) return t[v];
    int tm = (tl + tr) / 2;
    long long res = 0;
    if (l <= tm) res += getSum(2 * v, tl, tm, l, r);
    if (r > tm) res += getSum(2 * v + 1, tm + 1, tr, l, r);
    return res;
}
```
Идея доказательства ($4n$): $N\ge n$ — ближайшая сверху степень двойки, $N<2n$; дерево для $n$ не глубже, чем для $N$; при глубине $d$ номера $<2^{d+1}$, то есть $<2N<4n$.
Подвох: $2n$ мало: при $n=6$ номер $13=2n+1$.
См.: конспект, «Лекция 8, update и getSum»

## aisd-c-0330 · aisd-t-038
Почему запрос суммы на отрезке в дереве отрезков работает за $O(\log n)$, хотя рекурсия может раздваиваться?
---
`getSum(v, tl, tr, l, r)`: вершина целиком в запросе — вернуть `t[v]`; иначе $tm=\lfloor(tl+tr)/2\rfloor$, влево при $l\le tm$, вправо при $r>tm$.
Идея доказательства:
1. Случай $r\ge tr$: при раздвоении $l\le tm$, правый сын $[tm+1,tr]$ целиком в запросе и сразу завершается; в левом условие сохраняется. Не больше 2 вершин на уровень — $O(\log n)$.
2. Случай $l\le tl$ — симметрично.
3. Общий: до первого раздвоения (в вершине $u$) путь один; дальше левый сын $u$ — случай 1, правый — случай 2. Итого $O(\log n)$, примерно $\le4\log_2n$ вершин.
Подвох: тяжёлый пример — запрос $[1,n-2]$: раздвоение в корне, затем на каждом уровне в обоих поддеревьях.
См.: конспект, «Лекция 8, getSum работает за O(log n)»

## aisd-c-0314 · aisd-t-039
Как двоичным спуском найти первый префикс с суммой не меньше $x$?
---
Числа неотрицательны, `t[v]` — сумма отрезка вершины $v$. Ищем минимальное $R$ с $a_0+\dots+a_R\ge x$. Если `t[1] < x`, ответа нет. Иначе спуск из корня с $s=x$, инвариант `t[v] >= s`: если `t[2 * v] >= s` — влево с тем же $s$; иначе левый учтён целиком: `s -= t[2 * v]`, вправо. Лист — ответ.
```cpp
int descend(int v, int tl, int tr, long long s) {  // t[v] >= s
    while (tl < tr) {
        int tm = (tl + tr) / 2;
        if (t[2 * v] >= s) { v = 2 * v; tr = tm; }
        else { s -= t[2 * v]; v = 2 * v + 1; tl = tm + 1; }
    }
    return tl;
}
```
Время $O(\log n)$: один спуск без ветвлений.
Идея доказательства: если $t[2v]<s$, то в правом сыне нужно набрать $s-t[2v]\le t[2v+1]$ — инвариант сохраняется.
Подвох: нужна неотрицательность (сумма монотонна по $R$); бинпоиск по $R$ с `getSum` — $O(\log^2n)$.
См.: конспект, «Лекция 8, Задача 2: бинарный спуск»

## aisd-c-0315 · aisd-t-039
Как найти подотрезок с суммой $\geq x$ двоичным спуском в дереве отрезков?
---
Числа неотрицательны; `set(pos, val)`: $a_{pos}=val$; `lowerBound(L, S)`: минимальное $R\ge L$ с $a_L+\dots+a_R\ge S$. $O(\log n)$ на запрос.
Идея:
1. Разбиваем $[L,n-1]$ на $O(\log n)$ вершин слева направо, как в `getSum`.
2. Накапливаем их суммы, пока не станет $\ge S$; ответ в вершине $v$, где это случилось впервые; если до неё набрано $acc$, внутри нужно $s=S-acc$.
3. Спуск в $v$ ($t[v]\ge s$): если $t[2v]\ge s$ — влево, иначе вычитаем $t[2v]$ из $s$ и вправо; в листе — индекс.
Пример: $S=10$, суммы вершин 5, 3, 7, 1: после двух $8<10$, после третьей $15$ — в третьей ищем префикс с суммой $\ge2$.
Подвох: если и сумма до конца меньше $S$ — ответа нет ($-1$); бинпоиск по $R$ с `getSum` — $O(\log^2n)$.
См.: конспект, «Лекция 8, Задача 2: бинарный спуск»

## aisd-c-0316 · aisd-t-040
Как поддержать присваивание константы на отрезке в дереве отрезков?
---
`assign(l, r, x)`: $a_l=\dots=a_r=x$; `getMin(l, r)` (и `getSum`). Разбиваем $[l,r]$ на $O(\log n)$ вершин и ставим пометку «всё поддерево равно $x$», не спускаясь ниже: минимум $x$, сумма $x\cdot(tr-tl+1)$.
Вершина хранит минимум, сумму и пометку (нет или $x$). Инвариант: минимум и сумма учитывают свою пометку, но могут не учитывать пометки предков; верное значение задаёт самая высокая пометка на пути от корня — она поставлена позже всех.
Перед спуском в детей — `push`, после возврата минимум и сумма пересчитываются по детям. Все операции $O(\log n)$: `push` — $O(1)$, только в посещённых вершинах.
Корректность: спуск от корня с `push` — пометки предков уже стекли; новая пометка — самая высокая в поддеревьях разбиения, как и нужно последнему присваиванию.
Подвох: нужен отдельный признак «пометки нет» — $x$ может быть и 0.
См.: конспект, «Лекция 8, Задача 3: отложенные операции»

## aisd-c-0317 · aisd-t-040
Что делает `push` в дереве отрезков с отложенным присваиванием?
---
Вершина: минимум `mn`, сумма `sum`, пометка «поддерево равно $x$» (`has`, `val`). `push(v)` вызывается перед каждым спуском из $v$ (в `assign` и запросах): если пометка есть, ставит её обоим детям, затирая старые, пересчитывает им минимум ($=x$) и сумму ($=x\cdot$ длина), снимает пометку с $v$.
```cpp
void apply(int v, int tl, int tr, long long x) {
    has[v] = true; val[v] = x;
    mn[v] = x; sum[v] = x * (tr - tl + 1);
}
void push(int v, int tl, int tr) {
    if (!has[v]) return;
    int tm = (tl + tr) / 2;
    apply(2 * v, tl, tm, val[v]);
    apply(2 * v + 1, tm + 1, tr, val[v]);
    has[v] = false;
}
```
Время $O(1)$.
Идея корректности: пометка $v$ выше пометок детей, значит, поставлена позже — затирать их верно; значения в самой $v$ не меняются.
Подвох: длины сыновей разные — сумма по отрезку каждого.
См.: конспект, «Лекция 8, Задача 3: отложенные операции»

## aisd-c-0318 · aisd-t-041
Как Fractional Cascading ускоряет запрос числа элементов $\leq x$ на отрезке?
---
Массив статический; `count(l, r, x)` — число $a_i\le x$ на $[l,r]$. Merge sort tree: вершина хранит свой отрезок отсортированным ($T_v$); бинпоиск в $O(\log n)$ вершинах — $O(\log^2n)$. Fractional cascading: при слиянии детей запоминаем $left_v[i]$ — сколько из первых $i$ элементов $T_v$ пришли из левого сына. Если в $T_v$ ровно $k$ элементов $\le x$, то в левом сыне их $left_v[k]$, в правом $k-left_v[k]$.
```cpp
int count(int v, int tl, int tr, int l, int r, int k) {
    if (l <= tl && tr <= r) return k;
    int tm = (tl + tr) / 2, kl = left[v][k], res = 0;
    if (l <= tm) res += count(2 * v, tl, tm, l, r, kl);
    if (r > tm) res += count(2 * v + 1, tm + 1, tr, l, r, k - kl);
    return res;
}
```
Бинпоиск один раз в корне даёт $k$, дальше спуск как в `getSum`, $O(1)$ на вершину — запрос $O(\log n)$.
Идея доказательства: элементы $\le x$ — префикс $T_v$; слияние сохраняет порядок внутри сына, значит, и в сыне это префикс.
Подвох: длина $left_v$ — $|T_v|+1$; изменения массива не поддерживаются.
См.: конспект, «Лекция 8, Fractional cascading: запрос за O(log n)»

## aisd-c-0319 · aisd-t-041
Каковы затраты дерева отрезков со списками для Fractional Cascading?
---
Merge sort tree: в вершине — отсортированный вектор её отрезка; число элементов $\le x$ на $[l,r]$, массив статический.
- Построение: вектор вершины — слияние векторов детей (стрелки считаются в том же слиянии). Время и память $O(n\log n)$.
- Запрос без стрелок: $O(\log n)$ вершин, в каждой бинпоиск — $O(\log^2n)$.
- Со стрелками: бинпоиск только в корне, дальше $O(1)$ на вершину — $O(\log n)$.
Идея доказательства: это дерево рекурсии merge sort — каждый элемент лежит в $O(\log n)$ векторах; стрелки — константа на элемент.
Пример: $a=(3,1,4,2)$, корень $(1,2,3,4)$, $left=(0,1,1,2,2)$; $x=3$ на $[2,3]$: в корне $k=3$, правому сыну $3-left[3]=1$ — ответ 1.
Подвох: изменения элементов структура не поддерживает.
См.: конспект, «Лекция 8, Задача 4: число элементов ≤ x на отрезке»

## aisd-c-0320 · aisd-t-042
Что такое динамическое дерево отрезков?
---
Задача: длина $n$ огромна (например, $10^{18}$), дерево размера $4n$ не построить; изначально нули; изменение в точке и сумма на отрезке; запросов $q$ немного. Динамическое (неявное) дерево хранит только вершины, в поддереве которых что-то происходило.
- Сначала только корень $[0,n-1]$, сумма 0, детей нет.
- `update(pos, val)`: спуск к листу; отсутствующего сына создаём с нулевой суммой; на пути обновляем сумму.
- `getSum(l, r)`: как обычно, несуществующий сын даёт 0.
Вершина: сумма и указатели на сыновей (не $2v$, $2v+1$).
`update` — $O(\log n)$ времени и новой памяти; `getSum` — $O(\log n)$, вершин не создаёт. Всего $O(q\log n)$ времени и памяти.
Подвох: достоинство — онлайн; оффлайн сжатие координат даёт память $O(q)$. Середина `tl + (tr - tl) / 2`, координаты в `long long`.
См.: конспект, «Лекция 9, Динамическое дерево отрезков»

## aisd-c-0321 · aisd-t-043
Как сжатие координат позволяет применять дерево отрезков к разреженным координатам?
---
Массив огромной длины, изначально нули; изменения в точке и сумма на отрезке; все запросы известны заранее (оффлайн). Меняются только точки $p_1,\dots,p_q$ («засечки»), остальные навсегда нули.
Идея:
1. Сортируем различные засечки, нумеруем $0,\dots,m-1$ ($m\le q$).
2. Строим обычное дерево отрезков на $m$ элементах.
3. `update(pos, val)`: бинпоиском номер засечки $pos$, обновляем его.
4. `getSum(l, r)`: границы переводим в номера засечек, сумма в маленьком дереве.
Время $O(q\log q)$, память $O(q)$ — выигрыш по памяти против динамического дерева ($O(q\log n)$).
Корректность: вне засечек нули, вклада нет; перенумерация сохраняет порядок.
Подвох: только оффлайн; повторы убрать (`sort` и `unique`).
См.: конспект, «Лекция 9, Оффлайн-запросы и сжатие координат»

## aisd-c-0322 · aisd-t-043
Как сохранить запросы на интервалах после сжатия координат?
---
Различные засечки отсортированы в `xs` и получили номера $0,\dots,m-1$, дерево построено по номерам. Границы `getSum(l, r)` не обязаны быть засечками: берём самую левую засечку $\ge l$ (номер $i$) и самую правую $\le r$ (номер $j$); при $i\le j$ ответ — сумма на $[i,j]$, иначе 0.
```cpp
long long getSum(long long l, long long r) {
    int i = lower_bound(xs.begin(), xs.end(), l) - xs.begin();
    int j = int(upper_bound(xs.begin(), xs.end(), r) - xs.begin()) - 1;
    if (i > j) return 0;
    return tree.getSum(i, j);
}
```
Время $O(\log q)$: два бинпоиска и запрос к дереву.
Корректность: вне засечек нули, а засечки из $[l,r]$ идут подряд — номера $i..j$.
Пример: засечки 3, 6, 10, 15, 20; $[5,17]$: 6 (номер 1) и 15 (номер 3) — сумма на $[1,3]$.
Подвох: $i>j$ (засечек нет) — отдельно; для правой границы `upper_bound` минус 1, а не `lower_bound`.
См.: конспект, «Лекция 9, Оффлайн-запросы и сжатие координат»

## aisd-c-0323 · aisd-t-044
Что такое персистентное дерево отрезков?
---
Персистентность — структура хранит все прежние версии; версия $v$ — после первых $v$ изменений. Изменение в точке создаёт новую версию; `getSum(v, l, r)` — сумма в версии $v$.
Идея: изменение затрагивает $O(\log n)$ вершин пути корень–лист. Старые не трогаем, для каждой вершины пути — новая копия: сын на пути новый, другой — прежний. Вершина: сумма и указатели на сыновей; `root[v]` — корень версии $v$; запрос — обычный `getSum` из `root[v]`.
```cpp
int add(int v, int tl, int tr, int pos, long long val) {
    Node copy = nodes[v];
    copy.sum += val;
    if (tl < tr) {
        int tm = (tl + tr) / 2;
        if (pos <= tm) copy.left = add(copy.left, tl, tm, pos, val);
        else copy.right = add(copy.right, tm + 1, tr, pos, val);
    }
    nodes.push_back(copy);
    return nodes.size() - 1;
}
```
Корректность: из нового корня видна ровно новая версия — вдоль пути вершины новые, остальные ссылки ведут в неизменившиеся поддеревья.
Подвох: нумерация $2v$, $2v+1$ не годится; старые вершины менять нельзя.
См.: конспект, «Лекция 9, Персистентное дерево отрезков»

## aisd-c-0324 · aisd-t-044
Каковы затраты персистентного дерева отрезков с точечными обновлениями?
---
Изменение в точке создаёт версию, копируя путь корень–лист; корни версий в векторе `root`.
- `update` — $O(\log n)$ времени и $O(\log n)$ новых вершин;
- `getSum(v, l, r)` — $O(\log n)$: обычный запрос из `root[v]`, вершин не создаёт;
- после $q$ изменений память $O(q\log n)$ (в конспекте начальная версия — «пустая» вершина 0 из нулей).
Идея доказательства: на каждом уровне меняется одна вершина — чей отрезок содержит позицию; уровней $O(\log n)$; остальные поддеревья общие у старой и новой версий.
Сравнение: хранить версии целиком — $O(qn)$ памяти.
Подвох: версию создаёт только изменение, не запрос суммы; общие вершины менять на месте нельзя — испортятся старые версии.

## aisd-c-0325 · aisd-t-045
Как посчитать числа $\leq x$ на подотрезке с персистентным деревом?
---
Массив статический; запрос $(l,r,x)$ — сколько среди $a_l,\dots,a_r$ чисел $\le x$.
Идея: «убиваем» все элементы и оживляем по одному в порядке возрастания значений. Персистентное дерево по позициям: в листе $i$ 1, если $a_i$ жив, иначе 0; вершины хранят число живых. Версия $j$ — живы $j$ наименьших.

Подвох: равные значения оживляются по одному — берём верхнюю границу (`upper_bound`), где ожили все равные $x$.

Каковы затраты персистентного решения запроса количества значений $\leq x$?
---
Элементы оживляются по возрастанию значений в персистентном дереве по позициям (в листе 1, если элемент жив); версия $j$ — живы $j$ наименьших; запрос $(l,r,x)$ — сумма на $[l,r]$ в версии $j$, где $j$ — число элементов $\le x$.
