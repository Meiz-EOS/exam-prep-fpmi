## aisd-c-0201 · aisd-t-016
Как устроена цифровая сортировка LSD для ключей из $d$ цифр в системе счисления с основанием $k$ и почему она корректна?
---
Задача: отсортировать $n$ целых из $[0,K]$ при огромном $K$ (счётчиков не завести). Записываем числа в системе с основанием $k$, дополняя нулями слева до $d=O(\log_k K)$ цифр; сравнение чисел совпадает с лексикографическим сравнением записей. LSD (least significant digit): $d$ раз стабильно сортируем подсчётом — по младшей цифре, затем по следующей, …, по старшей.
Время $O(d(n+k))$ в худшем случае, память $O(n+k)$.
Идея доказательства: как для пар, индукция по проходам. Последний проход — по старшей цифре: при различных старших цифрах порядок верен, при равных стабильность сохраняет порядок, полученный по младшим разрядам.
Подвох: каждый проход стабилен; идём от младшего разряда к старшему.
См.: конспект, «Лекция 3, LSD sort»

## aisd-c-0202 · aisd-t-016
Каковы время и память LSD-сортировки для $n$ ключей длины $d$ в основании $k$ и как выбирать основание?
---
Проходов $d$, каждый — стабильная сортировка подсчётом за $O(n+k)$ ($k$ значений цифры). Время $O(d(n+k))$ в худшем случае, память $O(n+k)$. Для чисел до $K$: $d=O(\log_k K)$; при $k=10$ время $O(n\log K)$.
Основание $k=2^b$ удобно: цифра — блок из $b$ бит; младшая цифра `x & ((1 << b) - 1)` (это $x\bmod2^b$), отбросить её — `x >> b`; без деления.
Время $O\left(\frac{w}{b}(n+2^b)\right)$, $w$ — число бит; для 32 бит при $b=8$ — 4 прохода по $O(n+256)$. Если числа меньше $n^c$, то при $k=n$ проходов $c$ и время $O(cn)$. (Код на лекции дописан [не по конспекту].)
Подвох: $\Omega(n\log n)$ не нарушена — это не сравнения; слишком большое основание ($2^b\gg n$) делает проход дороже массива.
См.: конспект, «Лекция 3, LSD sort»

## aisd-c-0203 · aisd-t-017
Как устроены односвязный и двусвязный списки?
---
Двусвязный список — объекты, упорядоченные слева направо; каждый хранит значение и два указателя: `next` и `prev`. У первого `prev`, у последнего `next` равны `nullptr`; отдельно хранится `head`. Указатель — адрес объекта: соседа внутри узла хранить нельзя, только адрес. Обход $O(n)$ по `next`. Односвязный — только значение и `next` [не по конспекту]; память $O(n)$.
Идея: фиктивные `head_` и `tail_` по краям создаются один раз и не меняются: у любого настоящего узла всегда есть оба соседа, пропадают проверки «удаляем первый — сдвинуть `head`».
Подвох: доступа по индексу нет — $i$-й элемент за $O(i)$; в односвязном списке нельзя пойти назад и удалить узел, не зная предшественника. [не по конспекту]
См.: конспект, «Лекция 6, Двусвязные списки»

## aisd-c-0204 · aisd-t-017
Как выполняются вставка и удаление в двусвязном списке и каковы асимптотики операций со списком?
---
Удаление по указателю на узел $z$: $y$ = `z.prev`, $t$ = `z.next`; перешиваем: `y.next = t`, `t.prev = y`. Вставка после узла `pos` — аналогично.
```cpp
Node* insert_after(Node* pos, int value) {
    Node* v = new Node{value, pos, pos->next};
    pos->next->prev = v;
    pos->next = v;
    return v;
}
void erase(Node* v) {   // соседи есть: по краям head_ и tail_
    v->prev->next = v->next;
    v->next->prev = v->prev;
    delete v;
}
```
Время: удаление по указателю, вставка после узла, склейка двух списков (известны концы) — $O(1)$ в худшем случае; обход и поиск по значению — $O(n)$.
Подвох: $O(1)$ только при данном указателе, а не значении; без фиктивных узлов нужны случаи для краёв.
См.: конспект, «Лекция 6, Двусвязные списки»

## aisd-c-0205 · aisd-t-018
Как реализовать стек односвязным списком?
---
Стек: `push(x)` — положить $x$ наверх, `pop()` — удалить верхний, `top()` — вернуть верхний (LIFO). Узел хранит значение и указатель на элемент под ним (у нижнего `nullptr`); `top_` — голова списка.
```cpp
struct Node { int value; Node* below; };
Node* top_ = nullptr;
void push(int x) { top_ = new Node{x, top_}; }   // новая голова
int top() const { return top_->value; }          // стек не пуст
void pop() {                                     // стек не пуст
    Node* old = top_; top_ = top_->below; delete old;
}
```
Все операции — $O(1)$ в худшем случае, память $O(n)$.
Идея: `push` — вставка в начало списка, `pop` — удаление головы, `top` — чтение головы.
Подвох: `pop`, `top` на пустом стеке — разыменование `nullptr`. `std::stack` по умолчанию поверх `std::deque`.
См.: конспект, «Лекция 7, Стек»

## aisd-c-0206 · aisd-t-018
Каков инвариант и стоимость операций стека на списке?
---
Инвариант: `top_` указывает на последний добавленный и ещё не удалённый элемент; `below` ведут от вершины ко дну в порядке, обратном добавлению; у пустого стека `top_ == nullptr`.
Стоимость: `push`, `pop`, `top` — $O(1)$ в худшем случае (не учётная), память $O(n)$.
Идея доказательства: `push` создаёт узел, ссылающийся на старую голову, и делает его головой — порядок ниже не меняется; `pop` сдвигает голову на `below` — вершиной становится добавленный непосредственно перед удалённым. Инвариант сохраняется, `top` возвращает последний добавленный — LIFO.
Подвох: деструктор снимает все элементы (`while (!empty()) pop();`), иначе утечка; `pop`, `top` на пустом стеке не определены.
См.: конспект, «Лекция 7, Стек»

## aisd-c-0207 · aisd-t-019
Как проверить правильность скобочной последовательности с несколькими типами скобок?
---
ПСП: пустая строка; $(S)$, $[S]$, $\{S\}$ для ПСП $S$; конкатенация $S_1S_2$ ПСП; других нет. Идём слева направо со стеком ещё не закрытых открывающих скобок.
```cpp
std::vector<char> st;
for (char c : s) {
    if (c == '(' || c == '[' || c == '{') { st.push_back(c); continue; }
    char need = (c == ')') ? '(' : (c == ']') ? '[' : '{';
    if (st.empty() || st.back() != need) return false;
    st.pop_back();
}
return st.empty();
```
Время $O(n)$, память $O(n)$ в худшем случае.
Идея: закрывающая сопоставляется с ближайшей незакрытой открывающей — иначе вложенность нарушится.
Подвох: три отказа — стек пуст на закрывающей, тип вершины не тот, стек не пуст в конце. Счётчика мало: $([)]$ с верным балансом не ПСП. [не по конспекту]
См.: конспект, «Лекция 7, Задача 1: правильная скобочная последовательность»

## aisd-c-0208 · aisd-t-019
Какова сложность проверки скобок стеком и почему на любой ПСП алгоритм отвечает «да»?
---
Алгоритм: открывающую кладём в стек; для закрывающей требуем непустой стек с открывающей того же типа на вершине и снимаем её; в конце стек пуст. Время $O(n)$ в худшем случае, память $O(n)$ (строка из одних открывающих).
Идея доказательства (ПСП ⇒ «да», индукция по построению):
1. Пустая строка: стек пуст.
2. $S=(S_1)$: кладём открывающую; обработка $S_1$ добавляет и снимает только свои скобки, не заглядывая ниже; затем закрывающая сопоставляется с открывающей.
3. $S=S_1S_2$: $S_1$ начинается и кончается с тем же стеком, затем так же $S_2$.
Подвох: это половина корректности; обратное («не ПСП ⇒ нет») — через лемму о непересекающихся стрелках (следующая карточка).
См.: конспект, «Лекция 7, Задача 1: правильная скобочная последовательность»

## aisd-c-0233 · aisd-t-019
Сформулируйте критерий ПСП через отображение закрывающих скобок в открывающие и объясните, почему алгоритм со стеком отвечает «нет» на любой строке, не являющейся ПСП.
---
Лемма: $S$ — ПСП тогда и только тогда, когда существует биекция $f$ из позиций закрывающих скобок в позиции открывающих такая, что $f(j)<j$, типы $j$ и $f(j)$ совпадают, стрелки $j\to f(j)$ не пересекаются: для закрывающих $i<j$ либо $f(i)>f(j)$ (вложены), либо $i<f(j)$ (подряд); запрещено $f(i)<f(j)<i<j$.
Идея доказательства: (⇒) индукция по построению: для $(S_1)$ добавляем внешнюю стрелку, для $S_1S_2$ объединяем биекции. (⇐) индукция по длине: последняя скобка закрывающая, её стрелка ведёт в $p$; если $p$ — начало, то $S=(S_1)$, иначе $S=AB$, $B$ начинается с $p$, и стрелки границу не пересекают.
«Не ПСП ⇒ нет»: алгоритм строит $f$ — стрелка идёт в ближайшую свободную открывающую слева (в более левую она пересекла бы стрелку из промежуточной). Непересекающееся отображение единственно; при «да» оно построено, и по лемме $S$ — ПСП.
См.: конспект, «Лекция 7, Задача 1: правильная скобочная последовательность»

## aisd-c-0209 · aisd-t-020
Как найти ближайший строго меньший элемент слева для каждого элемента массива?
---
Для каждого $i$ найти наибольший $j<i$ с $a_j<a_i$ (или $-1$). Идём слева направо со стеком индексов; значения в нём строго возрастают от дна к вершине. [не по конспекту]
```cpp
std::vector<int> left(n, -1), st;
for (int i = 0; i < n; ++i) {
    while (!st.empty() && a[st.back()] >= a[i]) st.pop_back();
    if (!st.empty()) left[i] = st.back();
    st.push_back(i);
}
```
Время $O(n)$ в худшем случае на весь массив, память $O(n)$.
Идея доказательства: снятый $j$ с $a_j\ge a_i$ правее не нужен — $i$ ближе и не больше. После снятий вершина — ближайший слева меньший: все индексы между ней и $i$ сняты, их значения $\ge a_i$.
Подвох: для строгого меньшего снимаем при $\ge$; при $>$ получится «меньший или равный».
См.: программа экзамена, вопрос 20

## aisd-c-0210 · aisd-t-020
Как одним шаблоном находят ближайший больший/меньший элемент справа или слева?
---
Шаблон один — монотонный стек индексов [не по конспекту]; меняются направление обхода и условие снятия.
- Ближайший слева — обход слева направо; справа — справа налево.
- Строго меньший: перед обработкой $i$ снимаем вершины со значением $\ge a_i$; строго больший: снимаем $\le a_i$.
- После снятий вершина — ответ для $i$; пустой стек — ответа нет ($-1$ или $n$). Затем кладём $i$.
Время $O(n)$ в худшем случае, память $O(n)$ для каждого из четырёх вариантов.
Идея: снятый «заслонён» текущим — тот ближе ко всем будущим позициям и не хуже по значению.
Подвох: для нестрогого варианта (меньший или равный) снимаем при строгом $>a_i$; на равных элементах часто ошибаются.
См.: программа экзамена, вопрос 20

## aisd-c-0211 · aisd-t-020
Какова сложность поиска ближайшего меньшего/большего элемента монотонным стеком и почему?
---
Для массива длины $n$: время $O(n)$ в худшем случае на все $n$ ответов, память $O(n)$. Отдельный шаг может стоить $O(n)$, но учётная стоимость шага $O(1)$. [не по конспекту]
Идея доказательства: каждый индекс кладётся в стек ровно один раз и снимается не более одного раза, поэтому итераций внутреннего `while` суммарно не больше $n$, всего не более $2n$ операций со стеком.
Подвох: «вложенный цикл — значит $O(n^2)$» неверно, считать надо суммарно. Наивный поиск (влево до первого меньшего) на убывающем массиве $\Theta(n^2)$. Худший вход по памяти — возрастающий массив: в стеке все $n$ индексов.
См.: программа экзамена, вопрос 20

## aisd-c-0212 · aisd-t-021
Как вычислить выражение в обратной польской записи?
---
ОПЗ: число $x$ — выражение; если $\alpha$, $\beta$ — выражения, то $\alpha\ \beta\ +$, $\alpha\ \beta\ -$, $\alpha\ \beta\ *$, $\alpha\ \beta\ /$ тоже; значение $\alpha\ \beta\ \circ$ — (значение $\alpha$) $\circ$ (значение $\beta$). Скобки не нужны.
Алгоритм: слева направо со стеком чисел. Число — на стек; знак $\circ$ — снимаем $y$ (верхнее), затем $x$, кладём $x\circ y$. В конце в стеке одно число — ответ. Время $O(n)$, память $O(n)$ в худшем случае.
Пример: $1+(2-3\cdot4)\cdot2$ — это `1 2 3 4 * - 2 * +`; стек $[1,2,3,4]\to[1,2,12]\to[1,-10]\to[1,-10,2]\to[1,-20]\to[-19]$.
Подвох: верхний элемент — правый операнд; для `-` и `/` легко получить $y-x$ вместо $x-y$.
См.: конспект, «Лекция 7, Задача 2: обратная польская запись»

## aisd-c-0213 · aisd-t-021
Какова сложность вычисления выражения в ОПЗ и почему алгоритм со стеком корректен?
---
Число — на стек; знак $\circ$ снимает $y$, затем $x$ и кладёт $x\circ y$; ответ — единственное число. Для $n$ токенов время $O(n)$ в худшем случае, память $O(n)$.
Идея доказательства (индукция по построению):
1. Число: в стеке будет это число.
2. $\alpha\ \beta\ \circ$: после $\alpha$ добавлено одно число — значение $\alpha$; $\beta$ обрабатывается так, будто стек пуст, сверху оказывается значение $\beta$; знак кладёт $\alpha\circ\beta$.
Итог — одно число: чисел на одно больше, чем знаков (баланс $1$), знак уменьшает стек на $1$.
Подвох: порядок снятия важен для $-$ и $/$; на некорректной записи стек пуст при снятии или в конце не одно число.
См.: конспект, «Лекция 7, Задача 2: обратная польская запись»

## aisd-c-0234 · aisd-t-021
Что такое баланс строки в ОПЗ, как формулируется лемма о балансе суффиксов и почему из неё следует однозначность разбора выражения?
---
Баланс строки — число чисел минус число знаков операций.
Лемма: $E$ — корректное выражение в ОПЗ; читаем справа налево (суффиксы по возрастанию длины). Баланс пустого суффикса $0$, всех непустых собственных суффиксов $\le0$, всей строки $1$.
Идея доказательства: индукция по построению.
1. $E=x$: суффиксы — пустой ($0$) и вся строка ($1$).
2. $E=\alpha\ \beta\ \circ$: знак даёт $-1$. Внутри $\beta$ (по индукции, сдвиг $-1$) баланс $\le-1$, после целой $\beta$ — $0$. Далее в $\alpha$ баланс $\le0$, и $1$ лишь в самом начале.
Вывод: баланс впервые возвращается к $0$ на границе $\alpha$ и $\beta$; кратчайший непустой суффикс с нулевым балансом — $\beta\ \circ$, остаток — $\alpha$: разбор однозначен.
См.: конспект, «Лекция 7, Задача 2: обратная польская запись»

## aisd-c-0214 · aisd-t-022
Как поддерживать минимум в стеке за $O(1)$ на операцию?
---
С каждым элементом храним минимум среди него и всех элементов под ним (стек пар). Минимум стека — второе поле вершины.
```cpp
std::vector<std::pair<int, int>> a_;   // (значение, минимум под ним)
void push(int x) {
    int m = a_.empty() ? x : std::min(x, a_.back().second);
    a_.push_back({x, m});
}
void pop() { a_.pop_back(); }
int min() const { return a_.back().second; }
```
Все операции — $O(1)$ в худшем случае; память $O(n)$.
Идея: при `push(x)` новый минимум $\min(x,m)$, $m$ — у вершины; при `pop` у остальных всё верно.
Пример: 3, 1, 4, 0 — пары $(3,3),(1,1),(4,1),(0,0)$; после `pop` минимум $1$.
Подвох: одной переменной мало — после `pop` новый минимум неизвестен.
См.: конспект, «Лекция 7, Стек с минимумом»

## aisd-c-0215 · aisd-t-022
Каковы асимптотики операций стека с минимумом и почему минимум не нужно пересчитывать при `pop`?
---
Стек хранит пары (значение, минимум среди него и всех под ним). `push`, `pop`, `top`, запрос минимума — $O(1)$ в худшем случае; память $O(n)$.
Идея доказательства: инвариант — у каждого элемента записан минимум части стека от дна до него. `push(x)` пишет $\min(x,$ минимум вершины$)$ — верно по инварианту. `pop` убирает только вершину; минимумы остальных зависят лишь от элементов под ними. Минимум стека — у вершины.
Подвох: приём работает, потому что стек меняется с одного конца. Для очереди так не выйдет (после удаления головы записанные минимумы устаревают) — очередь с минимумом строят на двух стеках с минимумом.
См.: конспект, «Лекция 7, Стек с минимумом»

## aisd-c-0216 · aisd-t-023
Как реализовать очередь списком?
---
Очередь: `push(x)` — в конец, `pop()` — удалить из начала, `front()` — первый (FIFO). Реализация — двусвязный список с указателями на начало и конец (удобно с фиктивными элементами по краям). `push` — вставка в конец, `pop` — удаление из начала, `front` — чтение начала. Все операции — $O(1)$ в худшем случае; память $O(n)$.
Идея: элементы в порядке прихода; добавляем с одного конца, забираем с другого; вставка и удаление по указателю — перешивание $O(1)$ указателей.
Подвох: нужны указатели на оба конца. Хватит и односвязного списка с головой и хвостом (при удалении последнего хвост обнуляется). [не по конспекту]
См.: конспект, «Лекция 7, Очередь»

## aisd-c-0217 · aisd-t-023
Каков инвариант очереди на списке и расход времени и памяти?
---
Инвариант: узлы идут от начала к концу в порядке добавления. С фиктивными `head_` и `tail_` первый настоящий — `head_->next`, последний — `tail_->prev`, пустая очередь — `head_->next == tail_`.
`push(x)` — вставка перед `tail_`, `pop()` — удаление `head_->next`, `front()` — его значение. Каждая операция — $O(1)$ в худшем случае (не учётное); память $O(n)$.
Идея доказательства: `push` дописывает узел в конец, остальные не трогает; `pop` убирает первый, первым становится следующий по времени добавления. Значит `front` — самый старый элемент (FIFO).
Подвох: без фиктивных узлов нужен отдельный разбор пустой очереди и единственного элемента; `pop`, `front` на пустой очереди не определены.
См.: конспект, «Лекция 7, Очередь»

## aisd-c-0218 · aisd-t-024
Как устроена очередь на двух стеках и почему соблюдается порядок FIFO?
---
Два стека: $A$ (хвост, `in_`) и $D$ (голова, `out_`). `push(x)` кладёт $x$ в $A$; `pop()`, `front()` работают с $D$, а если $D$ пуст — сначала перекладывают в него все элементы $A$ по одному.
```cpp
void move_if_needed() {
    if (!out_.empty()) return;
    while (!in_.empty()) { out_.push(in_.top()); in_.pop(); }
}
void push(int x) { in_.push(x); }
int front() { move_if_needed(); return out_.top(); }
void pop() { move_if_needed(); out_.pop(); }
```
Время: учётное $O(1)$ на операцию; одиночный `pop` в худшем случае $O(n)$. Память $O(n)$.
Идея доказательства: при перекладывании порядок разворачивается — самый старый со дна $A$ оказывается на вершине $D$. Пока $D$ не пуст, извлекаются его элементы, все старше любого из $A$.
Подвох: перекладываем только при пустом $D$ и всё сразу.
См.: конспект, «Лекция 7, Задача 3: минимум в скользящем окне»

## aisd-c-0219 · aisd-t-024
Какова амортизированная сложность очереди на двух стеках и как она доказывается?
---
`push` кладёт в $A$; `pop`, `front` берут из $D$, при пустом $D$ перекладывают в него всё из $A$. `push` — $O(1)$ в худшем случае; `pop`, `front` — учётное $O(1)$, но $O(n)$ в худшем случае для одной операции. Память $O(n)$.
Идея доказательства: каждый элемент один раз кладётся в $A$, один раз снимается с $A$, один раз кладётся в $D$ и один раз снимается с $D$; при $n$ добавленных элементах всего не более $4n$ операций со стеками.
Интуиция: если переложили сразу 100 элементов, следующие 100 извлечений обходятся без перекладывания.
Подвох: это не худший случай для одной операции и не «в среднем» (случайности нет) — гарантируется суммарное время последовательности операций.
См.: конспект, «Лекция 7, Задача 3: минимум в скользящем окне»

## aisd-c-0220 · aisd-t-024
Как поддержать минимум в очереди на двух стеках?
---
Оба стека ($A$ — хвост, $D$ — голова) — стеки с минимумом. Минимум очереди $=\min(\min A,\min D)$; если один стек пуст, берём минимум другого.
Время: `min` и `push` — $O(1)$ в худшем случае; `pop`, `front` — учётное $O(1)$. Память $O(n)$.
Идея: каждый элемент лежит ровно в одном стеке; при перекладывании в $D$ обычным `push` минимумы пересчитываются сами.
Применение: минимумы во всех окнах длины $k$ массива длины $n$ (окон $n-k+1$): кладём первые $k$ элементов, выводим `min`; затем `push` нового, `pop` старого, `min`. Всего $O(n)$.
Подвох: один минимум не хранить — после удаления головы новый неизвестен; минимумы суффиксов не годятся — `push` может изменить их все (убывающие 5, 4, 3, 2, 1).
См.: конспект, «Лекция 7, Задача 3: минимум в скользящем окне»

## aisd-c-0221 · aisd-t-025
Что такое бинарная куча и как её представить в массиве?
---
Куча хранит мультимножество с линейным порядком и умеет `insert(x)`, `getMin()`, `extractMin()`, `decreaseKey(p, Δ)` (уменьшить на $\Delta\ge0$ элемент, на который указывает $p$). Двоичная куча: массив $a_1,\dots,a_n$ (с единицы), по которому мысленно строится полное двоичное дерево по слоям слева направо (корень $a_1$, дети $a_2,a_3$, …); последний уровень может быть неполным. Дети $v$ — $2v$ и $2v+1$, родитель — $\lfloor v/2\rfloor$; дерева в памяти нет. Глубина $\lfloor\log_2 n\rfloor$, память $O(n)$.
Требование кучи: $a_{\lfloor v/2\rfloor}\le a_v$ при $v>1$.
Подвох: куча не ищет элемент по значению. При нумерации с нуля дети $2v+1$, $2v+2$, родитель $\lfloor(v-1)/2\rfloor$. [не по конспекту]
См.: конспект, «Лекция 4, Двоичная куча»

## aisd-c-0222 · aisd-t-025
Каково требование min-кучи и что из него следует?
---
Массив $a_1,\dots,a_n$ удовлетворяет требованию кучи, если для каждой $v>1$ верно $a_{\lfloor v/2\rfloor}\le a_v$ — родитель не больше ребёнка.
Следствия: вниз по любому пути значения не убывают; элемент не больше всех в своём поддереве; $a_1$ — минимум, поэтому `getMin` за $O(1)$.
Идея доказательства: на каждом ребре вниз «родитель $\le$ ребёнок», по транзитивности вершина не больше любого потомка; любая вершина — потомок корня.
Пример: $a=(1,3,2,5,9,8,7)$ — куча.
Подвох: порядок слабый — между братьями и разными поддеревьями его нет ($a_2=3>a_3=2$), массив не отсортирован. Равные допустимы (неравенство нестрогое).
См.: конспект, «Лекция 4, Двоичная куча»

## aisd-c-0223 · aisd-t-026
Как работает siftUp в min-куче и почему он корректен?
---
`siftUp(v)`: элемент в $v$, возможно, слишком мал. Пока $v$ не корень и родитель больше $a_v$, меняем их и переходим в родителя.
```cpp
void sift_up(int v) {
    while (v > 1 && a_[v / 2] > a_[v]) {
        std::swap(a_[v / 2], a_[v]);
        v /= 2;
    }
}
```
Время $O(\log n)$ в худшем случае (не более $\lfloor\log_2 n\rfloor$ шагов), память $O(1)$.
Лемма: если в корректной куче $a_v$ заменили на $x\le a_v$, то после `siftUp(v)` куча корректна.
Идея доказательства: индукция по глубине $v$. Корень: родителя нет, неравенства с детьми усилились. Переход, $p$ — родитель: при $x\ge a_p$ стоп. Иначе в $v$ пишем $a_p\le$ старого $a_v$ (куча корректна), в $p$ заменяем $a_p$ на $x<a_p$ — уменьшение выше, по индукции `siftUp(p)` чинит кучу.
Подвох: `siftUp` чинит только уменьшение; после увеличения нужен `siftDown`.
См.: конспект, «Лекция 4, Просеивание вверх и вниз / Корректность»

## aisd-c-0224 · aisd-t-026
Как работает siftDown в min-куче и почему он корректен?
---
`siftDown(v)`: элемент в $v$, возможно, слишком велик. Нет детей — стоп. Иначе берём меньшего ребёнка $u$; если $a_u<a_v$, меняем и продолжаем из $u$, иначе стоп.
```cpp
void sift_down(int v) {
    while (2 * v <= n_) {
        int u = 2 * v;
        if (u + 1 <= n_ && a_[u + 1] < a_[u]) u = u + 1;
        if (a_[u] >= a_[v]) break;
        std::swap(a_[u], a_[v]);
        v = u;
    }
}
```
Время $O(\log n)$ в худшем случае, память $O(1)$.
Лемма: если в корректной куче $a_v$ заменили на $x\ge a_v$, то после `siftDown(v)` куча корректна.
Идея доказательства: индукция по высоте $v$. Лист: неравенство с родителем усилилось. Переход: при $x\le a_u$ стоп. Иначе в $v$ пишем $a_u$ ($\ge$ старого $a_v$, $\le$ второго ребёнка и детей $u$), в $u$ заменяем $a_u$ на $x>a_u$ — увеличение ниже, по индукции `siftDown(u)` чинит кучу.
Подвох: менять надо с меньшим ребёнком: при 5 в $v$ и детях 2 и 10 обмен с 10 поставит 10 над 2 и над 5.
См.: конспект, «Лекция 4, Просеивание вверх и вниз / Корректность»

## aisd-c-0225 · aisd-t-027
Как выразить insert, getMin и extractMin в min-куче через siftUp и siftDown и почему это корректно?
---
Куча в $a_1,\dots,a_n$. `getMin()` — $a_1$, $O(1)$. `insert(x)`: увеличить $n$, положить $x$ в $a_n$ (новый лист), `siftUp(n)`. `extractMin()`: запомнить $a_1$, поменять $a_1$ и $a_n$, уменьшить $n$ (отрезать последний лист), `siftDown(1)`.
`insert` и `extractMin` — $O(\log n)$ в худшем случае (одно просеивание), память $O(1)$ дополнительно.
Идея доказательства: по лемме `siftUp` чинит кучу после уменьшения, `siftDown` — после увеличения. `insert`: в новый лист положили $+\infty$ (требование не нарушено), затем уменьшили до $x$. `extractMin`: в корректной куче без последнего листа значение корня увеличилось.
Подвох: `extractMin` и `getMin` на пустой куче не определены; при `n_ == 0` после обмена `siftDown` не вызывают.
См.: конспект, «Лекция 4, Операции кучи»

Как выполнить decreaseKey в бинарной min-куче?

## aisd-c-0227 · aisd-t-028
Как построить бинарную кучу из массива за линейное время (heapify) и почему построение корректно?
---
Из произвольного массива $a_1,\dots,a_n$ получаем кучу на месте: считаем кучей сам массив и чиним — для $i=n,n-1,\dots,1$ вызываем `siftDown(i)` (для листьев вызов пуст, можно с $i=\lfloor n/2\rfloor$). Время $O(n)$ в худшем случае, память $O(1)$.
Утверждение: после `siftDown(i)` поддерево $i$ — куча.
Идея доказательства: индукция по $i$ вниз. Лист корректен. Иначе поддеревья детей (номера больше) уже корректны; нарушено может быть только неравенство $a_i$ с детьми. Пусть в $i$ сначала $-\infty$ (поддерево корректно), затем он заменён на $a_i$ — увеличение, по лемме `siftDown(i)` чинит поддерево.
Подвох: обход строго от больших номеров к меньшим; при нумерации с нуля старт с $\lfloor n/2\rfloor-1$.
См.: конспект, «Лекция 4, Построение кучи за O(n)»

## aisd-c-0228 · aisd-t-028
Почему построение кучи вызовами siftDown от $n$ до $1$ работает за $O(n)$?
---
`siftDown` из вершины работает за время, пропорциональное её высоте, а не глубине дерева. Листьев около $\frac n2$ (работа $O(1)$); вершин высоты $1$ около $\frac n4$ (до 1 шага), высоты $2$ около $\frac n8$ (до 2 шагов), …:
$$\frac n4\cdot1+\frac n8\cdot2+\frac n{16}\cdot3+\dots$$
Идея доказательства: слагаемое $\frac{n}{2^{h+1}}\cdot h$ разбиваем на $h$ одинаковых и собираем по строкам:
$$\left(\frac n4+\frac n8+\dots\right)+\left(\frac n8+\frac n{16}+\dots\right)+\dots\le\frac n2+\frac n4+\dots\le n.$$
Каждая строка — убывающая геометрическая прогрессия. Итого $O(n)$ в худшем случае; память $O(1)$.
Подвох: «$n$ вызовов по $O(\log n)$» даёт лишь $O(n\log n)$ — один `siftDown` может стоить $\log n$, но высоких вершин мало.
См.: конспект, «Лекция 4, Построение кучи за O(n)»

## aisd-c-0229 · aisd-t-029
Как выполняется Heap Sort с $O(1)$ дополнительной памяти?
---
Строим min-кучу в самом массиве за $O(n)$, затем $n-1$ раз: меняем корень с последним элементом кучи, уменьшаем размер кучи на 1, `siftDown` от корня. Минимумы остаются в конце, массив убывает — разворачиваем (с max-кучей разворот не нужен).
```cpp
void heap_sort(std::vector<int>& a) {   // с нуля: дети 2v+1, 2v+2
    int n = a.size();
    for (int i = n / 2 - 1; i >= 0; --i) sift_down(a, n, i);
    for (int m = n - 1; m > 0; --m) {
        std::swap(a[0], a[m]);
        sift_down(a, m, 0);   // куча - первые m элементов
    }
    std::reverse(a.begin(), a.end());
}
```
Время $O(n\log n)$ в худшем случае, память $O(1)$ (`siftDown` — цикл без рекурсии).
Подвох: Merge sort нужен массив, Quick sort — стек; `siftDown` получает размер кучи $m$, иначе заденет отсортированный хвост.
См.: конспект, «Лекция 4, Heap sort на месте»

## aisd-c-0230 · aisd-t-029
Почему не существует кучи, основанной на сравнениях, в которой и insert, и extractMin работают за $O(1)$?
---
Утверждение: кучи на сравнениях, в которой и `insert`, и `extractMin` работают за $O(1)$, не существует.
Идея доказательства (от противного):
1. Любой кучей можно сортировать: $n$ вставок в пустую кучу и $n$ извлечений минимума дают возрастающую последовательность.
2. Куча использует только сравнения — это сортировка сравнениями.
3. При $O(1)$ на обе операции она работала бы за $O(n)$ — противоречие с $\Omega(n\log n)$.
Следствие: двоичная куча (обе операции $O(\log n)$) близка к оптимальной; улучшить можно одну из операций, но не обе (дальше по конспекту — куча с `insert` за $O(1)$, `extractMin` за $O(\log n)$).

## aisd-c-0231 · aisd-t-030
Как удалить из бинарной кучи элемент по известному указателю на его позицию?
---
Min-куча $a_1,\dots,a_n$, удаляемый элемент в вершине $v$. Записываем в $a_v$ значение $-\infty$, вызываем `siftUp(v)` (поднимается в корень), затем `extractMin()`. Время $O(\log n)$ в худшем случае, память $O(1)$.
Идея доказательства: замена на $-\infty$ — уменьшение, по лемме после `siftUp(v)` куча корректна и $-\infty$ в корне; `extractMin` удаляет корень, остальные не меняются.
Подвох: $+\infty$ с опусканием хуже — неясно, в какой лист он придёт, и его трудно удалить. Роль $-\infty$ играет наименьшее значение типа (`numeric_limits<int>::min()`); удаляемый элемент должен точно быть в куче.

## aisd-c-0232 · aisd-t-030
Какова сложность удаления из кучи по указателю и что меняется, если известно только значение?

По указателю (известна вершина $v$): $-\infty$ в $a_v$, `siftUp(v)`, `extractMin()`. Время $O(\log n)$ в худшем случае, память $O(1)$.
