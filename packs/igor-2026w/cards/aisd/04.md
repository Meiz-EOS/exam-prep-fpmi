## aisd-c-0401 · aisd-t-046
Как находят $k$-ю порядковую статистику на отрезке $[l,r]$ с персистентным деревом отрезков?
---
Массив не меняется; запрос $(l,r,k)$: $k$-е по возрастанию среди $a_l,\dots,a_r$. Сжимаем значения до $0,\dots,m-1$; строим персистентное дерево отрезков по значениям (лист $c$ хранит, сколько раз $c$ встречается, вершина — сумму), версия $i$ — по префиксу $a_0,\dots,a_{i-1}$. Идём одновременно по версиям $r+1$ (корень `u`) и $l$ (корень `v`):
```cpp
while (hi - lo > 1) {          // диапазон значений [lo, hi)
    int mid = (lo + hi) / 2;
    int c = cnt[L[u]] - cnt[L[v]];   // чисел отрезка в левой половине
    if (c >= k) { u = L[u]; v = L[v]; hi = mid; }
    else { k -= c; u = R[u]; v = R[v]; lo = mid; }
}
return orig[lo];               // исходное значение листа
```
Запрос $O(\log n)$ в худшем случае, без ветвления.
Подвох: $k$ считается с единицы; при уходе вправо надо вычесть $c$ из $k$.
См.: конспект, «Лекция 9, Задача: k-я порядковая статистика на отрезке»

## aisd-c-0402 · aisd-t-046
Какова сложность построения префиксных версий персистентного дерева частот и почему версия $r+1$ без версии $l$ даёт отрезок $[l,r]$?
---
Построение: сжатие координат (сортировка) $O(n\log n)$; каждый элемент создаёт новую версию, копируя путь от корня до листа, то есть $O(\log n)$ новых вершин, остальные делятся со старой версией. Итого $O(n\log n)$ времени и памяти в худшем случае. Версии не меняются после создания.
Идея доказательства корректности: вершины версий $r+1$ и $l$, достигнутые одним путём от корня, отвечают одному диапазону значений; числа в них $B$ и $A$ — количества элементов префиксов длины $r+1$ и $l$ с такими значениями, поэтому $B-A$ — число элементов отрезка $[l,r]$ в диапазоне; в корнях $B-A=r-l+1$.
Подвох: иначе — merge sort tree с бинарным поиском по ответу, $O(\log^3 n)$ на запрос.
См.: конспект, «Лекция 9, Задача: k-я порядковая статистика на отрезке»

## aisd-c-0426 · aisd-t-046
Прогоните поиск $k$-й статистики на отрезке для $a=(10,2,7,2,1)$, $l=1$, $r=3$, $k=2$.
---
Сжатие $1\to0,\ 2\to1,\ 7\to2,\ 10\to3$ даёт $(3,1,2,1,0)$. Отрезок — числа $2,7,2$ (сжато $1,2,1$); сравниваем версии $4$ ($=r+1$) и $1$ ($=l$).
1. Корни, значения $0..3$: левые сыновья (значения $0..1$) дают $B-A=2\ge k=2$, идём влево.
2. Диапазон $0..1$: левый сын (значение $0$) даёт $0<2$, поэтому $k$ остаётся $2-0=2$, идём вправо.
3. Лист значения $1$: ответ — исходное число $2$.
Проверка: отсортированный отрезок $2,2,7$, вторая статистика равна $2$.
Подвох: при уходе вправо $k$ уменьшают на число пропущенных элементов $c$ (здесь $c=0$, поэтому $k$ не меняется).
См.: конспект, «Лекция 9, Задача: k-я порядковая статистика на отрезке»

## aisd-c-0403 · aisd-t-047
Что хранит классическое дерево Фенвика для сумм и какую задачу решает?
---
Задача: массив $a_1,\dots,a_n$, операции `update(i, d)`: $a_i \mathrel{+}= d$, и `getSum(i)`: $a_1+\dots+a_i$ (сумма на $[l,r]$ — разность $\text{getSum}(r)-\text{getSum}(l-1)$). Структура — массив `bit[1..n]`, где `bit[i]` $=\sum_{j=i-\mathrm{lowbit}(i)+1}^{i} a_j$, $\mathrm{lowbit}(i)=i\mathbin{\&}(-i)$ — младший единичный бит $i$. Память $O(n)$.
Идея: отрезки `bit[i]` вложены или не пересекаются, префикс $[1,i]$ раскладывается не более чем на $\log_2 n$ таких блоков (убираем младший бит по одному).
Подвох: индексация строго с $1$ (при $i=0$ $\mathrm{lowbit}=0$). Разность префиксов требует обратимой операции: максимум так не получить [не по конспекту].
См.: программа экзамена, вопрос 47

## aisd-c-0404 · aisd-t-047
Как реализованы `update` и `getSum` в дереве Фенвика и почему они работают за $O(\log n)$?
---
```cpp
void update(int i, int d) { for (; i <= n; i += i & -i) bit[i] += d; }
int getSum(int i) {
    int s = 0;
    for (; i > 0; i -= i & -i) s += bit[i];
    return s;
}
```
Время обеих операций $O(\log n)$ в худшем случае, память $O(n)$ [не по конспекту].
Идея: `getSum` на каждом шаге снимает младший единичный бит, шагов не больше числа единиц в $i$, то есть $\le\log_2 n$. В `update` посещаются ровно те $j$, чьи блоки содержат позицию $i$; $\mathrm{lowbit}$ при $i\mathrel{+}=\mathrm{lowbit}(i)$ строго растёт, значит шагов $\le\log_2 n+1$.
Подвох: построение из массива можно сделать за $O(n)$: сначала `bit[j] = a[j]`, затем для $j=1..n$ при `j + lowbit(j) <= n` делаем `bit[j + lowbit(j)] += bit[j]`, а не $n$ вызовов `update` ($O(n\log n)$).
См.: программа экзамена, вопрос 47

## aisd-c-0405 · aisd-t-048
Как обобщается дерево Фенвика на $d$ измерений и как меняется асимптотика?
---
Задача: массив $a$ размера $n_1\times\dots\times n_d$, точечное $a_{x}\mathrel{+}=\Delta$ и сумма на префиксном параллелепипеде. Индекс идёт во вложенных циклах Фенвика, по одному на координату: для каждой координаты используется свой путь `i += lowbit(i)` (update) или `i -= lowbit(i)` (запрос).
Время update и prefixSum — $O(\log^d n)$ в худшем случае ($n$ — размер по каждой координате), память плотного массива — $O(n^d)$. Сумма на произвольном параллелепипеде — включение-исключение по $2^d$ префиксным суммам: $O(2^d\log^d n)$ [не по конспекту].
Подвох: при $d=1$ получаем обычный $O(\log n)$; обратимая операция обязательна (иначе включение-исключение невозможно).
См.: программа экзамена, вопрос 48

## aisd-c-0427 · aisd-t-048
Как выглядит двумерное дерево Фенвика и как получить сумму на прямоугольнике?
---
`bit[i][j]` хранит сумму $a$ на прямоугольнике $(i-\mathrm{lowbit}(i),i]\times(j-\mathrm{lowbit}(j),j]$.
```cpp
void update(int x, int y, int d) {
    for (int i = x; i <= n; i += i & -i)
        for (int j = y; j <= m; j += j & -j) bit[i][j] += d;
}
int getSum(int x, int y) {
    int s = 0;
    for (int i = x; i > 0; i -= i & -i)
        for (int j = y; j > 0; j -= j & -j) s += bit[i][j];
    return s;
}
```
Прямоугольник $[x_1,x_2]\times[y_1,y_2]$: $S(x_2,y_2)-S(x_1-1,y_2)-S(x_2,y_1-1)+S(x_1-1,y_1-1)$, где $S$ — `getSum`. Время обеих операций $O(\log n\cdot\log m)$ в худшем случае, память $O(nm)$ [не по конспекту].
Подвох: вычитаемых префиксов три, добавляется угловой; индексация с $1$.
См.: программа экзамена, вопрос 48

## aisd-c-0406 · aisd-t-049
Что поддерживает обратное дерево Фенвика для максимумов и почему для него нужна особая схема?
---
Задача: массив $a_1,\dots,a_n$, операции $a_i\leftarrow\max(a_i,x)$ (значения только растут) и максимум на отрезке $[l,r]$. Максимум необратим, поэтому вычитанием префиксов отрезок не получить, а обычное дерево Фенвика `f[i]` (максимум на $(i-\mathrm{lowbit}(i),i]$) отвечает только на префиксные запросы. Обратное дерево `g[i]` хранит максимум на $[i,\,i+\mathrm{lowbit}(i))$ (блоки «вперёд» от $i$). Увеличение $a_i$: в `f` цепочка $i\mathrel{+}=\mathrm{lowbit}(i)$, в `g` цепочка $i\mathrel{-}=\mathrm{lowbit}(i)$, в каждом узле берём максимум. Запрос $[l,r]$ покрывается блоками `f` (идём от $r$ вниз) и `g` (идём от $l$ вверх).
Время $O(\log n)$ на операцию (худший случай), память $O(n)$ [не по конспекту]; точная схема запроса на семинарах может отличаться, простой вариант с `f` и массивом $a$ даёт $O(\log^2 n)$.
Подвох: значения можно только увеличивать: после уменьшения $a_i$ максимум в блоках пересчитать нельзя.
См.: программа экзамена, вопрос 49

## aisd-c-0407 · aisd-t-050
Как устроено дерево Фенвика деревьев Фенвика?
---
Задача: $N$ точек $(x,y)$ с весами, операции — прибавить вес в точке и узнать сумму на прямоугольнике. Внешнее дерево Фенвика по $x$; каждый его узел $i$ содержит внутреннее дерево Фенвика по сжатым $y$-координатам тех точек, чей $x$ попадает в блок $(i-\mathrm{lowbit}(i),i]$. Обновление точки: идём по внешнему пути $x\mathrel{+}=\mathrm{lowbit}(x)$ и в каждом узле обновляем внутреннее дерево по $y$. Сумма на прямоугольнике — включение-исключение по четырём префиксным $S(x,y)$.
Подвох: все точки (или хотя бы их координаты) должны быть известны заранее, чтобы построить сжатые внутренние деревья [не по конспекту].
См.: программа экзамена, вопрос 50

## aisd-c-0408 · aisd-t-050
Каковы асимптотики двумерного дерева Фенвика деревьев Фенвика?
---
Для $N$ точек точечное обновление и префиксная сумма $S(x,y)$ занимают $O(\log^2 N)$ времени в худшем случае (внешний путь $\le\log N$ узлов, в каждом внутренний путь $\le\log N$), сумма на прямоугольнике — столько же (4 префикса). Память $O(N\log N)$ при сжатых координатах [не по конспекту].
Идея доказательства памяти: точка $(x,y)$ лежит в блоках $O(\log N)$ внешних узлов (тех, что на пути $x\mathrel{+}=\mathrm{lowbit}$), поэтому во внутренних деревьях всего $O(N\log N)$ вершин.
Подвох: без сжатия внутренние деревья имели бы по $O(N)$ вершин и память $O(N^2)$.
См.: программа экзамена, вопрос 50

## aisd-c-0409 · aisd-t-051
Что такое дерево поиска и какую задачу оно решает?
---
Хотим хранить множество $S$ и отвечать на `find(x)`, `insert(x)`, `erase(x)` (дубликаты и удаление отсутствующего игнорируются); кроме того, порядок элементов важен (в хеш-таблице он теряется). Бинарное дерево поиска — корневое дерево, где у каждой вершины не больше двух сыновей (левый и правый), в вершинах записаны элементы $S$ (каждый один раз), и выполнен инвариант: для вершины с числом $x$ все числа левого поддерева меньше $x$, а правого — больше $x$.
Подвох: в вершине хранится число и указатели на сыновей; при дубликатах нужно особое соглашение, в конспекте элементы различны.
См.: конспект, «Лекция 10, Задача и определение дерева поиска»

## aisd-c-0410 · aisd-t-051
Что делают операции `find`, `insert` и `erase` в наивном дереве поиска и за сколько работают?
---
`find(x)`: от корня идём влево при $x<y$, вправо при $x>y$, пока не найдём $x$ или не придётся идти по несуществующему ребру. `insert(x)`: как `find`; если ребра нет, подвешиваем туда новую вершину (место, где $x$ лежал бы). `erase(x)`: найти $x$; если сыновей $\le1$, заменить вершину на её единственное поддерево; если два — найти минимум $m$ правого поддерева (из правого сына идём влево), удалить $m$ (у него нет левого сына) и записать $m$ на место $x$.
Все три операции — $O(h)$ в худшем случае, $h$ — высота дерева, память $O(n)$.
Подвох: вставки $1,2,\dots,n$ по порядку дают «бамбук» высоты $n$, и всё линейно.
См.: конспект, «Лекция 10, Наивные find, insert, erase»

## aisd-c-0411 · aisd-t-051
Что означают `merge` и `split` для деревьев поиска?
---
Это опциональные операции. `merge`: из деревьев на $S_1$ и $S_2$ получить дерево на $S_1\cup S_2$, обычно в предположении, что все элементы $S_1$ меньше элементов $S_2$. `split(k)`: разбить $S$ на два дерева $\{x\in S: x\le k\}$ и $\{x\in S: x>k\}$. Реализация зависит от вида дерева: в AVL они неудобны (особенно `split`), в splay-дереве через `splay` оба выполняются за $O(\log n)$ амортизированно.
Подвох: без предположения $\max S_1<\min S_2$ `merge` — это не конкатенация, а вставка элементов поштучно.
См.: конспект, «Лекция 10, Задача и определение дерева поиска»

## aisd-c-0428 · aisd-t-051
Как в дереве поиска вывести элементы по возрастанию и почему это работает?
---
Рекурсивный обход: сначала левое поддерево, затем число в вершине, затем правое. По инварианту дерева поиска левое поддерево целиком меньше вершины, а правое — больше, поэтому порядок возрастающий. Время $O(n)$ в худшем случае (оптимально, так как надо вывести $n$ чисел), память — $O(h)$ на стек рекурсии. Это то, что хеш-таблица не умеет.
Подвох: опирается только на инвариант и не меняет дерево.
См.: конспект, «Лекция 10, Вывод элементов по возрастанию»

## aisd-c-0412 · aisd-t-052
Как определяется AVL-дерево?
---
AVL-дерево (Адельсон-Вельский, Ландис) — бинарное дерево поиска, в котором для каждой вершины $v$ глубины левого и правого поддеревьев отличаются не больше чем на $1$: $|h(L)-h(R)|\le1$. Через $\Delta(v)=h(L)-h(R)$ (без модуля) условие: $\Delta(v)\in\{-1,0,1\}$ во всех вершинах. В вершине хранятся число, указатели на сыновей и глубина поддерева $h$ (чтобы считать $\Delta$).
Подвох: требовать равенство глубин нельзя — даже дерево из двух вершин его не выполняет; глубина $h$ — число вершин на самом длинном пути вниз (у пустого дерева $0$).
См.: конспект, «Лекция 10, AVL-дерево»

## aisd-c-0413 · aisd-t-052
Докажите, что глубина AVL-дерева на $n$ вершинах равна $O(\log n)$.
---
Пусть $S(h)$ — минимальное число вершин в AVL-дереве глубины $h$ (глубина — число вершин на самом длинном пути).
Идея доказательства:
1. У корня оба поддерева глубины $\le h-1$, хотя бы одно ровно $h-1$; по условию AVL другое $\ge h-2$. Значит, $S(h)=1+S(h-1)+S(h-2)$, $S(1)=1$, $S(2)=2$.
2. Индукцией $S(h)=F_{h+2}-1$ (числа Фибоначчи, $F_1=F_2=1$): $1+(F_{h+1}-1)+(F_h-1)=F_{h+2}-1$.
3. $F_h$ растёт как $\varphi^h$, $\varphi=\frac{1+\sqrt5}2$, поэтому $S(h)=\Theta(\varphi^h)$; из $n\ge S(h)$ следует $h=O(\log_\varphi n)=O(\log n)$.
Оценка верна в худшем случае; уточнение: глубина $\approx 1{,}44\log_2 n$ [не по конспекту].
Подвох: в рекурренте поддерево меньшей глубины берётся минимальным ($h-2$), иначе вершин больше.
См.: конспект, «Лекция 10, AVL-дерево»

## aisd-c-0414 · aisd-t-053
Как устраняют дисбаланс в AVL-дереве после вставки или удаления?
---
После наивной вставки/удаления глубины меняются не больше чем на $1$ и только на пути от корня к месту изменения, поэтому там встречаются вершины с $\Delta=\pm2$. Идём по пути снизу вверх и чиним каждую такую вершину $a$. Пусть $\Delta(a)=-2$ (перекос вправо, $b$ — правый сын, $h(a)=h$, $h(b)=h-1$); $+2$ зеркально. Если $\Delta(b)\in\{0,-1\}$ — левый поворот в $a$; если $\Delta(b)=1$ — большой: правый поворот в $b$, затем левый в $a$.
```cpp
Node* rebalance(Node* a) {
    update(a);
    if (delta(a) == -2) {
        if (delta(a->right) == 1) a->right = rotate_right(a->right);
        return rotate_left(a);
    }
    if (delta(a) == 2) {
        if (delta(a->left) == -1) a->left = rotate_left(a->left);
        return rotate_right(a);
    }
    return a;
}
```
Каждое исправление $O(1)$. После большого поворота новый корень $c$ имеет $\Delta(c)=0$.
Подвох: при $\Delta(b)=1$ одного левого поворота мало — новый корень получит перекос $+2$.
См.: конспект, «Лекция 10, AVL-дерево / Балансировка»

## aisd-c-0429 · aisd-t-053
Что такое поворот в дереве поиска и почему он сохраняет порядок ключей?
---
Правый поворот ребра $(a,b)$, где $b$ — левый сын $a$: $b$ поднимается на место $a$, $a$ становится правым сыном $b$, а правое поддерево $\beta$ вершины $b$ переходит левым сыном к $a$. Левый поворот симметричен. Поворот — перенаправление $O(1)$ указателей и пересчёт глубин $a$, $b$.
Идея доказательства: множество ключей поддерева не меняется, поэтому неравенства с внешними предками сохраняются; внутри порядок $\alpha<b<\beta<a<\gamma$ одинаков до и после, значит инвариант дерева поиска цел. Малый поворот — один из двух; большой — композиция двух.
Подвох: поворот не гарантирует баланс сам по себе, нужно выбирать его по знакам $\Delta(a)$ и $\Delta(b)$.
См.: конспект, «Лекция 10, AVL-дерево / Повороты»

## aisd-c-0415 · aisd-t-054
Как реализуются `find`, `insert` и `erase` в AVL-дереве?
---
`find` — как в наивном дереве поиска. `insert` и `erase` — рекурсивные: наивная операция, затем на возврате вверх по пути в каждой вершине `rebalance` (пересчёт глубины и повороты по $\Delta=\pm2$). При `erase` вершины с двумя сыновьями: минимум $m$ правого поддерева вынимают (`erase_min` с `rebalance` на пути) и ставят на место $x$.
```cpp
Node* insert(Node* v, int x) {
    if (v == nullptr) return new Node(x);
    if (x < v->key) v->left = insert(v->left, x);
    else if (x > v->key) v->right = insert(v->right, x);
    else return v;                 // дубликат
    return rebalance(v);
}
```
Все три операции — $O(\log n)$ в худшем случае (путь $O(\log n)$, каждое исправление $O(1)$), память $O(n)$, стек рекурсии $O(\log n)$.
Подвох: нужны глубины в вершинах (или указатели на родителя); после исправления глубина поддерева отличается от исходной не более чем на $1$, дисбаланс хуже $\pm2$ не возникает.
См.: конспект, «Лекция 10, AVL-дерево / Балансировка»

## aisd-c-0416 · aisd-t-055
Что такое splay-дерево и в чём его практическая значимость?
---
Splay-дерево — бинарное дерево поиска, в котором после каждого запроса самая глубокая вершина, к которой было обращение, поднимается в корень (операция `splay`): для `insert` и успешного `find` это сам элемент, для неуспешного `find` — последняя посещённая вершина, для `erase` — самая глубокая достигнутая вершина. Явных ограничений баланса нет, балансировка идёт только через `splay`.
Плюсы: недавно и часто запрашиваемые элементы лежат близко к корню; `merge` и `split` пишутся за несколько строк. Минус: оценки только амортизированные ($O(\log n)$ на операцию), отдельный запрос в худшем случае может занять $O(n)$.
Подвох: дерево может выродиться в «бамбук», но любые $m$ операций занимают $O(m\log n)$.
См.: конспект, «Лекция 10, Splay-дерево»

## aisd-c-0417 · aisd-t-056
Что такое `zig`, `zig-zig` и `zig-zag` в splay-дереве?
---
Пусть $x$ поднимается, $p$ — его родитель, $g$ — дед; каждый шаг возможен в двух зеркальных вариантах.
- `zig`: $x$ — сын корня; один поворот ребра $(x,p)$, $x$ становится корнем.
- `zig-zig`: $x$ не сын корня, $x$ и $p$ лежат по одну сторону от своих родителей; сначала поворот ребра $(p,g)$, затем $(x,p)$.
- `zig-zag`: $x$ и $p$ лежат по разные стороны; поворот ребра $(x,p)$, затем $(x,g)$ (большой поворот из AVL).
Все шаги сохраняют порядок дерева поиска, потому что состоят из поворотов.
Подвох: в `zig-zig` порядок поворотов принципиален: сначала $(p,g)$, потом $(x,p)$ — иначе амортизированная оценка не получится; одиночные повороты вместо пар дают $+1$ на каждом шаге.
См.: конспект, «Лекция 10, Splay-дерево / Как вершина поднимается в корень»

## aisd-c-0418 · aisd-t-056
Что делает операция `splay(x)` и как её реализовать?
---
`splay(x)` поднимает вершину $x$ в корень, сохраняя порядок дерева поиска: пока $x$ не корень и не сын корня, смотрим на родителя $p$ и деда $g$ и применяем `zig-zig` или `zig-zag`; в конце, если $x$ сын корня, — `zig`. Последовательность однозначна. Ниже `rotate(v)` поворачивает ребро $(v,\text{родитель})$.
```cpp
void splay(Node* x) {
    while (x->parent != nullptr) {
        Node* p = x->parent; Node* g = p->parent;
        if (g == nullptr) rotate(x);                        // zig
        else if ((g->left == p) == (p->left == x)) { rotate(p); rotate(x); } // zig-zig
        else { rotate(x); rotate(x); }                      // zig-zag
    }
}
```
Время $O(\text{глубина }x)$ в худшем случае, амортизированно $O(\log n)$; память $O(1)$.
Подвох: в `zig-zig` первым поворачивается родитель.
См.: конспект, «Лекция 10, Splay-дерево / Как вершина поднимается в корень»

## aisd-c-0419 · aisd-t-057
В чём состоит метод потенциалов для амортизированного анализа?
---
Берут функцию $\Phi$ от состояния структуры, неотрицательную и равную $0$ в начале. Если $t_i$ — реальное время $i$-й операции, $\Phi_{i-1},\Phi_i$ — потенциалы до и после, то $a_i=t_i+\Phi_i-\Phi_{i-1}$ — амортизированные (учётные) стоимости.
Идея доказательства: сумма телескопируется, $\sum a_i=\sum t_i+\Phi_m-\Phi_0=\sum t_i+\Phi_m\ge\sum t_i$, поэтому амортизированная оценка сверху оценивает реальное суммарное время $m$ операций.
Подвох: оценка относится к последовательности операций, а не к одной — отдельная операция может быть долгой; $\Phi\ge0$ и $\Phi_0=0$ обязательны.
См.: конспект, «Лекция 10, Splay-дерево / Метод потенциалов»

## aisd-c-0420 · aisd-t-058
Какой потенциал используют для оценки операции `splay` и какова амортизированная стоимость `splay`?
---
Пусть $s(v)$ — число вершин в поддереве $v$, ранг $r(v)=\log_2 s(v)$, потенциал $\Phi=\sum_v r(v)$ ($\Phi\ge0$, для пустого дерева $0$); поворот считаем одним действием. Теорема: амортизированная стоимость $\text{splay}(x)$ не больше $1+3\,(r_{\text{кон}}(x)-r_{\text{нач}}(x))=O(\log n)$.
Идея доказательства: шаги `zig-zig` и `zig-zag` стоят $\le3(r_i-r_{i-1})$ (без слагаемого $+1$), единственный `zig` — $\le1+3(r_k-r_{k-1})$. Сумма телескопируется до $1+3(r_k-r_0)$, а $r\le\log_2 n$.
Для `zig`: меняются ранги только $x$ и $p$, $a=1+r'(x)+r'(p)-r(x)-r(p)$, $r'(p)\le r(p)$ и $r'(x)\ge r(x)$.
Подвох: это амортизированная оценка, отдельный `splay` может стоить $O(n)$; $m$ операций — $O(m\log n)$.
См.: конспект, «Лекция 11, Учётная стоимость splay»

## aisd-c-0430 · aisd-t-058
Докажите, что амортизированная стоимость шага `zig-zig` не больше $3(r'(x)-r(x))$.
---
Реальное время $2$; ранги меняются только у $x,p,g$, поэтому $a=2+r'(x)+r'(p)+r'(g)-r(x)-r(p)-r(g)$.
Идея доказательства:
1. $r'(x)=r(g)$ (оба — ранг всего поддерева), $r(x)\le r(p)$, $r'(p)\le r'(x)$; значит $a\le2+r'(x)+r'(g)-2r(x)$.
2. Достаточно $r(x)+r'(g)-2r'(x)\le-2$, то есть $\log_2\frac{s(x)}{s'(x)}+\log_2\frac{s'(g)}{s'(x)}\le-2$.
3. До шага поддерево $x$ и после шага поддерево $g$ не пересекаются и не содержат $p$, поэтому $\frac{s(x)}{s'(x)}+\frac{s'(g)}{s'(x)}<1$.
4. Лемма: при $a,b>0$, $a+b\le1$ верно $\log_2 a+\log_2 b=\log_2(ab)\le-2$, так как $ab\le\frac14$ (неравенство о средних).
Подвох: в отличие от `zig`, здесь нет слагаемого $+1$: реальное время $2$ гасится слагаемым $-2$ из леммы, поэтому оценка не накапливает $+1$ на каждом шаге.
См.: конспект, «Лекция 11, Анализ шагов zig-zig и zig-zag»

## aisd-c-0431 · aisd-t-058
Докажите, что амортизированная стоимость шага `zig-zag` не больше $2(r'(x)-r(x))$.
---
Реальное время $2$; как и в `zig-zig`, $a=2+r'(x)+r'(p)+r'(g)-r(x)-r(p)-r(g)$, где $r'(x)=r(g)$ и $r(x)\le r(p)$, откуда $a\le2+r'(p)+r'(g)-2r(x)$.
Идея доказательства: оценка $a\le2r'(x)-2r(x)$ равносильна $\log_2\frac{s'(p)}{s'(x)}+\log_2\frac{s'(g)}{s'(x)}\le-2$. После шага поддеревья $p$ и $g$ не пересекаются и вместе дают поддерево $x$ без самой $x$, сумма долей меньше $1$, и работает лемма ($a+b\le1\Rightarrow\log_2a+\log_2b\le-2$). Затем $r'(x)\ge r(x)$ ($x$ поднялся), поэтому $2(r'(x)-r(x))\le3(r'(x)-r(x))$.
Подвох: если поднимать $x$ одиночными поворотами, на каждом шаге оценка $1+3(\dots)$ дала бы лишнюю глубину $x$, которая может быть сколь угодно большой; пары шагов избавляют от $+1$ на шаге.
См.: конспект, «Лекция 11, Анализ шагов zig-zig и zig-zag»

## aisd-c-0421 · aisd-t-059
Как реализовать `find`, `insert` и `erase` в splay-дереве и как это связано с `splay`?
---
Все три операции: спуск как в наивном дереве поиска, затем `splay` самой глубокой посещённой вершины.
- `find(x)`: спуск, затем `splay` найденной вершины, а если $x$ нет — последней посещённой (без этого анализ не сходится).
- `insert(x)`: спуск, подвешиваем $x$ листом, `splay(x)`; если $x$ уже есть, только поднимаем его.
- `erase(x)`: находим $x$; при двух сыновьях записываем на его место минимум $m$ правого поддерева и вырезаем $m$, иначе вырезаем $x$ (ставим на его место единственное поддерево); затем `splay` родителя вырезанной вершины. Если $x$ нет — `splay` последней посещённой.
Реальное время спуска равно реальному времени `splay`, поэтому реальное время операции примерно вдвое больше `splay`.
Подвох: `splay` нужен и при неудачном поиске, и в `erase`; без него потенциал не успевает уравновесить длинный спуск.
См.: конспект, «Лекция 11, find, insert, erase за учётный логарифм»

## aisd-c-0422 · aisd-t-059
Каковы оценки времени `find`, `insert` и `erase` в splay-дереве?
---
Каждая операция занимает $O(\log n)$ амортизированного (учётного) времени; $m$ операций — $O(m\log n)$. Одна операция в худшем случае может занять $O(n)$ (дерево бывает «бамбуком»). Память $O(n)$, на вершину $O(1)$ (число, сыновья, родитель). Доказательство по конспекту здесь не требуется (б/д).
Идея: потенциал $\Psi=2\Phi$ с $\Phi=\sum_v\log_2 s(v)$ даёт $a_{\text{find}}=2a_{\text{splay}}=O(\log n)$; при `insert` потенциал растёт на $O(\log n)$, при `erase` — не больше $\log_2 n$.
Подвох: оценка именно амортизированная, не среднее по случайному входу и не худший случай одной операции.
См.: конспект, «Лекция 11, find, insert, erase за учётный логарифм»

## aisd-c-0423 · aisd-t-060
Как выполнить `split(k)` в splay-дереве?
---
Задача: разбить множество на два дерева — ключи $\le k$ и ключи $>k$.
1. Найти $x$ — максимальный ключ $\le k$: если ключ вершины больше $k$, идём влево, иначе запоминаем вершину и идём вправо.
2. `splay(x)`: в левом поддереве ключи меньше $x$, в правом — больше $x$, и так как $x$ — максимальный ключ $\le k$, все они $>k$.
3. Отрезать правое поддерево: левое дерево — $x$ с левым поддеревом, правое — бывшее правое поддерево.
Если ключей $\le k$ нет, левое дерево пусто. Разрез меняет ранг только у $x$.
Подвох: именно `splay` делает разрез за $O(1)$; без него пришлось бы перестраивать поддеревья.
См.: конспект, «Лекция 11, Чем хорош splay. Merge и split»

## aisd-c-0424 · aisd-t-060
Как выполнить `merge(A,B)` в splay-дереве?
---
Предположение: все ключи $A$ меньше всех ключей $B$.
1. Найти максимум $m$ в $A$: идти вправо, пока можно.
2. `splay(m)`: $m$ — корень $A$, и у него нет правого сына (больше $m$ в $A$ ничего нет).
3. Подвесить $B$ правым сыном $m$.
Инвариант дерева поиска сохраняется. Подвешивание меняет ранг только у $m$, не больше чем на $O(\log n)$.
Подвох: без условия $\max A<\min B$ результат не будет деревом поиска; пустое $A$ или $B$ — тривиальный случай.
См.: конспект, «Лекция 11, Чем хорош splay. Merge и split»

## aisd-c-0425 · aisd-t-060
Какова амортизированная сложность `split` и `merge` в splay-дереве?
---
Обе операции занимают $O(\log n)$ амортизированного времени: основной вклад — один `splay` (учётно $O(\log n)$), остальное — спуск к максимуму/ближайшему ключу и $O(1)$ переподвешиваний. Изменение потенциала: при `merge` меняется ранг только $m$, не больше чем на $O(\log n)$; при `split` ранг меняется только у $x$ и не растёт. Отдельный вызов в худшем случае — $O(n)$. Доказательство не требуется (б/д).
Подвох: оценки амортизированные, а не по матожиданию.
См.: конспект, «Лекция 11, Чем хорош splay. Merge и split»
