## cpp-c-0101 · cpp-t-001
Какие четыре стадии обычно выделяют при сборке C++ программы?
---
1) Препроцессирование: обработка директив, подстановка макросов и `include`, результат — текст единицы трансляции. 2) Компиляция: разбор кода и генерация ассемблера (`.s`). 3) Ассемблирование: объектный файл (`.o`) с машинным кодом. 4) Компоновка: объединение объектных файлов и библиотек в исполняемый файл.
Подвох: cppreference описывает трансляцию как 9 фаз (включая разбор на токены и инстанцирование шаблонов); деление на 4 стадии — практика GCC/Clang. Единицы трансляции можно транслировать отдельно, а затем связать. [не по cppreference]
См.: language/translation_phases

## cpp-c-0102 · cpp-t-001
Что делает компоновщик и что означает `undefined reference`?
---
Компоновщик (линкер) связывает отдельно оттранслированные единицы трансляции (объектные файлы) и библиотеки в исполняемую программу, сопоставляя использования имён с определениями. `undefined reference to 'f()'` — функция объявлена и вызвана, но определения нет ни в одном из переданных файлов или библиотек.
```cpp
void f();
int main() { f(); } // ошибка: нет определения f, ошибка линковки
```
Подвох: это ошибка линковки, а не компиляции: каждый файл по отдельности компилируется успешно. Частые причины: файл не добавлен в сборку, не подключена библиотека, сигнатура определения не совпала с объявлением. [не по cppreference]
См.: language/translation_phases

## cpp-c-0131 · cpp-t-001
Как выполнить только отдельные стадии сборки в GCC/Clang?
---
Флаги останавливают сборку после выбранной стадии: `-E` — только препроцессирование (результат в stdout или в `-o`), `-S` — до ассемблерного кода (`.s`), `-c` — до объектного файла (`.o`). Без этих флагов выполняются все стадии, включая компоновку.
```cpp
// g++ -E main.cpp -o main.i
// g++ -S main.cpp -o main.s
// g++ -c main.cpp -o main.o
// g++ main.o util.o -o prog
```
Подвох: при `-c` линковка не выполняется, поэтому ошибка `undefined reference` проявится только на последнем шаге. [не по cppreference]
См.: language/translation_phases

## cpp-c-0103 · cpp-t-002
Что означает статическая типизация в C++?
---
У каждого выражения и объекта тип известен на этапе компиляции и не меняется; допустимость операций проверяет компилятор по типам. В динамической типизации (Python) тип связан со значением и проверяется во время выполнения. Каждое выражение характеризуется типом и категорией значения.
```cpp
int x = 5;
x = "abc"; // ошибка: нет преобразования const char* в int
```
Подвох: динамический тип есть только у объектов полиморфных классов (с `virtual`), но статический тип выражения фиксирован в любом случае. Определения статической/динамической типизации cppreference не даёт. [не по cppreference]
См.: language/types

## cpp-c-0104 · cpp-t-002
Что такое `size_t`?
---
`std::size_t` — беззнаковый целочисленный тип результата `sizeof`, `sizeof...` и `alignof`. Какой именно это базовый тип, определяет реализация (implementation-defined; обычно `unsigned long`).
```cpp
std::vector<int> v;
for (std::size_t i = v.size(); i-- > 0; ) {}
```
Подвох: беззнаковая арифметика идёт по модулю 2^n: `0u - 1` — максимальное значение, поэтому `for (size_t i = n - 1; i >= 0; --i)` не завершается; при сравнении со знаковым знаковый приводится к беззнаковому.
См.: language/types, language/ub

## cpp-c-0105 · cpp-t-002
Чем отличаются `std::vector`, `std::set` и `std::map` по назначению?
---
`vector` — последовательный контейнер, динамический массив с непрерывным хранением; доступ по индексу за O(1), вставка в конец — амортизированно O(1), в середину — O(n). `map` — отсортированный ассоциативный контейнер пар «ключ–значение» с уникальными ключами; поиск, вставка, удаление за O(log n), обычно красно-чёрное дерево. `set` — аналогично, но хранит только уникальные ключи.
```cpp
std::map<std::string, int> m;
m["a"] = 1; // operator[] вставляет ключ, если его нет
```
Подвох: `m[k]` для отсутствующего ключа создаёт элемент со значением по умолчанию; проверить наличие без вставки — `find`, `count` или `contains` (C++20). `set` в вырезке не разобран.
См.: container/vector, container/map

## cpp-c-0144 · cpp-t-002
Что такое литерал и как задаются суффиксы и префиксы `0`, `0x`?
---
Литерал — токен, задающий константное значение прямо в коде. Целочисленные: десятичный `42`, восьмеричный с префиксом `0` (`052`), шестнадцатеричный `0x2a`, двоичный `0b101010` (C++14). Суффиксы `u`, `l`, `ll` задают беззнаковость и размер; тип — первый из допустимых, в который помещается значение. Вещественный без суффикса — `double`, `f` — `float`, `l` — `long double`.
```cpp
int o = 052;      // 42, восьмеричное
int x = 0x2a;     // 42
auto u = 10u;     // unsigned int
auto f = 1.5f;    // float
```
Подвох: отрицательных литералов нет, `-1` — унарный минус к `1`; `0x1e5` — целое (485), а `0xE+2` лексер читает как одну лексему и это ошибка, нужен пробел.
См.: language/integer_literal, language/floating_literal

## cpp-c-0106 · cpp-t-003
Чем объявление отличается от определения?
---
Объявление вводит имя в программу и задаёт его тип (сущности: переменные, функции, классы, перечисления, псевдонимы типов, пространства имён, шаблоны). Определение — объявление, полностью определяющее сущность: выделяет память под переменную или задаёт тело функции/класса. Любое объявление является определением, кроме перечисленных исключений.
```cpp
extern int x;   // объявление
int x = 1;      // определение
void f();       // объявление
void f() {}     // определение
```
Подвох: исключения: функция без тела, `extern` без инициализатора, не-inline статический член, объявленный внутри класса, предварительное объявление класса `struct S;`, `typedef`/`using`.
См.: language/declarations, language/definition

## cpp-c-0107 · cpp-t-003
Что такое область видимости и время жизни?
---
Область видимости (scope) — участок программы, где имя связано со своим объявлением; бывают глобальная, блочная, область параметров функции, лямбды и др. Время жизни (lifetime) — свойство времени выполнения: у объекта начинается, когда получена память и завершена инициализация, и заканчивается, когда начинается вызов деструктора (для не-классов — когда объект уничтожен) или освобождена память.
```cpp
int i = 42;
for (int i = 0; i < 10; ++i) {} // внутреннее i — в блочной области for
int j = i;                      // j == 42
```
Подвох: scope и lifetime независимы: объект может жить, когда имя уже не видно; ссылка или указатель может пережить объект — получается висячая ссылка/указатель.
См.: language/scope, language/lifetime

## cpp-c-0132 · cpp-t-003
Что такое ODR (правило одного определения) для функций и переменных?
---
В одной единице трансляции допускается не более одного определения переменной или функции. Для каждой не-inline функции или переменной, которая odr-используется, во всей программе нужно ровно одно определение; компилятор не обязан диагностировать нарушение, а поведение такой программы не определено.
```cpp
// a.cpp
int g = 1;
// b.cpp
int g = 2; // ошибка: второе определение g в программе
```
Подвох: несколько определений допустимы для классов, перечислений, inline-функций/переменных и шаблонов, если в разных единицах трансляции они состоят из одной и той же последовательности токенов; inline-функцию нужно определить в каждой единице, где она используется.
См.: language/definition

## cpp-c-0108 · cpp-t-004
Как работают логические операторы `&&` и `||`?
---
Вычисляют операнды слева направо с коротким замыканием: правый операнд не вычисляется, если результат уже определён левым (`false && …`, `true || …`). Операнды контекстно преобразуются к `bool`; результат — `bool`. По приоритету `&&` выше `||`, оба ниже сравнений.
```cpp
int* p = nullptr;
if (p && *p > 0) {} // *p не вычисляется
```
Подвох: перегруженные для классов `&&` и `||` — обычные вызовы функций и теряют короткое замыкание.
См.: language/operator_precedence, language/implicit_conversion

## cpp-c-0109 · cpp-t-004
Чем префиксный инкремент отличается от постфиксного?
---
Префиксный `++x` эквивалентен `x += 1` и возвращает ссылку на сам объект — lvalue. Постфиксный `x++` изменяет объект, а результат — prvalue со значением до изменения.
```cpp
int x = 1;
int a = ++x; // x == 2, a == 2
int b = x++; // x == 3, b == 2
```
Подвох: `++x = 5` допустимо, `x++ = 5` — ошибка (prvalue); `n + ++n` в одном выражении — UB (нарушение последовательности вычислений); для итераторов постфиксная форма дороже из-за копии.
См.: language/operator_incdec

## cpp-c-0133 · cpp-t-004
Что делают тернарный оператор `?:` и оператор «запятая»?
---
`c ? a : b` проверяет `c` как `bool`, вычисляет и возвращает только одну из ветвей; оператор не перегружается. Запятая `a, b` вычисляет `a`, отбрасывает результат, затем вычисляет `b` и возвращает его; у неё самый низкий приоритет, а оператор можно перегрузить.
```cpp
int x = 1, y = 2;
int z = (x++, y); // x == 2, z == 2
int m = x > y ? x : y;
```
Подвох: в списке аргументов `f(a, b)` запятая — разделитель, не оператор; `?:` ассоциативен справа налево; категория значения и общий тип при разных ветвях выводятся по отдельным правилам.
См.: language/operator_other, language/operator_precedence

## cpp-c-0143 · cpp-t-004
Что такое приоритет и ассоциативность операторов? Приведите примеры.
---
Приоритет определяет, какой оператор привязывается к операндам раньше; при равном приоритете порядок задаёт ассоциативность. Сверху вниз: `::`; постфиксные `++ -- () [] . ->`; префиксные `++ --`, унарные `+ - ! ~ * &`, `sizeof`, `new`; `* / %`; `+ -`; `<< >>`; сравнения; `==`; `&`; `^`; `|`; `&&`; `||`; `?:` и присваивания; запятая.
```cpp
int a = 1, b = 2, c = 3;
a = b = c; // присваивание справа налево: a == b == 3
```
Подвох: `*p++` — это `*(p++)`; приоритет не задаёт порядок вычисления операндов (это разные понятия) и не меняется при перегрузке операторов.
См.: language/operator_precedence

## cpp-c-0110 · cpp-t-005
Чем `while` отличается от `do...while`?
---
`while (c) body` проверяет условие перед каждой итерацией, поэтому тело может не выполниться ни разу. `do body while (c);` сначала безусловно выполняет тело, затем проверяет условие, поэтому тело выполняется минимум один раз.
```cpp
int i = 10;
while (i < 10) { }     // 0 итераций
do { } while (i < 10); // 1 итерация
```
Подвох: после `do...while (…)` обязательна `;`; цикл без наблюдаемого поведения, который не завершается, — UB (компилятор вправе его удалить); с C++26 тривиальные бесконечные циклы вроде `while (true);` больше не UB. В условии `while` можно объявить переменную — она создаётся заново на каждой итерации.
См.: language/while, language/do

## cpp-c-0111 · cpp-t-005
Что делают `break` и `continue` в цикле?
---
`break` завершает ближайший объемлющий цикл (или `switch`). `continue` завершает текущую итерацию и переходит к следующей: в `for` сначала вычисляется выражение-итерация, затем проверяется условие.
```cpp
for (int i = 0; i < 5; ++i) {
    if (i == 1) continue;
    if (i == 3) break;   // выполнятся тела при i = 0 и i = 2
}
```
Подвох: `break` выходит только из одного уровня вложенности; в `while` и `do` `continue` переходит к проверке условия.
См.: language/for, language/while

## cpp-c-0134 · cpp-t-005
Как работает `switch` и что такое fallthrough?
---
Условие `switch` должно иметь целочисленный или перечислимый тип (или класс, неявно приводимый к такому). Управление передаётся на `case` с равной константой, иначе на `default`, а если его нет — выполнение пропускается. Метки сами поток не меняют: выполнение идёт дальше по тексту, пока не встретится `break`.
```cpp
switch (x) {
    case 1: f(); break;
    case 2: g();               // провал в case 3
    [[fallthrough]];           // C++17: провал намеренный
    case 3: h(); break;
    default: break;
}
```
Подвох: два `case` с одинаковым значением или два `default` — ошибка компиляции; по строке `switch` не работает; компиляторы могут предупреждать о непреднамеренном провале.
См.: language/switch

## cpp-c-0145 · cpp-t-005
Что делает `return`?
---
`return expr;` вычисляет выражение, неявно преобразует его к возвращаемому типу, завершает текущую функцию и возвращает значение вызывающему. В функции с `void` выражение не нужно (`return;`); в конструкторе и деструкторе выражение запрещено.
```cpp
int sign(int x) {
    if (x > 0) return 1;
    if (x < 0) return -1;
    return 0;
}
```
Подвох: если управление дошло до конца функции с не-`void` возвращаемым типом без `return` — это UB (кроме `main`, где неявно выполняется `return 0;`).
См.: language/return

## cpp-c-0112 · cpp-t-006
Что называют неопределённым поведением (undefined behavior, UB)?
---
Поведение, на которое стандарт не накладывает никаких ограничений: программа может работать «как задумано», упасть или выдать любой результат. Реализация не обязана диагностировать UB, а компилятор вправе считать, что UB не возникает, и оптимизировать исходя из этого.
```cpp
int a[3] = {};
int x = a[5];   // ошибка: выход за границы массива, UB
int m = INT_MAX;
m += 1;         // ошибка: знаковое переполнение, UB
```
Подвох: UB влияет на программу в целом, а не на одну строку; примеры: разыменование нулевого указателя, гонки данных, неупорядоченные изменения одного скаляра, доступ через указатель другого типа. Не путать с implementation-defined (поведение документировано) и unspecified (например, порядок вычисления аргументов).
См.: language/ub

## cpp-c-0113 · cpp-t-006
Чем ошибка компиляции отличается от ошибки времени выполнения?
---
Ошибка компиляции (CE) возникает при трансляции: программа ill-formed, и компилятор обязан выдать диагностику. Виды: лексическая (нельзя разбить на токены), синтаксическая (нарушена грамматика), семантическая (необъявленное имя, несовпадение типов). Ошибка времени выполнения (RE) возникает при запуске: неперехваченное исключение, обращение по нулевому указателю, деление на ноль.
```cpp
int foo = 1;
int a = 0xE+foo;     // ошибка: «жадная» лексема 0xE+foo недопустима
int b = foo+++++bar; // ошибка: читается как foo++ ++ +bar
```
Подвох: лексер берёт самую длинную возможную лексему (maximal munch), пробел `0xE + foo` это лечит. Часть нарушений (ODR) не диагностируется. Примеры RE — [не по cppreference].
См.: language/translation_phases, language/ub

## cpp-c-0114 · cpp-t-007
Что делают операторы взятия адреса и разыменования указателя?
---
`&x` применяется к выражению типа объекта и возвращает указатель на него — адрес первого байта объекта. `*p` — встроенное разыменование: возвращает lvalue, обозначающий объект, на который указывает `p`.
```cpp
int x = 1;
int* p = &x;
*p = 2;       // x == 2
```
Подвох: разыменование недействительного указателя (в том числе `nullptr` и указателя «за концом» объекта) — UB. Указатель на ссылку и указатель на битовое поле создать нельзя.
См.: language/pointer

## cpp-c-0115 · cpp-t-007
На сколько элементов сдвигает `p + n` указатель `p`?
---
На `n` элементов типа, на который указывает `p`, то есть адрес меняется на `n * sizeof(T)` байт. Сложение, вычитание, инкремент и декремент определены для указателей на элементы массива; допустим результат внутри массива и указатель сразу за последним элементом.
```cpp
int a[4] = {};
int* p = a;
int* q = p + 4; // допустимо (за концом), но разыменовывать q нельзя
```
Подвох: разыменование указателя «за концом» — UB; сравнение `p < q` определено для указателей на элементы одного массива; для `void*` арифметика недоступна (`void` — неполный тип).
См.: language/pointer, language/types

## cpp-c-0135 · cpp-t-007
Чем `nullptr` отличается от `NULL` и что такое `void*`?
---
`nullptr` — ключевое слово, prvalue типа `std::nullptr_t`; неявно преобразуется в нулевое значение любого типа указателя, но не в целое. `NULL` — макрос, тоже нулевая константа-указатель, но реализация определяет, чем он является (часто целый `0`), поэтому в перегрузке он может выбрать версию с целым параметром. `void*` — указатель на объект неизвестного типа: разыменовать его и применить арифметику нельзя.
```cpp
void f(int);
void f(char*);
f(nullptr); // вызывается f(char*)
```
Подвох: из `void*` в `T*` в C++ нужно явное `static_cast`. Нулевая константа теряет свойство после передачи через шаблон: `clone(0)` не даёт указатель, а `clone(nullptr)` даёт. Перегрузка с `NULL` — по практике. [не по cppreference]
См.: language/nullptr, language/types

## cpp-c-0146 · cpp-t-007
Как реализовать `swap` через указатели и как выводятся указатели в `cout`?
---
Функция принимает адреса и меняет значения по ним через разыменование.
```cpp
void swap(int* a, int* b) {
    int t = *a;
    *a = *b;
    *b = t;
}
// int x = 1, y = 2; swap(&x, &y);
```
Подвох: нулевой или недействительный указатель — UB. `std::cout << p` для указателя печатает адрес (обычно в шестнадцатеричном виде), а для `char*` печатает строку до `'\0'`. [не по cppreference]

## cpp-c-0116 · cpp-t-008
Какова роль секций `text` и `data` в типичной модели памяти программы?
---
`text` — машинный код программы (обычно только для чтения и исполнения). `data` — глобальные и статические переменные с начальными значениями; неинициализированные или нулевые обычно лежат в `bss`. Остальное: стек (автоматические объекты) и куча (динамическая память).

## cpp-c-0117 · cpp-t-008
Что называют автоматической памятью и переполнением стека?
---
Автоматическую длительность хранения имеют переменные блочной области (без `static`, `thread_local`, `extern`) и параметры функции: память живёт до выхода из блока. Обычно она размещается на стеке вызовов. Переполнение стека (stack overflow) — исчерпание стека, например бесконечной рекурсией или огромным локальным массивом.
```cpp
int f(int n) { return f(n + 1) + 1; } // ошибка: бесконечная рекурсия
```
Подвох: стек имеет ограниченный размер (в Linux по умолчанию около 8 МБ), стандарт его не описывает; большие массивы лучше размещать в куче. [не по cppreference]
См.: language/storage_duration

## cpp-c-0136 · cpp-t-008
Как работают `new` и `delete` и какие типичные ошибки?
---
`new T(args)` выделяет память с динамической длительностью хранения, создаёт объект и возвращает prvalue-указатель на него. `delete p` вызывает деструктор и освобождает память; `p` должен быть нулевым или указателем, полученным из `new` (не из `new[]`). Время жизни объекта задаёт программист.
```cpp
int* p = new int(5);
delete p;
p = nullptr;
```
Подвох: не вызвали `delete` — утечка памяти; повторный `delete` того же указателя и использование после `delete` — UB; `delete nullptr` безопасен; `delete` на указатель из `new[]` — UB (нужен `delete[]`).
См.: language/new, language/delete

## cpp-c-0147 · cpp-t-008
Что такое локальная статическая переменная?
---
Переменная блочной области, объявленная с `static`, имеет статическую длительность хранения: её память существует всё время работы программы, хотя имя видно только в блоке. Значение сохраняется между вызовами функции.
```cpp
int next() {
    static int n = 0; // инициализируется один раз
    return ++n;       // 1, 2, 3, ...
}
```
Подвох: инициализация выполняется при первом прохождении управления через объявление, а не при каждом вызове; у такой переменной нет внешней компоновки. [не по cppreference]
См.: language/storage_duration

## cpp-c-0118 · cpp-t-009
Как определяется выражение `a[i]` для встроенного массива?
---
Оператор `[]` обращается к элементу массива; для встроенного массива `a[i]` равно `*(a + i)`: массив неявно преобразуется в указатель на первый элемент, затем прибавляется `i` и результат разыменовывается. Результат — lvalue элемента с номером `i` из `0 … N-1`.
```cpp
int a[3] = {10, 20, 30};
int x = a[1];      // 20
int y = *(a + 1);  // 20, то же самое
```
Подвох: границы не проверяются, выход за них — UB; размер массива должен быть константным выражением больше нуля (кроме `new[]`).
См.: language/array, language/pointer

## cpp-c-0119 · cpp-t-009
Назовите одно ключевое различие массива и указателя.
---
Массив — один объект из `N` подряд лежащих элементов; размер входит в тип (`int[5]`), `sizeof(a)` равен `N * sizeof(T)`. Указатель — отдельный объект, хранящий адрес; `sizeof(p)` — размер указателя. Массив неявно преобразуется в указатель на первый элемент (array-to-pointer decay), но обратно нет.
```cpp
int a[3] = {1, 2, 3};
int* p = a;       // a превратился в &a[0]
int b[3] = {};
// a = b;         // ошибка: массив нельзя присвоить целиком
```
Подвох: у многомерного массива преобразование срабатывает один раз: `int b[2][3]` даёт `int (*)[3]`, а не `int**`; ссылки на массив (`int (&)[3]`) и range-for работают с массивом, но не с указателем.
См.: language/array, language/pointer

## cpp-c-0137 · cpp-t-009
Чем `new[]` и `delete[]` отличаются от `new` и `delete`?
---
`new T[n]` создаёт массив из `n` объектов и возвращает указатель на первый элемент; `n` может быть задан во время выполнения (только первая размерность). `delete[] p` разрушает все элементы (от последнего к первому) и освобождает память. `p` должен быть нулевым или результатом `new[]`; одиночный `delete` для массива — UB, и наоборот.
```cpp
int n = 3;
int* a = new int[n];
delete[] a;
```
Подвох: массив нулевого размера допустим, но обращаться к его элементам нельзя, а `delete[]` всё равно нужен.
См.: language/new, language/delete, language/array

## cpp-c-0120 · cpp-t-010
Что такое перегрузка функций?
---
Несколько функций с одним именем в одной области видимости, но с разными списками параметров. Если имя обозначает несколько сущностей, компилятор разрешает перегрузку и вызывает ту, чьи параметры лучше всего соответствуют аргументам.
```cpp
void f(int);
void f(double);
f(1);   // f(int)
f(1.0); // f(double)
```
Подвох: функции, отличающиеся только возвращаемым типом, — не перегрузки (ошибка компиляции).
См.: language/overload_resolution, language/function

## cpp-c-0121 · cpp-t-010
По чему разрешается перегрузка функции?
---
Компилятор строит набор кандидатов, оставляет жизнеспособные (подходящие по числу и типам аргументов с неявными преобразованиями) и выбирает единственную лучшую по качеству преобразований. Возвращаемый тип в выборе не участвует.
```cpp
void f(long);
void f(float);
f(0L); // f(long)
f(0);  // ошибка: неоднозначная перегрузка
```
Подвох: если лучшей функции нет, вызов неоднозначен и это ошибка компиляции; неоднозначность могут создавать и аргументы по умолчанию.
См.: language/overload_resolution

## cpp-c-0138 · cpp-t-010
Что такое аргументы по умолчанию и как массив передаётся в функцию?
---
Параметру функции задают значение по умолчанию; оно подставляется вместо пропущенных последних аргументов. После параметра с умолчанием все следующие тоже должны иметь умолчание (в этом или предыдущем объявлении той же области). Массив при передаче неявно преобразуется в указатель на первый элемент, размер теряется; чтобы сохранить его, принимают ссылку на массив.
```cpp
void point(int x = 3, int y = 4);
point(1);  // point(1, 4)
void g(int (&a)[3]); // принимает только int[3]
```
Подвох: повторное объявление не может заново задать уже заданное умолчание; значения вычисляются в момент вызова. В `sizeof` внутри функции с `int* p` получится размер указателя.
См.: language/default_arguments, language/array

## cpp-c-0122 · cpp-t-011
Как объявляют ссылку на `T` и что она обозначает?
---
`T& r = x;` — lvalue-ссылка, псевдоним уже существующего объекта или функции. Её обязательно инициализируют при объявлении, и все действия над `r` — это действия над `x`.
```cpp
int x = 1;
int& r = x;
r = 5;      // x == 5
```
Подвох: `T&` не привязывается к rvalue (`int& r = 5;` — ошибка), но `const T&` привязывается; ссылка — не объект и не обязана занимать память.
См.: language/reference, language/reference_initialization

## cpp-c-0123 · cpp-t-011
Можно ли переназначить ссылку после инициализации?
---
Нет. После инициализации ссылку нельзя перепривязать; любое присваивание через ссылку присваивает обозначаемому объекту.
```cpp
int a = 1, b = 2;
int& r = a;
r = b; // a == 2, r по-прежнему ссылается на a
```
Подвох: из-за этого у классов со ссылочными полями неявный конструктор по умолчанию удалён, если у ссылки нет инициализатора; ссылку член-данных инициализируют в списке инициализации.
См.: language/reference_initialization, language/default_constructor

## cpp-c-0139 · cpp-t-011
Какие ссылки и указатели с участием ссылок бывают, и что такое висячая ссылка?
---
Ссылки — не объекты, поэтому нельзя: ссылку на ссылку (в явном виде), указатель на ссылку, массив ссылок. Можно ссылку на массив (`int (&)[3]`) и ссылку на указатель (`int*&`). Ссылки на ссылки возникают только через typedef и шаблоны и схлопываются (reference collapsing). Висячая ссылка обозначает объект, чьё время жизни закончилось; обращение к ней — UB.
```cpp
int& f() {
    int x = 1;
    return x; // ошибка: ссылка на локальную переменную, висячая
}
```
Подвох: ссылка не обязана занимать память, но компилятор выделяет её при необходимости (ссылочное поле обычно увеличивает класс на размер адреса); с C++26 возврат ссылки на временный объект — ошибка компиляции.
См.: language/reference, language/lifetime

## cpp-c-0148 · cpp-t-011
Как реализовать `swap` через ссылки?
---
Параметры — ссылки на `int`, поэтому функция меняет сами объекты вызывающего кода, а не копии; адреса брать и разыменовывать не нужно.
```cpp
void swap(int& a, int& b) {
    int t = a;
    a = b;
    b = t;
}
// int x = 1, y = 2; swap(x, y);
```
Подвох: в `swap(x, x)` обе ссылки обозначают один объект — здесь это безопасно; в отличие от указателей, ссылка не бывает нулевой.
См.: language/reference

## cpp-c-0124 · cpp-t-012
Что означает `const T* p`?
---
`p` — указатель на константный `T`: менять объект через `p` нельзя, но сам `p` можно переназначить. Запись `T const* p` — то же самое.
```cpp
int a = 1, b = 2;
const int* p = &a;
p = &b;      // можно
// *p = 3;   // ошибка: объект константен через p
```
Подвох: сам `a` можно менять по его имени; а вот изменение объекта, объявленного `const`, через указатель на неконстантный тип (после `const_cast`) — UB. Преобразование к более cv-квалифицированному типу неявное, обратно — только `const_cast`.
См.: language/cv

## cpp-c-0125 · cpp-t-012
Что означает `T* const p`?
---
`p` — константный указатель на неконстантный `T`: сам `p` нельзя переназначить (обязан быть инициализирован), но объект по нему менять можно.
```cpp
int a = 1, b = 2;
int* const p = &a;
*p = 5;      // можно
// p = &b;   // ошибка: p константен
```
Подвох: бывает `const T* const p` — нельзя менять ни указатель, ни объект. Квалификатор `const` после `*` относится к самому указателю.
См.: language/cv, language/pointer

## cpp-c-0140 · cpp-t-012
Как передавать аргументы в функцию и что такое продление жизни временного объекта?
---
Малые примитивные типы — по значению; большие объекты, которые не нужно менять, — по `const T&`; если функция должна изменить аргумент — по `T&`. Ссылка на `const` (и rvalue-ссылка) может привязаться к временному объекту и продлевает его жизнь до конца жизни ссылки.
```cpp
std::string s1 = "Test";
const std::string& r = s1 + s1; // временный объект живёт, пока жива r
void f(const std::string&);
f("abc");                        // временная строка живёт до конца вызова
```
Подвох: неконстантная lvalue-ссылка к временному не привязывается (`int& r = 5;` — ошибка). Рекомендации по способам передачи — практика, а не cppreference. [не по cppreference]
См.: language/reference, language/reference_initialization

## cpp-c-0149 · cpp-t-012
Можно ли перегружать функции по `int&` и `const int&`?
---
Да, это разные типы параметров: неконстантный lvalue выбирает версию `int&`, константный lvalue — `const int&`, а временное значение (rvalue) — `const int&`, потому что `int&` к rvalue не привязывается.
```cpp
void f(int& x);
void f(const int& x);
int i = 1;
const int ci = 2;
f(i);  // f(int&)
f(ci); // f(const int&)
f(3);  // f(const int&)
```
Подвох: если добавить перегрузку `f(int&&)`, то `f(3)` и `f(std::move(i))` пойдут в неё.
См.: language/reference, language/reference_initialization

## cpp-c-0126 · cpp-t-013
В чём основное отличие `static_cast` от C-style cast?
---
`static_cast<T>(x)` выполняет только преобразования, перечисленные для него (неявные, обратные к стандартным, вверх/вниз по иерархии, `void*` в `T*`), и никогда не снимает `const`. C-style cast `(T)x` пробует по порядку: `const_cast`, `static_cast` (в том числе игнорируя закрытое наследование), `static_cast` + `const_cast`, `reinterpret_cast`, `reinterpret_cast` + `const_cast` — и берёт первый подошедший.
```cpp
const int c = 1;
// int* p = static_cast<int*>(&c); // ошибка: снимает const
int* q = (int*)&c;                 // компилируется как const_cast; запись через q — UB
```
Подвох: C-style cast молча превращается в `reinterpret_cast`, скрывает намерение и ищется в тексте хуже; `static_cast` вниз по иерархии к типу, которым объект не является, — UB.
См.: language/static_cast, language/explicit_cast

## cpp-c-0127 · cpp-t-014
Каково различие доступа по умолчанию у `struct` и `class`?
---
У `class` члены и базовые классы по умолчанию `private`, у `struct` (и `union`) — `public`. Других различий нет: оба могут иметь методы, конструкторы, наследование.
```cpp
struct S { int x; };   // x public
class C { int x; };    // x private
```
Подвох: наследование тоже: `struct D : B` — публичное, `class D : B` — приватное; обращение к закрытому члену снаружи — ошибка компиляции.

## cpp-c-0128 · cpp-t-014
Чем `p->member` эквивалентно для указателя на объект?
---
Выражению `(*p).member`: сначала разыменование указателя, затем доступ к члену. Оператор `.` применяют к объекту или ссылке, `->` — к указателю.
```cpp
struct P { int x; };
P a{1};
P* p = &a;
int v = p->x; // 1
```
Подвох: скобки в `(*p).member` обязательны, так как `.` приоритетнее `*`; `->` можно перегрузить для класса, `.` — нельзя. Встроенный `p->m` эквивалентен `(*p).m`.

## cpp-c-0141 · cpp-t-014
Что такое `this`, `friend` и инкапсуляция?
---
`this` — prvalue-указатель на объект, для которого вызван нестатический метод; его тип `X*` (в `const`-методе — `const X*`). Инкапсуляция — скрытие реализации (`private`) за открытым интерфейсом (`public`). Объявление `friend` даёт функции или классу доступ к `private` и `protected` членам.
```cpp
class A {
    int x = 0;
    friend void peek(const A& a);
};
void peek(const A& a) { int v = a.x; (void)v; } // доступ благодаря friend
```
Подвох: `friend` не объявляет метод — функцию определяют отдельно как внешнюю; `this->x` нужен, когда параметр заслоняет член.
См.: language/friend, language/this, language/access

## cpp-c-0150 · cpp-t-014
Что такое инициализатор поля по умолчанию (default member initializer)?
---
Значение, заданное прямо в объявлении нестатического поля: `int n = 5;`. Оно используется конструкторами, которые не указали это поле в списке инициализации.

```cpp
struct S {
```

## cpp-c-0129 · cpp-t-015
Что делает конструктор класса?
---
Конструктор — нестатическая функция-член особого вида, инициализирующая объект класса. Имя совпадает с именем класса, возвращаемого типа нет (и квалификаторов `const`/`ref` нет). Вызывать его напрямую нельзя: он запускается при инициализации и выбирается по её правилам; конструкторы можно перегружать.

```cpp
struct S {

S s(10);
```

## cpp-c-0130 · cpp-t-015
Для чего нужен список инициализации конструктора?
---
Он задаёт инициализацию баз и нестатических полей, которая завершается до входа в тело конструктора; присваивание в теле — это уже вторая запись после инициализации по умолчанию. Список обязателен для ссылочных и `const` полей и баз/полей без конструктора по умолчанию.
```cpp
struct B {
    const int c;
    int& r;
    B(int v, int& x) : c(v), r(x) {}
};
```
Подвох: порядок инициализации определяется порядком объявления полей в классе, а не порядком в списке.
См.: language/initializer_list

## cpp-c-0151 · cpp-t-015
Когда компилятор генерирует конструктор по умолчанию?
---
Если в классе нет ни одного пользовательского конструктора, компилятор неявно объявляет публичный inline-конструктор по умолчанию; он вызывает конструкторы по умолчанию баз и полей. Если конструкторы заданы, генерацию можно вернуть записью `= default`.
```cpp
struct A { int x; };                  // A() есть неявно
struct B { B(int); };                 // B() нет
struct C { C(int); C() = default; };  // принудительно
```
Подвох: неявный конструктор определяется как удалённый, например при ссылочном поле без инициализатора или поле класса без доступного конструктора по умолчанию; `= delete` запрещает генерацию.
См.: language/default_constructor

## cpp-c-0142 · cpp-t-015
Что делают деструктор, `= default` и `= delete`, и каков порядок вызова?
---
Деструктор `~A()` неявно вызывается, когда заканчивается время жизни объекта (выход из области, `delete`, конец программы, конец полного выражения для временных) и освобождает ресурсы. Конструкторы выполняются: базы, затем поля в порядке объявления, затем тело; деструкторы — в обратном порядке. `= default` просит компилятор сгенерировать функцию, `= delete` запрещает её.
```cpp
struct A {
    A() = default;
    A(const A&) = delete;
    ~A() {}
};
```
Подвох: попытка вызвать удалённую функцию — ошибка компиляции.
См.: language/destructor, language/default_constructor
