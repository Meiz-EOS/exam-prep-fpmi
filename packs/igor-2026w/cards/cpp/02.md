## cpp-c-0201 · cpp-t-016
Что делает конструктор копирования?
---
Конструктор копирования `T(const T&)` создаёт новый объект того же класса из существующего: его первый параметр — `T&`, `const T&` и т. п., остальные (если есть) имеют значения по умолчанию. Вызывается при `T b = a;`, `T b(a);`, передаче и возврате по значению.
Подвох: если он не объявлен, компилятор неявно объявляет его (почленное копирование); он будет удалён, если у класса есть пользовательский move-конструктор или move-присваивание. Конструктор `T(T)` недопустим.
См.: language/copy_constructor

## cpp-c-0202 · cpp-t-016
В чём различие поверхностного и глубокого копирования объекта с указателем-владельцем?
---
Поверхностное копирует значение указателя, и два объекта владеют одним ресурсом; глубокое выделяет новый ресурс и копирует в него содержимое.
```cpp
String(const String& o) : size_(o.size_), data_(new char[o.size_ + 1]) {
    std::copy(o.data_, o.data_ + o.size_ + 1, data_);
}
```
Подвох: неявный конструктор копирования делает именно поверхностную копию, поэтому деструкторы обоих объектов делают `delete` одного указателя (двойное освобождение, UB).
См.: language/copy_constructor, language/rule_of_three

## cpp-c-0203 · cpp-t-016
Что формулирует правило трёх?
---
Если классу нужен пользовательский деструктор, конструктор копирования или копирующее присваивание, то, скорее всего, нужны все три: каждый из них обычно управляет ресурсом, а неявные версии копируют его поверхностно.
Подвох: с C++11 неявная генерация копирующих операций при пользовательском деструкторе объявлена устаревшей (deprecated), но не запрещена; при добавлении move-операций правило превращается в правило пяти.
См.: language/rule_of_three

## cpp-c-0244 · cpp-t-016
Когда компилятор генерирует копирующее присваивание?
---
Если в классе нет пользовательского `operator=(const T&)`, оно неявно объявляется и определяется как почленное присваивание (базы и поля в порядке объявления).
Подвох: оно удалено, если есть пользовательский move-конструктор или move-присваивание, а также если поле — ссылка, `const`-объект или тип без доступного присваивания. Неявное присваивание, как и копи-конструктор, копирует указатели поверхностно.
См.: language/as_operator

## cpp-c-0245 · cpp-t-016
Как реализовать копирующее присваивание для String безопасно при самоприсваивании?
---
Через идиому copy-and-swap: создать копию аргумента и обменять с ней состояние; старые данные освободит деструктор временной копии.
```cpp
String& operator=(const String& o) {
    String tmp(o);
    std::swap(data_, tmp.data_);
    std::swap(size_, tmp.size_);
    return *this;
}
```
Подвох: при исключении в конструкторе копии `*this` не меняется (строгая гарантия), `s = s` работает без отдельной проверки `this == &o`; оператор должен возвращать `T&`.
См.: language/rule_of_three, language/as_operator

## cpp-c-0204 · cpp-t-017
Что означает const после списка параметров метода?
---
`this` внутри такого метода имеет тип `const T*`, поэтому он не может изменять нестатические поля (кроме `mutable`) и вызывать неконстантные методы; зато его можно вызывать для константного объекта.
```cpp
struct A {
    int x = 0;
    int get() const { return x; }
    // void set() const { x = 1; } // ошибка
};
```
Подвох: `const` защищает только сам объект: через указатель-член можно изменить то, на что он указывает; изменение `const`-объекта в обход — UB.
См.: language/cv, language/member_functions

## cpp-c-0205 · cpp-t-017
Как могут перегружаться методы, различающиеся только константностью?
---
Квалификатор `const` метода входит в сигнатуру, поэтому `f()` и `f() const` — разные перегрузки: для неконстантного объекта выбирается неконстантная, для константного — только const-версия. Так обычно пишут `operator[]`.
```cpp
int& operator[](size_t i) { return d_[i]; }
const int& operator[](size_t i) const { return d_[i]; }
```
Подвох: если есть только const-версия, она вызывается и для неконстантного объекта; обратное невозможно: из `const`-объекта неконстантный метод не вызвать.
См.: language/member_functions, language/overload_resolution

## cpp-c-0206 · cpp-t-017
Что означает static у метода класса?
---
Статический метод не связан с объектом: у него нет `this`, поэтому нестатические члены он использует только через конкретный объект. Вызывается как `T::f()` или через объект.
```cpp
struct C { static int n; static int get() { return n; } };
int C::n = 0; // определение статического поля вне класса
```
Подвох: объявление `static`-поля в теле класса — не определение: до C++17 нужно определение в одном `.cpp`, с C++17 помогает `inline static`; статический метод нельзя сделать `const` или `virtual`.
См.: language/static

## cpp-c-0246 · cpp-t-017
Что делает mutable у поля и где применяется?
---
Поле с `mutable` можно изменять даже в const-методе и у константного объекта; типичный случай — кэш, счётчик обращений, мьютекс.
```cpp
struct S {
    mutable int hits = 0;
    int f() const { return ++hits; }
};
```
Подвох: `mutable` нельзя применять к ссылкам и к полям, объявленным `const`; он не должен менять наблюдаемое логическое состояние.
См.: language/cv

## cpp-c-0207 · cpp-t-018
Какова идея наследования?
---
Класс объявляется производным списком баз `class D : public B`: каждый объект `D` содержит `B` как подобъект, а при публичном наследовании public- и protected-члены базы сохраняют свой уровень доступа в `D`. Конструкторы подобъектов базы вызывает конструктор производного класса.
Подвох: приватные члены базы всегда недоступны из `D`; уровень наследования по умолчанию — `private` для `class` и `public` для `struct`.
См.: language/derived_class

## cpp-c-0208 · cpp-t-018
Каково назначение protected у члена класса?
---
`protected`-член доступен членам и друзьям самого класса и членам и друзьям производных классов, но не внешнему коду.
```cpp
struct B { protected: int x = 0; };
struct D : B { void f(D& d) { d.x = 1; } }; // OK; через B& b: b.x — ошибка
```
Подвох: из `D` защищённый член базы доступен только через объект типа `D` (или производного), но не через ссылку или указатель на `B`.
См.: language/access

## cpp-c-0209 · cpp-t-018
В каком порядке вызываются конструкторы и деструкторы при наследовании?
---
Конструктор производного класса вызывает конструкторы баз (виртуальные базы инициализируются раньше невиртуальных), затем инициализирует поля в порядке объявления и выполняет тело; деструкторы вызываются в обратном порядке.
Подвох: аргументы конструктору базы передают в списке инициализации производного, а конструктор виртуальной базы вызывает только самый производный класс; порядок определяет объявление (прямые базы — слева направо в списке баз класса, затем поля), а не список инициализации.
См.: language/initializer_list, language/derived_class

## cpp-c-0247 · cpp-t-018
Как объект производного класса размещается в памяти?
---
Каждая прямая и косвенная база присутствует в объекте производного класса как подобъект на смещении, зависящем от ABI; пустые базы обычно не увеличивают размер (empty base optimization).
Подвох: на практике (GCC/Clang) при одиночном наследовании база лежит в начале объекта, а при множественном адрес второй базы смещён, поэтому приведение указателя может менять его значение. [не по cppreference]
См.: language/derived_class

## cpp-c-0210 · cpp-t-019
Что называется приведением «вверх» при публичном наследовании?
---
Неявное преобразование указателя или ссылки на производный класс в указатель или ссылку на доступную однозначную базу (`D*` в `B*`, `D&` в `B&`). Явное приведение не нужно.
```cpp
D d;
B* p = &d; // upcast
B& r = d;  // upcast
```
Подвох: статический тип меняется, динамический остаётся `D`, поэтому виртуальные вызовы идут в `D`; при неоднозначной или недоступной базе преобразование — ошибка компиляции.
См.: language/implicit_conversion, language/derived_class

## cpp-c-0211 · cpp-t-019
Что такое срезка при копировании производного объекта в базовый объект?
---
При инициализации или присваивании объекта базового типа объектом производного копируется только базовый подобъект; поля производного класса теряются, а динамический тип нового объекта — `B`.
```cpp
D d;
B b = d; // копируется только B-часть
```
Подвох: срезает и передача параметра по значению (`void f(B)`); ссылки и указатели не срезают. Виртуальные вызовы у `b` идут в `B`. [не по cppreference]
См.: language/copy_constructor

## cpp-c-0212 · cpp-t-019
Как static_cast ведёт себя при приведении по иерархии наследования?
---
Вверх — всегда корректно. Вниз (`B*` в `D*`, `B&` в `D&`) допускается для невиртуальной доступной однозначной базы, но без проверки во время выполнения: если объект на самом деле не `D`, поведение не определено.
```cpp
D d; B* pb = &d;
D* pd = static_cast<D*>(pb); // OK: объект действительно D
```
Подвох: приведение вниз через виртуальную базу `static_cast` не умеет — нужен `dynamic_cast` (требует полиморфный тип, при неудаче даёт `nullptr` или `bad_cast`).
См.: language/static_cast, language/dynamic_cast

## cpp-c-0213 · cpp-t-020
Зачем нужны шаблоны?
---
Шаблон описывает семейство функций или классов, параметризованных типами и значениями; компилятор генерирует конкретную сущность при инстанцировании. Так один код работает для разных типов без потери производительности.
```cpp
template<class T> T mx(T a, T b) { return a < b ? b : a; }
// mx(1, 2) и mx(1.5, 0.5) — две разные функции
```
Подвох: шаблон — не код, а «чертёж»; определение должно быть видно в точке инстанцирования, поэтому обычно лежит в заголовке.
См.: language/templates

## cpp-c-0214 · cpp-t-020
Чем шаблон функции отличается от шаблона класса?
---
Шаблон функции задаёт семейство функций, аргументы шаблона обычно выводятся из аргументов вызова; шаблон класса задаёт семейство классов, аргументы обычно указываются явно (с C++17 возможен вывод CTAD).
```cpp
template<class T> T id(T x) { return x; }
template<class T> struct Box { T v; };
id(5);       // T выведен
Box<int> b{};
```
Подвох: частичной специализации у шаблонов функций нет (только перегрузка и полная специализация), у шаблонов классов и переменных — есть.
См.: language/function_template, language/class_template

## cpp-c-0215 · cpp-t-020
Что задаёт шаблонный псевдоним типа?
---
Шаблон псевдонима `template<class T> using Vec = std::vector<T>;` задаёт семейство имён типов; `Vec<int>` — просто другое имя `std::vector<int>`, а не новый тип.
Подвох: `typedef` шаблонным быть не может; шаблон псевдонима нельзя специализировать (ни частично, ни явно) и он не выводится при выводе шаблонного шаблонного параметра.
См.: language/type_alias

## cpp-c-0248 · cpp-t-020
Что такое шаблонная переменная?
---
Шаблон переменной (C++14) задаёт семейство переменных по параметрам шаблона.
```cpp
template<class T> constexpr T pi = T(3.14159265358979L);
double d = pi<double>;
float f = pi<float>;
```
Подвох: аргументы указываются всегда явно, `pi` без них — ошибка; шаблонные статические поля класса определяются вне класса отдельным `template<...>`.
См.: language/variable_template

## cpp-c-0249 · cpp-t-020
Как определить шаблонный метод шаблонного класса вне класса?
---
Нужны два отдельных списка параметров: сначала класса, потом метода.
```cpp
template<class T> struct A { template<class U> void f(U u); };
template<class T> template<class U>
void A<T>::f(U u) {}
```
Подвох: списки `template<class T, class U>` объединять нельзя; внеклассовое определение обязано быть эквивалентным объявлению в классе, иначе оно считается перегрузкой.
См.: language/member_template

## cpp-c-0216 · cpp-t-021
Что такое нетиповой параметр шаблона?
---
Параметр шаблона, принимающий значение, а не тип: целое, перечисление, указатель/ссылка на объект или функцию, `nullptr_t`; с C++20 также число с плавающей точкой и структурный литеральный класс. Аргумент — константное выражение.
```cpp
template<int N> struct Buf { char d[N]; };
Buf<16> b;
```
Подвох: до C++20 нельзя `double` и класс-тип; внутри шаблона имя такого параметра — немодифицируемый prvalue; значение времени выполнения передать нельзя.
См.: language/template_parameters

## cpp-c-0217 · cpp-t-021
Какова роль числового параметра в шаблоне массива фиксированного размера?
---
Размер известен на этапе компиляции и входит в тип: `Arr<int,3>` и `Arr<int,4>` — разные несовместимые типы, память хранится внутри объекта.
```cpp
template<class T, std::size_t N> struct Arr { T d[N]; };
Arr<int, 3> a;
// Arr<int, 4> b = a; // ошибка: другой тип
```
Подвох: `N` — константа компиляции; каждая комбинация значений даёт отдельную инстанциацию (раздувание кода).
См.: language/template_parameters, container/array

## cpp-c-0250 · cpp-t-021
Как объявляют оператор умножения матриц для класса Matrix<N, M>?
---
Размеры матриц делают параметрами шаблона, а согласованность размеров контролируется типами.
```cpp
template<size_t N, size_t M, size_t K>
Matrix<N, K> operator*(const Matrix<N, M>& a, const Matrix<M, K>& b);
```
Подвох: если внутренние размеры не совпадают, вывод `M` противоречив и вызов не компилируется (ошибка на этапе компиляции, а не в рантайме).
См.: language/function_template, language/template_parameters

## cpp-c-0218 · cpp-t-022
Что такое виртуальная функция?
---
Нестатическая функция-член, объявленная с `virtual`: при вызове через ссылку или указатель на базу выполняется замещающая функция (final overrider) по динамическому типу объекта.
```cpp
struct B { virtual void f() { std::puts("B"); } };
struct D : B { void f() override { std::puts("D"); } };
D d; B& r = d; r.f(); // D
```
Подвох: диспетчеризации нет при квалифицированном вызове `r.B::f()` и при вызове из конструктора и деструктора (берётся версия строящегося класса); у переопределения `virtual` писать необязательно.
См.: language/virtual

## cpp-c-0219 · cpp-t-022
Что означает override у метода наследника?
---
Спецификатор требует, чтобы функция переопределяла виртуальную функцию базы; иначе ошибка компиляции.
```cpp
struct B { virtual void f() const; };
struct D : B { void f() override; }; // ошибка: нет const
```
Подвох: без `override` функция с чуть другой сигнатурой (иной `const`, параметр) молча становится новой функцией, скрывающей базовую, а не переопределением. `override` — контекстное слово, а не зарезервированное.
См.: language/override, language/virtual

## cpp-c-0220 · cpp-t-022
Что называют полиморфным классом в C++?
---
Класс, который объявляет или наследует хотя бы одну виртуальную функцию.
Подвох: виртуальный деструктор тоже делает класс полиморфным; именно для таких типов работают `dynamic_cast` из указателя на базу и `typeid` по динамическому типу.
См.: language/virtual, language/dynamic_cast

## cpp-c-0251 · cpp-t-022
Что делает final и где применяется?
---
`final` у виртуальной функции запрещает её дальнейшее переопределение, у класса — запрещает от него наследоваться.
```cpp
struct B { virtual void f(); };
struct D final : B { void f() final; };
```
Подвох: `final` у невиртуальной функции — ошибка; это контекстное слово, вне объявления функции и заголовка класса его можно использовать как имя.
См.: language/final

## cpp-c-0221 · cpp-t-023
Что такое чисто виртуальная функция?
---
Виртуальная функция с `= 0` в объявлении: `virtual void f() = 0;`. Она делает класс абстрактным и должна быть переопределена в конкретном наследнике.
Подвох: у неё всё же может быть определение (вне класса), доступное через `B::f()`; чисто виртуальный деструктор обязан иметь определение, иначе ошибка линковки.
См.: language/abstract_class

## cpp-c-0222 · cpp-t-023
Что такое абстрактный класс?
---
Класс, который определяет или наследует функцию, чей final overrider — чисто виртуальная. Объект такого типа создать нельзя (кроме подобъекта базы), поле такого типа тоже нельзя, но указатели и ссылки допустимы.
Подвох: абстрактный тип нельзя использовать как тип параметра или результата функции; виртуальный вызов чисто виртуальной функции из конструктора или деструктора — UB.
См.: language/abstract_class

## cpp-c-0223 · cpp-t-023
Зачем базовому классу виртуальный деструктор?
---
Чтобы `delete` производного объекта через указатель на базу вызвал деструктор производного класса, а затем базового.
```cpp
struct B { virtual ~B() = default; };
struct D : B { int* p = new int; ~D() { delete p; } };
B* b = new D; delete b; // ~D, затем ~B
```
Подвох: без `virtual` такое удаление — UB (обычно не вызывается `~D`, утечка ресурсов).
См.: language/destructor, language/virtual

## cpp-c-0252 · cpp-t-023
Что происходит, если приватность виртуальной функции в базе и в наследнике различается?
---
Права доступа проверяются по статическому типу в месте вызова, а не по типу переопределения; переопределить можно и приватную виртуальную функцию.
```cpp
struct B { virtual void f() {} };
struct D : B { private: void f() override {} };
D d; B& r = d; r.f(); // OK
// d.f();             // ошибка: приватна
```
Подвох: на этом основан NVI: публичный невиртуальный метод вызывает приватный виртуальный.
См.: language/virtual, language/access

## cpp-c-0224 · cpp-t-024
Для чего применяют исключения?
---
Они отделяют обнаружение ошибки от её обработки: `throw` переносит управление вверх по стеку вызовов к подходящему `catch`, а промежуточный код не проверяет коды возврата.
```cpp
try { std::vector<int> v(3); v.at(5); }
catch (const std::out_of_range&) { /* обработка */ }
```
Подвох: ошибку-код можно проигнорировать, исключение — нет (необработанное завершит программу через `std::terminate`); для обычного потока управления исключения не предназначены.
См.: language/exceptions

## cpp-c-0225 · cpp-t-024
Что делают throw и try...catch?
---
`throw expr` создаёт объект исключения (копия `expr`) и начинает поиск обработчика; `catch (T)` блока `try` принимает исключение, если тип тот же или однозначная публичная база (`catch (...)` ловит всё).
```cpp
try { throw std::runtime_error("x"); }
catch (const std::exception& e) { std::puts(e.what()); }
```
Подвох: ловить нужно по `const&` (иначе копирование и срезка); обработчики проверяются по порядку, производный ставят перед базовым, `catch (...)` — только последним; `throw;` перебрасывает то же исключение.
См.: language/throw, language/catch

## cpp-c-0226 · cpp-t-024
Что такое сворачивание стека при исключении?
---
Это уничтожение автоматических объектов выходящих из области видимости (в порядке, обратном созданию) при передаче управления от `throw` к обработчику.
Подвох: если подходящего обработчика нет, вызывается `std::terminate`, и раскрутка стека может вообще не произойти (определяется реализацией); исключение, вышедшее из деструктора при раскрутке, тоже ведёт к `terminate`.
См.: language/throw, error/terminate

## cpp-c-0253 · cpp-t-024
Когда вызывается std::terminate?
---
Среди случаев: исключение не поймано; нарушена спецификация `noexcept`; исключение вышло из функции, вызванной при обработке исключения (например, из деструктора при раскрутке); `throw;` без обрабатываемого исключения; уничтожен joinable `std::thread`. `terminate` вызывает текущий `terminate_handler`, по умолчанию — `std::abort`.
Подвох: в случаях «не поймано» и `noexcept` раскрутка стека до `terminate` определяется реализацией.
См.: error/terminate

## cpp-c-0254 · cpp-t-024
Чем RE (runtime error) отличается от исключения? Примеры RE, не являющихся исключениями.
---
RE — аварийное завершение процесса (сигнал, ненулевой код, `abort`), которое фиксирует система; исключение — механизм C++, который можно поймать. Деление целого на ноль, разыменование нулевого указателя, выход за границы `operator[]`, бесконечная рекурсия — UB/сигнал, исключения не бросают.
Подвох: `v.at(i)` бросает `std::out_of_range`, а `v[i]` — нет; `std::runtime_error` — стандартный класс исключений, не связанный с вердиктом RE. [не по cppreference]
См.: error/exception, error/runtime_error

## cpp-c-0227 · cpp-t-025
В чём состоит идиома RAII?
---
Владение ресурсом привязывается к времени жизни объекта: ресурс получается в конструкторе, освобождается в деструкторе, поэтому освобождение происходит при любом выходе из области видимости, в том числе при исключении.
```cpp
{
    std::lock_guard<std::mutex> g(m);
    work();
} // m освобождён
```
Подвох: RAII-объект должен быть именованным (временный `lock_guard{m};` разрушится сразу); класс-владелец нужно защитить от копирования или определить правило трёх.
См.: language/raii

## cpp-c-0228 · cpp-t-025
Как RAII помогает избежать утечки ресурса при исключении?
---
При раскрутке стека вызываются деструкторы автоматических объектов, и владелец сам освобождает ресурс; с сырым `new`/`delete` управление до `delete` не дойдёт.
```cpp
void f() {
    auto p = std::make_unique<int[]>(100);
    g(); // бросит — память всё равно освободится
}
```
Подвох: гарантия действует, только если исключение где-то поймано; деструктор RAII-класса не должен бросать.
См.: language/raii, language/throw

## cpp-c-0229 · cpp-t-025
Чем отличаются std::unique_ptr и std::shared_ptr по владению?
---
`unique_ptr` — единоличное владение, не копируется, только перемещается; `shared_ptr` — разделяемое, ресурс удаляется, когда уничтожен последний владелец (счётчик в управляющем блоке).
```cpp
auto u = std::make_unique<int>(1);
auto u2 = std::move(u);  // u == nullptr
auto s = std::make_shared<int>(2);
auto s2 = s;             // s.use_count() == 2
```
Подвох: `unique_ptr<Base>` из `unique_ptr<Derived>` без виртуального деструктора — UB, а `shared_ptr<Base>` удалит объект корректно; циклы из `shared_ptr` дают утечку (нужен `weak_ptr`).
См.: memory/unique_ptr, memory/shared_ptr

## cpp-c-0255 · cpp-t-025
Можно ли использовать unique_ptr в контейнерах?
---
Да: он перемещаемый, поэтому подходит для `vector<unique_ptr<T>>`, но элементы добавляют только перемещением или конструированием на месте.
```cpp
std::vector<std::unique_ptr<int>> v;
v.push_back(std::make_unique<int>(1));
v.emplace_back(new int(2));
// auto w = v; // ошибка: копирование
```
Подвох: сам контейнер при этом становится move-only; инициализация через `initializer_list` не работает (элементы копируются).
См.: memory/unique_ptr

## cpp-c-0230 · cpp-t-026
Чем последовательные контейнеры отличаются от ассоциативных?
---
Последовательные (`array`, `vector`, `deque`, `list`, `forward_list`) хранят элементы в порядке вставки и доступны последовательно; ассоциативные отсортированы по ключу (`set`, `map`, поиск O(log n)); неупорядоченные ассоциативные (`unordered_*`, C++11) хешированы (O(1) в среднем, O(n) в худшем).
Подвох: `stack`, `queue`, `priority_queue` — не контейнеры, а адаптеры над последовательными; `map::operator[]` вставляет отсутствующий ключ.
См.: container

## cpp-c-0231 · cpp-t-026
Каковы основные различия vector, deque и list?
---
`vector` — непрерывный массив: доступ O(1), `push_back` амортизированно O(1), вставка в середину O(n). `deque` — произвольный доступ O(1) и быстрая вставка с обоих концов, но не непрерывна. `list` — двусвязный список: вставка и удаление по итератору O(1), нет доступа по индексу.
Подвох: реаллокация `vector` инвалидирует итераторы и ссылки; вставка в `deque` инвалидирует итераторы, но не ссылки, если вставка на концах; в `list` итераторы инвалидируются только у удалённого элемента.
См.: container/vector, container/deque, container/list

## cpp-c-0232 · cpp-t-026
Какие контейнеры относятся к упорядоченным ассоциативным и к хеш-контейнерам?
---
`map`, `set`, `multimap`, `multiset` — упорядоченные (обычно красно-чёрное дерево), операции за O(log n). `unordered_map`, `unordered_set` и их multi-версии — хеш-таблицы, в среднем O(1).
Подвох: у `unordered_*` эквивалентные ключи должны давать равный хеш, итераторы — forward; у упорядоченных ключи сравниваются через `Compare`, а эквивалентность — `!comp(a,b) && !comp(b,a)`.
См.: container/map, container/unordered_map

## cpp-c-0256 · cpp-t-026
Что такое адаптеры stack, queue, priority_queue?
---
Это обёртки над последовательным контейнером (по умолчанию `deque`, у `priority_queue` — `vector`) с урезанным интерфейсом: `stack` — LIFO, `queue` — FIFO, `priority_queue` — доступ к наибольшему элементу за O(1), вставка и извлечение за O(log n).
```cpp
std::priority_queue<int> pq;
pq.push(3); pq.push(5);
int t = pq.top(); // 5; pop() за O(log n)
```
Подвох: `pop()` возвращает `void`, итераторов нет; для минимума в `top()` нужен `std::greater`.
См.: container/stack, container/queue, container/priority_queue

## cpp-c-0257 · cpp-t-026
Чем forward_list отличается от list?
---
`forward_list` — односвязный список: только прямой обход, нет `size()` и `push_back`, вставка идёт после заданной позиции (`insert_after`), меньше памяти на узел.
Подвох: вставка и удаление идут через `insert_after`/`erase_after` (нужен итератор на предыдущий элемент, для первого — `before_begin()`); итератор на удалённый элемент инвалидируется.
См.: container/forward_list

## cpp-c-0233 · cpp-t-027
Что такое итератор?
---
Объект, обобщающий указатель: указывает на элемент диапазона `[first, last)`, поддерживает разыменование `*it`, продвижение `++it` и сравнение; позволяет алгоритмам не зависеть от контейнера.
```cpp
std::vector<int> v{1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it) std::cout << *it;
```
Подвох: `end()` указывает за последний элемент и не разыменовывается; изменение контейнера может инвалидировать итераторы.
См.: iterator

## cpp-c-0234 · cpp-t-027
Какие основные категории итераторов выделяют в C++20?
---
Input, output, forward, bidirectional, random access и contiguous (формально с C++17; в C++20 им соответствуют концепты). Forward добавляет многопроходность, bidirectional — `--`, random access — произвольный доступ, contiguous — хранение подряд в памяти. Каждая следующая (кроме output) включает операции предыдущей.
Подвох: output стоит вне иерархии; от категории зависит сложность `std::advance` и `std::distance` (линейная, для random access — константная).
См.: iterator

## cpp-c-0258 · cpp-t-027
Какие категории итераторов у стандартных контейнеров?
---
`vector`, `array`, `string` — contiguous; `deque` — random access; `list`, `map`, `set` (и multi-версии) — bidirectional; `forward_list`, `unordered_*` — forward.
Подвох: итераторы `set`/`map` — bidirectional, но не random access, поэтому `it + 5` не работает; для `std::set` нет `std::sort`.
См.: container, iterator

## cpp-c-0235 · cpp-t-027
Как работает range-based for на уровне идеи?
---
Цикл `for (decl : range)` берёт `begin()` и `end()` диапазона (или одноимённые функции) и итерируется, присваивая переменной `*it`.
```cpp
// for (auto&& x : v) body
// эквивалентно примерно:
// { auto&& r = v; for (auto b = r.begin(), e = r.end(); b != e; ++b) { auto&& x = *b; body } }
```
Подвох: `for (auto x : v)` копирует элементы, для изменения нужен `auto&`; временный объект в `range-initializer` живёт до конца цикла, но временные внутри него до C++23 — нет (UB).
См.: language/range-for

## cpp-c-0259 · cpp-t-027
Какие алгоритмы неприменимы к некоторым контейнерам из-за категории итераторов?

`std::sort` требует random access, поэтому к `list` и `forward_list` неприменим (у `list` есть метод `sort`); `std::reverse` требует bidirectional, `std::find` — достаточно input.

std::list<int> l{3, 1, 2};

## cpp-c-0236 · cpp-t-028
Какую проблему решает move-семантика?
---
Позволяет не копировать ресурсы временного или более не нужного объекта, а передать их (указатели и т. п.) новому объекту за O(1).
```cpp
std::string a(1000, 'x');

```
Подвох: после перемещения исходный объект в корректном, но неуказанном состоянии — его можно разрушить или присвоить, но не полагаться на значение.

## cpp-c-0237 · cpp-t-028
Что делает std::move?
---
Приводит выражение к rvalue (xvalue), то есть эквивалентно `static_cast<T&&>`; сам ничего не перемещает, а лишь позволяет выбрать перегрузку для rvalue (move-конструктор, move-присваивание).
```cpp
const std::string s = "abc";
std::string t = std::move(s); // копия: const T&& не привязывается к T&&
```
Подвох: от `const`-объекта получится копирование; имя rvalue-ссылки — lvalue, поэтому в move-конструкторе поле перемещают явно: `member(std::move(arg.member))`.
См.: utility/move

## cpp-c-0238 · cpp-t-028
Чем emplace_back отличается от push_back?
---
`emplace_back(args...)` строит элемент прямо в контейнере, передавая аргументы конструктору; `push_back` принимает уже готовый объект (копию или `&&`).
```cpp
std::vector<std::pair<int, int>> v;
v.push_back({1, 2});   // временный pair, затем перемещение
v.emplace_back(1, 2);  // конструируется на месте
```
Подвох: с C++17 возвращает ссылку на новый элемент; при реаллокации старые элементы перемещаются или копируются (нужен `MoveInsertable`), и все итераторы инвалидируются.
См.: container/vector/emplace_back

## cpp-c-0260 · cpp-t-028
Когда компилятор генерирует move-операции, и что такое правило пяти?
---
Неявный move-конструктор объявляется, только если нет пользовательских копи-конструктора, копирующего и move-присваивания и деструктора; аналогично для move-присваивания. Правило пяти: если нужна одна из пяти операций (деструктор, копирующие и перемещающие конструктор и присваивание), продумайте все пять.

## cpp-c-0239 · cpp-t-029
Что делает auto при объявлении переменной?
---
Тип выводится из инициализатора по правилам вывода аргументов шаблона: ссылка и верхнеуровневые `const`/`volatile` отбрасываются.

const int c = 1;

## cpp-c-0240 · cpp-t-029
Как различаются auto, auto& и const auto& при выводе типа?
---
`auto` — копия без ссылки и верхнего `const`; `auto&` — ссылка на объект, сохраняет его константность; `const auto&` — константная ссылка.
```cpp
std::vector<int> v{1, 2};
auto a = v[0];        // int, копия
auto& b = v[0];       // int&
const auto& c = v[0]; // const int&
```
Подвох: `auto&` не привязывается к rvalue, `const auto&` привязывается и продлевает жизнь временному; `auto&&` — универсальная ссылка.
См.: language/auto

## cpp-c-0262 · cpp-t-029
Что такое trailing return type и auto в возвращаемом типе?
---
`auto f(...) -> T` задаёт тип результата после списка параметров, так он может зависеть от параметров. С C++14 можно писать просто `auto f()`, тогда тип выводится из `return`.
```cpp
template<class T, class U>
auto add(T a, U b) -> decltype(a + b) { return a + b; }
auto sq(int x) { return x * x; } // C++14
```
Подвох: все `return` обязаны давать один тип; `auto` отбрасывает ссылку (нужен `decltype(auto)`); определение функции должно быть видно до использования.
См.: language/function, language/auto

## cpp-c-0263 · cpp-t-029
Можно ли использовать auto в параметрах функций?
---
С C++20 да: `void f(auto x)` — сокращённый шаблон функции, каждый `auto` становится отдельным параметром шаблона.
```cpp
void print(auto x) { std::cout << x; }
print(1); print("a");
```
Подвох: у `f(auto a, auto b)` типы параметров независимы; в лямбдах `auto` в параметрах разрешён уже с C++14.
См.: language/function_template, language/lambda

## cpp-c-0241 · cpp-t-030
Что такое лямбда-выражение?
---
Выражение, создающее безымянный объект-замыкание с `operator()`; позволяет описать функцию прямо в месте использования.
```cpp
std::vector<int> v{3, 1, 2};
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
```
Подвох: тип замыкания уникален и безымянен (хранят через `auto` или `std::function`); лямбда без захвата неявно приводится к указателю на функцию.
См.: language/lambda

## cpp-c-0242 · cpp-t-030
Что задаёт список захвата лямбда-функции?
---
Какие внешние переменные доступны в теле и как: `[x]` — по значению (копия), `[&x]` — по ссылке, `[=]`/`[&]` — по умолчанию все используемые, `[this]`, `[*this]` (C++17), `[y = expr]` (C++14).
```cpp
int x = 1, y = 2;
auto f = [x, &y] { return x + y; };
```
Подвох: захват по ссылке даёт висячую ссылку, если замыкание переживёт переменную; `[=]` и `[&]` захватывают `*this` по ссылке (неявный захват `this` при `[=]` с C++20 устарел), `[*this]` копирует объект.
См.: language/lambda

## cpp-c-0243 · cpp-t-030
Можно ли менять захваченную по значению переменную внутри лямбды?
---
По умолчанию нет: `operator()` у замыкания `const`. С `mutable` менять можно, но только собственную копию внутри замыкания.
```cpp
int n = 0;
auto f = [n]() mutable { return ++n; };
f(); f(); // внутренняя копия 2, внешний n == 0
```
Подвох: захваченную по ссылке можно менять и без `mutable`; копия замыкания получает отдельную копию состояния.
См.: language/lambda

## cpp-c-0264 · cpp-t-030
Что такое немедленный вызов лямбды (immediate invocation)?
---
Лямбда вызывается сразу в месте создания: `[]{ ... }()`.
```cpp
const int v = [] {
    int s = 0;
    for (int i = 1; i <= 3; ++i) s += i;
    return s;
}(); // v == 6
```
Подвох: приём нужен, чтобы инициализировать `const` или `constexpr` переменную сложной логикой; если забыть круглые скобки в конце, получится ошибка компиляции (замыкание не преобразуется в `int`); с `auto v` в `v` молча попало бы само замыкание.
См.: language/lambda

## cpp-c-0265 · cpp-t-030
Можно ли узнать «настоящий» тип замыкания?
---
Назвать его нельзя: у каждой лямбды свой уникальный безымянный тип. Получить его можно через `auto` и `decltype`, а для хранения с общим типом — `std::function` или шаблонный параметр.
```cpp
auto f = [] {};
decltype(f) g = f; // тот же тип
```
Подвох: две лямбды с идентичным текстом имеют разные типы; `std::function` стирает тип ценой возможной динамической аллокации.
См.: language/lambda
