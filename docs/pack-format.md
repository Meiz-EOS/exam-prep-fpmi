# Формат пакета

Пакет — это папка с одним курсом: предметы, экзамены, задания, билеты, тесты, карточки, теория. Приложение собирает её в одну страницу. Все файлы — обычный текст (YAML и Markdown), правятся в любом редакторе.

Проверить пакет: `npm run check:pack` (подробнее — в конце). Точные правила — в схемах [`engine/src/content/schema.ts`](../engine/src/content/schema.ts); если здесь и там расходится, верна схема.

## Раскладка папок

```
packs/<имя-пакета>/
  pack.yaml                  обязательно: название, предметы, экзамены, пороги
  items/<предмет>.yaml       задания и сдачи предмета
  tickets/<предмет>.yaml     билеты (темы, которые надо знать)
  tickets/<предмет>.remap.yaml   старые id билетов → новые (если переименовали)
  exam/<предмет>.yaml        экзаменационные билеты: из каких билетов состоят
  tests/<предмет>/*.md       тесты с вопросами и эталонами
  cards/<предмет>/*.md       карточки вопрос/ответ (для Anki)
  theory/<предмет>/*.md      теория: формулировка, скелет доказательства
```

Обязателен только `pack.yaml`. Остальные папки можно не заводить: пакет с одними `items/` — нормальный пакет. Вопросы тестов, карточки и теория ссылаются на билеты, поэтому вместе с `tests/`, `cards/`, `theory/` обычно нужна и `tickets/`.

`<предмет>` — это id предмета из `pack.yaml`. Имя файла (или папки) должно совпадать с ним: `items/algebra.yaml` — для предмета `id: algebra`. Файл про предмет, которого нет в `pack.yaml`, — ошибка.

Личное (заметки со ссылками, настройки синхронизации) в пакет не кладётся: оно живёт в папке данных рядом с репозиторием и в сборку не попадает.

## Правила id

- Допустимы строчные латинские буквы, цифры, точка и дефис; первый символ — буква или цифра: `alg-hw3-07`, `alg.t.12`. Пробелы, заглавные и русские буквы нельзя.
- **Id уникален во всём пакете**: один и тот же id у задания, билета, теста, вопроса или карточки — ошибка, даже если они в разных файлах.
- Id — это ключ прогресса: переименовав id, вы теряете отметки по нему. Билет всё же можно переименовать, записав старый id в `.remap.yaml` (см. ниже).
- Удобно начинать id с префикса предмета (`alg-…`): так проще не промахнуться.

## `pack.yaml`

```yaml
id: demo-2026w
title: Зимняя сессия
subjects:
  - { id: algebra, name: Алгебра }
  - { id: analysis, name: Анализ }
exams:
  - { id: ex-algebra, subject: algebra, title: Экзамен по алгебре, date: "2026-12-26" }
thresholds:                       # необязательно
  ud: { L0: 0.95, L1: 0.5 }
  hor: { L0: 1.0, L1: 0.85, L2: 0.5, keyL2: true }
```

Все поля `id`, `title`, `subjects`, `exams` обязательны (`exams: []` — если экзаменов пока нет). Дата — строго `ГГГГ-ММ-ДД` и существующая (30 февраля нельзя). Лишних полей быть не должно: опечатка в имени поля — ошибка. `thresholds` — пороги готовности для экрана «готовность»; если их нет, пороги не применяются.

## `items/<предмет>.yaml` — задания

Список групп; у группы есть общее (`kind`), у пункта — свои поля.

```yaml
- group: Задание 3 · неделя 1
  kind: дз-задача
  items:
    - { id: alg-hw3-01, title: "№ 1.4" }
    - { id: alg-hw3-02, title: "№ 1.9", star: true }
- group: Задание 3
  items:
    - { id: alg-hw3-submit, kind: дз, title: "Сдать задание 3", soft: "2026-11-10", hard: "2026-11-16", note: "до 17:00" }
```

- Обязательны `group` у группы и `id`, `title` у пункта.
- `kind` — у группы или у пункта (у пункта главнее). Допустимо: `дз`, `дз-задача`, `теордз`, `контест`, `задача-cpp`, `устная`, `кр`, `экзамен`. Если вид не указан нигде — ошибка.
- `soft` — желательный срок, `hard` — жёсткий; даты `ГГГГ-ММ-ДД`, `soft` не позже `hard`. Необязательны.
- `star: true` — задача со звёздочкой; `note` — короткая пометка. Необязательны.
- Порядок пунктов в файле — порядок на странице.

## `tickets/<предмет>.yaml` — билеты

```yaml
provisional: true        # необязательно: список билетов ещё не утверждён
tickets:
  - { id: alg-t-01, title: "Определение группы", src: "conspect.tex:10-40" }
  - { id: alg-t-02, title: "Теорема Лагранжа", key: true }
  - { id: alg-t-03, title: "Простое определение", maxLevel: L1 }
```

- Обязательны `id` и `title`.
- `src` — откуда взято (свободная строка), `key: true` — ключевой билет, `maxLevel` — `L0`, `L1` или `L2`: выше какого уровня глубины от билета не требуют. Ключевой билет (`key: true`) не может иметь `maxLevel` ниже `L2`.

### `tickets/<предмет>.remap.yaml` — переименования

```yaml
alg-old-5: alg-t-02
```

Слева старый id (его в пакете больше нет), справа текущий билет этого же предмета. Нужен, чтобы прогресс по старому id не пропал.

## `exam/<предмет>.yaml` — экзаменационные билеты

```yaml
tickets:
  - { id: ex-alg-1, title: "Билет 1", confidence: sure, includes: [alg-t-01, alg-t-02] }
```

- Все четыре поля обязательны. `confidence` — насколько вы уверены, что такой билет будет: `sure`, `likely`, `ours`, `doubtful`.
- `includes` — id билетов из `tickets/` того же предмета; один билет входит не более чем в один экзаменационный билет.

## `tests/<предмет>/*.md` — тесты

Файл начинается с заголовка между строками `---`, дальше вопросы; каждый вопрос — раздел `## <id вопроса>`.

````markdown
---
id: alg-entry
title: Входной тест
kind: entry
minutes: 30
---
## alg-q-001
ticket: alg-t-01 · level: L0
Дайте определение группы.

### Эталон
- множество с операцией
- ассоциативность
- нейтральный элемент и обратные
````

- Заголовок: `id`, `title`, `kind`, `minutes` обязательны. `kind` — `entry`, `retest`, `mock`, `ticket` или `topic`.
- `kind: ticket` требует `exam: <id экзаменационного билета>`; `kind: topic` требует `covers: [<id билетов>]`. Для других видов эти поля писать нельзя.
- `level: L2` допустим только для `ticket` и `topic` (тесты уровня доказательств).
- `reuse: [<id вопросов>]` — взять готовые вопросы из других тестов того же предмета.
- Вопрос: после заголовка строка `ticket: <id билета> · level: <L0|L1|L2>`, затем условие, затем раздел `### Эталон` — маркированный список из 2–6 пунктов (что должно быть в хорошем ответе).
- Заголовки `##` внутри блоков кода (между ``` ) за вопросы не считаются.

## `cards/<предмет>/*.md` — карточки

````markdown
---
deck: Группы
tickets: [alg-t-01]
---
## alg-c-1
Что такое группа?
---
Множество с ассоциативной операцией, нейтральным элементом и обратными.

## alg-c-2 · alg-t-01, alg-t-02
Ещё вопрос?
---
Ответ.
````

- В заголовке `deck` обязателен, `tickets` — билеты по умолчанию для всех карточек файла.
- Карточка: `## <id>`, вопрос, строка из трёх дефисов `---`, ответ. После id можно через `·` перечислить билеты именно этой карточки — они заменяют `tickets` из заголовка.
- Вопрос и ответ не пустые; билеты существуют и принадлежат этому же предмету.

## `theory/<предмет>/*.md` — теория

````markdown
## alg-t-01
### Формулировка
Группа — это множество $G$ с операцией, для которой выполнены аксиомы.
### Скелет
1. Проверить ассоциативность.
2. Найти нейтральный элемент.
3. Построить обратные.
### Опирается на
alg-t-02
````

- Раздел на билет: `## <id билета>`; билет должен быть в `tickets/` этого же предмета, запись для него — одна.
- `### Формулировка` обязательна. `### Скелет` — нумерованный список из 3–5 шагов (необязателен). `### Опирается на` — id билетов через запятую (необязателен, тот же предмет).

## Проверка: `npm run check:pack`

```
npm run check:pack                    # пакет из zachetka.local.json
npm run check:pack packs/demo-2026w   # конкретная папка
```

Команда читает весь пакет и печатает **все** ошибки сразу, по одной в строке, в виде `файл:строка: что не так`:

```
packs/demo-2026w/items/algebra.yaml:12: поле "soft" — нужна дата ГГГГ-ММ-ДД, получено "15 ноября" (задача alg-hw3-07)
packs/demo-2026w/cards/algebra/groups.md:10: карточка "alg-c-2" ссылается на неизвестный тикет "alg-t-404"
```

Если ошибок нет — одна строка `ok: <путь> (…сколько чего…)`, код выхода 0; при ошибках код выхода 1. Исправьте то, что названо, и запустите снова: одна ошибка в файле иногда прячет другие (например, из файла с неверной схемой не проверяются сроки), а одна ошибка в списке билетов может породить лишние «неизвестный тикет» — их стоит перепроверить после правки первых. Та же проверка выполняется при сборке страницы и в тестах.
