# 13. Доступ одногруппникам: публичный репо и форки

Версия: 0.1 · 2026-11-12 · Статус: **согласовано** 12.11 (решения по вопросам — [ниже](#questions)). Основа: [roadmap](../roadmap.md) E-10, M-6; [functional-spec](../functional-spec.md) Н-6, не-цели §2; [07-standalone.md](07-standalone.md) Р-29; [11-apk.md](11-apk.md) Р-61…Р-64; [12-sync.md](12-sync.md).

Решения пользователя 12.11 (опрос): каждый одногруппник **форкает** репо и ведёт свою копию, общего экземпляра и общего прогресса нет; 2–5 человек, знают git; ПК (клон + локальный сервер) и APK; APK собирает **GitHub Actions форка** (пакет вшит, ключ в Secrets, APK в Releases); репо **публичный**, пакет `igor-2026w` остаётся с пометкой группы, но **без прогресса** автора; контент без Claude — руками + валидатор с понятными ошибками + готовый промпт для любой LLM; обновления движка — релизы с тегами и CHANGELOG; лицензия — сначала AGPL-3.0, затем **MIT** (вопрос 4); Anki — готовая колода `.apkg` от автора.

## Р-69. Новый публичный репо вместо переписывания истории {#repo}

- Публичный репо `Meiz-EOS/exam-prep-fpmi` создаётся **заново**: одно стартовое дерево (после Р-70…Р-72) одним коммитом без истории. Текущий `Meiz-EOS/zachetka` остаётся приватным и архивируется (история, ветки `task/*` и `debt/*` сохраняются там).
- Почему не `git filter-repo` + сделать текущий репо публичным: после force-push GitHub ещё держит старые коммиты доступными по SHA и через ссылки PR (убрать — только через поддержку GitHub); в истории ~20 веток, тексты коммитов и автор с личной почтой — проверить их всё целиком нереально. Новый репо этих объектов никогда не получает.
- Автор коммитов в публичном репо — адрес `…@users.noreply.github.com`, не личная почта (`git config user.email` в клоне).
- Автор после выкладки работает **из клона публичного репо**, как все; его личное — в папке данных (Р-70). Основная ветка публичного репо — `main`; `dev` и `task/*` — как раньше (правило 1 [README](README.md)).

## Р-70. Личное — в папку данных, не в репо {#private}

- `packs/<пакет>/private/` и `packs/<пакет>/sync.yaml` переезжают в папку данных: `<dataDir>/<пакет>/private/`, `<dataDir>/<пакет>/sync.yaml` (у автора это `zachetka-data` — отдельный приватный git, Р-29). В `.gitignore`: `packs/*/private/`, `packs/*/sync.yaml`.
- Читатели — по новому пути: агент (`private/notes.yaml`), `tools/sync/sync.ts` (нет `sync.yaml` → синхронизация молча выключена, строка в журнале). `main.tsx` больше не импортирует `v0-seed.json` (перенос с v0 давно сделан, W5).
- Р-11 (private/ не попадает в страницу) остаётся в силе, меняется только место.
- Тесты, которые читают `private/`, переходят на фикстуру `engine/tests/fixtures/pack-valid/private/`.

## Р-71. Локальные настройки — нетрекаемый файл {#settings}

- `zachetka.local.json` в корне клона, в `.gitignore`; образец `zachetka.local.example.json` в репо:
  ```json
  { "pack": "packs/igor-2026w", "dataDir": "../zachetka-data", "androidDir": "../android" }
  ```
- Порядок для каждого значения: переменная окружения (`ZACH_PACK`, `ZACHETKA_DATA`, `ZACH_ANDROID` — как сейчас) → `zachetka.local.json` → значение по умолчанию (пакет — единственный в `packs/`, иначе ошибка с подсказкой; данные — `../zachetka-data` рядом с клоном). Один модуль `tools/lib/settings.ts`, его читают `vite.config.ts`, `server.ts`, `sync.ts`, `today.ts`, `diff.ts`, `dump-pack.ts`, `tools/apk/env.sh` (через `node`).
- Абсолютных путей автора в коде не остаётся. У автора свой `zachetka.local.json` с абсолютными путями — работа не меняется.
- Итог: `git pull upstream main` в форке не конфликтует из-за настроек.

## Р-72. Чистка контента и документов (Н-6) {#scrub}

- `functional-spec.md`: «<имя> (МФТИ, ФПМИ, Б05-618)» → «студент группы Б05-618 (МФТИ, ФПМИ)» без имени; URL страниц claude.ai, отпечаток ключа, id сообщений Telegram — убрать из `docs/`.
- `packs/igor-2026w/items/*.yaml`: личные заметки о собственных сдачах убрать; общие сведения курса (сроки, условия, «обязательно для зачёта») оставить. Пометка группы — в `pack.yaml`: `title: "Зимняя сессия 2026/27, Б05-618"`.
- `docs/architecture/tasks/` (≈110 карточек прошлых волн, в них пути и подробности работы автора): в публичный репо **не выкладываются**, остаются в архиве приватного; в публичном — только `tasks/README.md` с текущими волнами. Документы `01…13` и ADR выкладываются после чистки.
- Последний шаг перед выкладкой — проверка дерева: `tools/release/audit.sh` (grep по списку из [аудита](#audit): логины, ID таблиц, адреса страниц claude.ai, абсолютные пути, фамилия, почта) — пусто, иначе выкладка останавливается. Общие шаблоны (абсолютные пути, адреса claude.ai, ID таблиц, почта, ссылки Telegram) — `tools/release/patterns.txt` в репо; личные (логины, фамилия, ID) — `<dataDir>/release/audit-patterns.txt`, вне репо. Что не публикуется — `tools/release/exclude.txt`. Тот же скрипт — в CI публичного репо на каждый push (там только общие шаблоны, `.github/workflows/audit.yml`).
- Дерево для публичного репо собирает `node tools/release/export.ts OUT` (W12-08): `git archive HEAD` → без путей из `exclude.txt` → `tasks/README.md` только с текущей волной → ссылки на невыложенные файлы становятся текстом, любая другая битая относительная ссылка — ошибка → `audit.sh OUT` пуст. `OUT` — не на NTFS (иначе `git init` там теряет +x у скриптов). Коммит и тег в новом репо — от нейтрального имени и адреса `…@users.noreply.github.com`, не от личной почты.

## Р-73. APK в GitHub Actions форка {#ci-apk}

- `.github/workflows/apk.yml`: запуск по тегу `v*` и вручную; JDK 21 (`actions/setup-java`), Android SDK 36 (`android-actions/setup-android`), `npm ci`, `npm test`, `npm run build:apk`; APK прикладывается к GitHub Release тега.
- Ключ: каждый одногруппник создаёт **свой** keystore один раз (инструкция с `keytool`) и кладёт в Secrets форка: `ZACH_KEYSTORE_B64`, `ZACH_KEYSTORE_PASSWORD`, `ZACH_KEY_ALIAS`, `ZACH_KEY_PASSWORD`. Workflow раскодирует в файл и выставляет переменные, которые уже читает `build.gradle` (Р-62). Без Secrets workflow падает с понятным сообщением, а не собирает неподписанный APK.
- `appId` у всех `app.zachetka` (Р-62): у каждого своё устройство, ставит только свой APK; обновление поверх работает, пока ключ тот же. **Потерянный ключ = переустановка с потерей прогресса на телефоне** — в инструкции: сохранить keystore у себя (Telegram «Избранное» и т. п.).
- Пакет вшивается из `ZACH_PACK` (переменная репо `vars.ZACH_PACK`, по умолчанию — единственный пакет).
- Локальная сборка `npm run build:apk` остаётся (автор собирает так же, как раньше).

## Р-74. Формат пакета и валидатор с понятными ошибками {#format}

- `docs/pack-format.md` — для человека, не для агента: раскладка папок, каждый файл с минимальным примером, правила id, что обязательно; ссылки на схемы `zod`.
- `npm run check:pack [путь]`: ошибки в виде `packs/x/items/aig.yaml:12: поле "due" — нужна дата ГГГГ-ММ-ДД, получено "15 ноября"` (файл, строка из `yaml` CST, человеческий текст по коду ошибки `zod`), все ошибки сразу, код выхода 1. Сейчас проверка пакета живёт в тестах (`pack-*.test.ts`) — она остаётся, но сообщения берёт из того же модуля.

## Р-75. Промпт для любой LLM {#prompt}

- `docs/pack-prompt.md`: готовый текст «вот формат пакета, вот мой материал (программа экзамена, конспект, список заданий) — выдай файлы `tickets/`, `cards/`, `tests/`, `items/`»; в конце — «проверь: `npm run check:pack`». Включает сжатый `pack-format.md` и один образец каждого файла из `igor-2026w`.
- Не зависит от Claude: проверяется ручным прогоном в одной сторонней модели на материале одного предмета (результат — проходит `check:pack` с ≤ 3 правками руками).

## Р-76. Релизы и CHANGELOG {#releases}

- Теги `vMAJOR.MINOR.PATCH` на `main`; первый публичный — `v1.0.0`. MINOR — новые возможности, PATCH — исправления, MAJOR — **несовместимое изменение формата пакета или прогресса**.
- `CHANGELOG.md` (по выпускам, сверху новые); у выпуска с изменением формата — раздел «Миграция пакета» с точными шагами (или скриптом `tools/migrate/…`). Прошлые v1…v10 сводятся в одну запись «до v1.0.0».
- Форк обновляется: `git fetch upstream && git merge upstream/main` → `npm ci` → `npm run check:pack` → новый тег в форке → CI собирает APK.

## Р-77. Колода `.apkg` в релизе {#apkg}

- Автор собирает колоду из `igor-2026w` существующим `tools/anki` (Р-14, GUID = хеш(пакет:id) — повторный импорт обновляет карточки, а не дублирует) и прикладывает `zachetka-igor-2026w-<версия>.apkg` к релизу вручную (CI для Python/`genanki` не делается — 2–5 человек).
- Одногруппники только импортируют; история Anki у каждого своя, агентских функций по ней у них нет.

## Р-78. Лицензия и вход для одногруппника {#license}

- `LICENSE` — MIT, `"license": "MIT"` в `package.json`. Контент пакета — под той же лицензией (одна на репо).
- `README.md` переписывается для одногруппника: что это, форк → клон → `npm ci` → `zachetka.local.json` → `npm start`; APK — Secrets → тег; где формат и промпт; как обновляться. Части, нужные только агенту автора (Claude, `diff.ts`, `today.ts`, синхронизация из таблиц), — отдельным разделом «необязательно».

## Р-79. Что не делается {#non-goals}

- Общий экземпляр, общий прогресс, обмен прогрессом между одногруппниками.
- Сборка APK за других, раздача чужих ключей.
- Поддержка Windows/macOS для `npm start` (`open.sh` — Linux; на других системах — `npm run serve` (добавлена в W12-01) и открыть адрес руками).
- Автосинхронизация статусов (Р-66) для других: `sync.yaml` у каждого свой и необязателен; в документации — как завести.

## Решения по вопросам (12.11) {#questions}

1. **Новый публичный репо** с чистой историей — `Meiz-EOS/exam-prep-fpmi`. Приватный `Meiz-EOS/zachetka` остаётся под своим именем и архивируется. Приложение внутри по-прежнему «Зачётка».
2. Одногруппники работают **прямо в `packs/igor-2026w`**, обновления контента — через `merge upstream`. Имя пакета не меняется (GUID в Anki, Р-13).
3. Карточки `docs/architecture/tasks/` в публичный репо **не выкладываются**.
4. Лицензия — **MIT** на весь репо, включая контент (вместо AGPL-3.0 из опроса: проще, снимает вопрос «можно ли»; без лицензии форки формально запрещены).
5. Коммиты — **честно**: участие ИИ указывается трейлером `Co-Authored-By`. Правило 5 [README](README.md) обновлено.
6. Группа **Б05-618** указывается в пакете и README.
