# 07. Своя версия для ПК: уход с claude.ai

Версия: 0.1 · 2026-11-09 · Статус: **согласовано** 09.11. Основа: [roadmap](../roadmap.md) ГЗ-13, ГЗ-17, E-9; [functional-spec](../functional-spec.md) Н-7, Н-8, А-1; [01-overview.md#adapters](01-overview.md#adapters); [ADR-0002](../adr/0002-data-delivery-and-validation.md).

Решения пользователя 09.11: версия для ПК — **локальный сервер из репозитория**, APK потом на **Capacitor**; волна W5 — **только ПК**; страница claude.ai после переноса **замораживается** (только просмотр); PWA на ПК **не нужен** (обычная вкладка); прогресс — в **отдельном git-репозитории**, коммитит агент в начале и в конце сессии; запуск — **ярлык, который сразу открывает вкладку**.

Что не меняется: курс-пакет и его формат, `core`, интерфейс страниц, Anki, форматы документов прогресса (`items`, `attempts`, `meta`).

## Схема {#scheme}

```
ярлык «Зачётка» ─► tools/serve/open.sh ─► сервер жив? ── нет ─► запустить в фоне
                                               │
                                               ▼
                    браузер http://127.0.0.1:4317/  ◄── dist/local/index.html (пакет встроен, Р-2)
                                │  fetch /api/…
                                ▼
                    tools/serve/server.ts (Node, без зависимостей)
                                │  чтение/запись по документу
                                ▼
          ../zachetka-data/igor-2026w/{items,attempts,meta}/<id>.json   (свой git)
                                ▲
              агент: Read/diff.ts/today.ts напрямую, git commit в начале и конце сессии
```

## Р-28. Форма версии для ПК {#form}

Локальный HTTP-сервер `tools/serve/server.ts` на встроенном `node:http` (новых зависимостей нет). Слушает **только `127.0.0.1`**, порт **4317** (8765 занят AnkiConnect/разметчиком Elixir). Отдаёт статику из `dist/local/` и API прогресса ([#api](#api)). Страницу читает с диска на каждый запрос — новая сборка видна после перезагрузки вкладки, без перезапуска сервера.

APK (следующая волна) — Capacitor поверх той же веб-сборки со своим адаптером хранения; сервер в APK не переносится.

## Р-29. Где лежит прогресс {#data-dir}

Папка данных — `../zachetka-data/<пакет>/`, отдельный git-репозиторий `../zachetka-data` (не часть репо кода; удалённого нет, пока пользователь не попросит). Путь задаётся `--data`, переменной `ZACHETKA_DATA` или `dataDir` в `zachetka.local.json` ([13-classmates.md#settings](13-classmates.md#settings)).

```
zachetka-data/
  igor-2026w/
    items/<id>.json       # тело документа, как в базе claude.ai, с updatedAt
    attempts/<id>.json
    meta/today.json
    private/              # личное для агента: notes.yaml, last-seen*.json (13-classmates.md#private)
    sync.yaml             # конфиг синхронизации статусов (12-sync.md), необязателен
```

**Один файл на документ** — тот же вид, что даёт `ArtifactData list … out_dir`, поэтому `tools/agent/diff.ts` (`readDocs`) читает папку без изменений; в git видны маленькие понятные изменения. Id документа — имя файла; допустимые символы `[A-Za-z0-9_-]`, иначе сервер отвечает 400 (защита от `../`).

**Запись атомарная:** во временный файл рядом → `rename`. Записи в один документ — строго по очереди (как `KeyedQueue` в адаптерах).

**Резервные копии = git.** Сервер ничего не коммитит. Агент делает `git -C ../zachetka-data add -A && git commit` в начале сессии (зафиксировать то, что студент наотмечал) и в конце (свои записи, например `meta/today`). Коммиты без упоминаний ИИ.

## Р-30. API сервера и адаптер `http` {#api}

| Запрос | Ответ |
|---|---|
| `GET /api/health` | `{ok: true, pack}` — для ярлыка |
| `GET /api/<col>` | `[{id, …тело}]` — все документы коллекции (`items`, `attempts`, `meta`) |
| `PATCH /api/<col>/<id>` | слить поля в документ (создать, если нет); сервер ставит `updatedAt` |
| `POST /api/<col>` | создать документ с новым id (`crypto.randomUUID`), ответ `{id}` |
| `DELETE /api/<col>/<id>` | удалить |

Другая коллекция → 404; неверный JSON или id → 400; ошибка диска → 500. Тело запроса — до 256 КиБ (как документ claude.ai).

**Слияние `PATCH`** — поверхностное, как `update` у `claude-db`: поля патча заменяют поля документа целиком; `null` сохраняется как значение (интерфейс так сбрасывает `override`, `core/merge.ts` читает `null` как «нет»); удаления поля нет.

**Защита:** запрос с заголовком `Host` не `127.0.0.1:<порт>` или `localhost:<порт>` → 403 (DNS rebinding); запись без `Content-Type: application/json` → 415 (простые POST из чужих вкладок).

Адаптер `engine/src/store/http.ts` реализует `ProgressStore` (интерфейс не меняется):
- `subscribe` — первая загрузка `GET /api/<col>`, затем повторная загрузка при возврате на вкладку (`visibilitychange`/`focus`) и раз в 30 с, пока вкладка видна. Так страница видит, что агент записал на диск (`meta/today`). Ошибка сети → `StoreError("unavailable")`.
- Изменения применяются в интерфейсе сразу (как сейчас), затем уходят запросом; ответ ≠ 2xx → ошибка, как у `claude-db`.
- `canWrite()` → `true`.

Обновление «на лету» с сервера (SSE, слежение за файлами) не делается: один пользователь, один экран, перезагрузки при фокусе хватает.

## Р-31. Сборка `build:local` {#build-local}

`npm run build:local -- --pack igor-2026w` → `dist/local/index.html` — **обычный HTML с полным каркасом** (`<!doctype>`, `<head>`, charset, viewport); постобработка claude.ai (снятие каркаса) не применяется. Пакет и KaTeX встроены так же, как в `build:claude` (Р-2 и Р-8 без изменений; вариант B из ADR-0002 не нужен, пока нет APK).

Адаптер выбирается **при сборке**: Vite `mode` (`production` → claude.ai, `pc` → ПК; имя `local` Vite запрещает) → в `main.tsx connect()` ветка `import.meta.env.MODE`; лишний адаптер вырезается из сборки. `npm run dev` по-прежнему с `memory`.

Попутно: в [01-overview.md#adapters](01-overview.md#adapters) интерфейс `ProgressStore` дописать коллекцией `meta` (в коде она есть), строку `indexeddb + sync или http` заменить на `http` (W5) и `capacitor` (APK).

## Р-32. Запуск ярлыком {#launch}

`tools/serve/open.sh`: если `GET http://127.0.0.1:4317/api/health` отвечает — открыть вкладку (`xdg-open`); иначе запустить сервер в фоне (`setsid nohup node tools/serve/server.ts …`, журнал `~/.cache/zachetka/serve.log`), дождаться `health` (до 5 с) и открыть вкладку. Если не поднялся — уведомление `notify-send` с путём к журналу.

Ярлык `~/.local/share/applications/zachetka.desktop` (меню приложений, при желании — на рабочий стол) ставит `tools/serve/install-shortcut.sh`. Сервер работает до выхода из системы; остановить — `tools/serve/open.sh --stop`.

## Р-33. Процедуры агента без ArtifactData {#agent}

| Было (claude.ai) | Стало (ПК) |
|---|---|
| `ArtifactData list items/attempts … out_dir` → `diff.ts --docs <out_dir>/items` | `diff.ts --docs <data>/items --attempts <data>/attempts` — сразу по папке данных |
| `today.ts … > /tmp/today.json` → `ArtifactData update meta/today` | `today.ts … --write <data>/meta/today.json` (проверка `TodayDocSchema` как сейчас) |
| Выпуск: `build:claude` → `Artifact read` → публикация с `url` → снимки базы до/после | `build:local` → перезагрузить вкладку; снимки не нужны (данные в git, сборка их не трогает) |
| Пробная страница | `npm run build:local` в worktree + сервер на другом порту и с копией данных (`--port 4318 --data <tmp>`) |

## Р-34. Перенос данных и заморозка страницы {#migration}

1. **Снимок** рабочей базы: `ArtifactData list` коллекций `items`, `attempts`, `meta` с `out_dir` → `../zachetka-snapshots/v5-migrate/` (под `~/.claude` писать нельзя).
2. **Перенос:** `tools/migrate/from-artifact.ts --from <снимок> --data <data>/igor-2026w` — принимает и голое тело, и обёртку `{id, data}` (как `readDocs`), пишет по файлу на документ, `updatedAt` сохраняет. Отказывается писать в непустую папку.
3. **Сверка:** число документов по коллекциям равно (в снимке v4.1-after 121 `items`, 2 `attempts`; `meta` раньше не снимался — ожидается 1 документ `today`); тела совпадают побайтно после нормализации JSON; `diff.ts` по новой папке даёт тот же отчёт, что по снимку.
4. Первый коммит репо данных.
5. **Заморозка:** `build:claude -- --frozen` — адаптер `claude-db` со `canWrite() = false` (интерфейс уже умеет «только чтение») и плашка сверху «Зачётка переехала на ПК. Здесь только просмотр (данные на 09.11)». Публикация на рабочий адрес по обычной процедуре ([03#publish](03-build.md#publish)).
6. **Откат:** опубликовать на рабочий адрес сборку v4.1 (`fabca39`) — база claude.ai не тронута переносом. Отметки, сделанные на ПК после переноса, туда сами не попадут: перенести обратно скриптом по `updatedAt` (пишется только если понадобится).

Замороженная страница **не обновляется** до APK (решение 09.11): на телефоне видны данные на момент переноса.

Между снимком (шаг 1) и заморозкой (шаг 5) отмечать на странице claude.ai нельзя — агент предупреждает пользователя перед шагом 1; после шага 5 сверяет, что в базе ничего не изменилось с момента снимка.

## Р-35. Файл обмена прогрессом (для APK; реализация — [11-apk.md](11-apk.md#merge), W10) {#exchange}

Формат зафиксирован сейчас, чтобы папка данных и будущий APK не разошлись (Н-8):

```json
{ "format": "zachetka-progress/1", "pack": "igor-2026w", "exportedAt": "2026-11-09T20:00:00Z",
  "collections": { "items": [{"id": "…", "updatedAt": "…"}], "attempts": [], "meta": [] } }
```

Слияние при импорте — по документу, побеждает больший `updatedAt` (поле уже ставят оба адаптера); попытки тестов (`attempts`) только добавляются. В W5 не реализуется.
