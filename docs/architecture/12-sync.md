# 12. Статусы из источников курса (C++, АиСД)

Версия: 0.1 · 2026-11-12 · Статус: **согласовано** 12.11 (решения пользователя ниже). Основа: [02-data.md#agent](02-data.md#agent), [07-standalone.md](07-standalone.md).

Решения пользователя 12.11: синхронизацию делает **алгоритм, не ИИ**; источник может **только повышать** статус и ставить **«доработку»**; решение в `cotests` = **«сдано»**; теорДЗ АиСД — **по таблице потока**.

## Р-66. Источники {#sources}

Все таблицы курса открыты по ссылке и скачиваются как CSV без входа (`/gviz/tq?tqx=out:csv&sheet=<лист>`). Конфиг — `<папка данных>/<пакет>/sync.yaml` (личный, не в репо: [13-classmates.md#private](13-classmates.md#private)); нет файла — синхронизация выключена, в журнале строка `sync: off`.

| Предмет | Источник | Что даёт |
|---|---|---|
| C++ | таблица manytask «ФПМИ С++ 2026-2027», лист `review_details`, строки логина | `+` → принято, `?` → сдано, `-` → доработка |
| C++ | `git ls-remote origin` в клоне manytask: `refs/merge-requests/N/head` = ветка `submit/<задача>` | сдано |
| АиСД | PR в репозитории ревью (`gh pr list`), ветки `<N>contest_task<X>` → `aisd-c<N>-<x>` | одобрен или слит → принято; правки запрошены → доработка; открыт → сдано |
| АиСД | таблица «Алгоритмы, основной поток»: блок «Теория» после «<N>. … Контест», строка студента по ФИО | есть оценка → `aisd-td<NN>` принято |
| АиСД | файлы `cotests/algos_dz_<N>/<x>.cpp` (одна буква) | `aisd-c<N>-<x>` сдано |

Источник без пункта в пакете не создаёт пунктов — попадает в отчёт («no pack item»).

## Р-67. Правило {#rule}

- По пункту несколько утверждений → берётся самое сильное (не начато < в работе < доработка < сдано < принято).
- Утверждение применяется, **только если значение источника изменилось** с прошлого запуска (`meta/sync.json` → `seen`): ручная отметка после синхронизации не затирается устаревшей таблицей.
- Применяется, если повышает статус или это «доработка»; иначе пропускается.
- Запись — как у `PATCH`: слияние `{status, updatedAt}` в документ пункта; отчёт последнего запуска — `meta/sync.json` → `last`.

## Р-68. Запуск {#run}

- Сервер ПК (`tools/serve/server.ts`) — при старте и раз в час, через ту же очередь записи на документ; отчёт — в журнал сервера (`~/.cache/zachetka/serve-4317.log`). `--no-sync` выключает.
- Вручную: `npm run sync` (`--dry-run` — только показать).
- Упавший источник (сеть, `gh`) не мешает остальным: строка `ERROR` в отчёте.
- На телефон статусы попадают обычным обменом Р-35.
