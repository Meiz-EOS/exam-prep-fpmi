# 11. APK для Android и обмен прогрессом файлом

Версия: 0.1 · 2026-11-11 · Статус: **согласовано** 11.11. Основа: [roadmap](../roadmap.md) E-9b; [functional-spec](../functional-spec.md) Н-7, Н-8; [07-standalone.md](07-standalone.md) Р-28, Р-35; [01-overview.md#adapters](01-overview.md#adapters); [ADR-0002](../adr/0002-data-delivery-and-validation.md) (обновление одним APK через «Избранное»).

Решения пользователя 11.11: APK делать **сейчас, до сессии** (раньше вехи M-5) — и обмен Р-35, и сам APK; собирать **локально на ПК**; обмен — **вручную кнопками** «Экспорт»/«Импорт» и отправкой файла в Telegram «Избранное»; на телефоне — **все разделы, как на ПК** (одна сборка, без урезанного режима).

Что не меняется: курс-пакет, `core`, экраны, формат документов прогресса, формат файла обмена Р-35, сервер ПК (только два новых запроса), Anki (на телефоне — AnkiDroid отдельно).

## Схема {#scheme}

```
ПК (вкладка, адаптер http)                          Телефон (APK, адаптер capacitor)
  ⇅ «Сохранить файл» ─► GET /api/export                ⇅ «Загрузить файл» ─► <input type=file>
         │  читает с диска                                     │  planImport (core/exchange)
         ▼                                                     ▼
  zachetka-progress-….json ── Telegram «Избранное» ──►  Data/zachetka/<пакет>/<col>.json
                                                               │
  POST /api/import ◄── «Загрузить файл» ◄── «Избранное» ◄── ⇅ «Отправить файл» (Filesystem + Share)
         │  planImport на сервере, запись документов как есть (updatedAt сохраняется)
         ▼
  zachetka-data/igor-2026w/{items,attempts,meta}/   (git, коммитит агент как раньше)
```

## Р-56. Объём и порядок {#scope}

Две части, сливаются в `dev` по отдельности, ПК не ломается между ними:

1. **Обмен на ПК** (W10-01…05): слияние в `core`, два запроса сервера, кнопка в интерфейсе. Android не нужен; проверяется кругом «экспорт → импорт в копию данных».
2. **APK** (W10-06…09): инструменты сборки, обёртка Capacitor, адаптер `capacitor`, выпуск и первая доставка через «Избранное».

## Р-57. Слияние: `core/exchange.ts` {#merge}

Чистый модуль без зависимостей от платформы (его импортирует и сервер — с `.ts` в пути, как `tools/agent/diff.ts`).

- `buildExchange(pack, collections, now) → ExchangeFile` — файл Р-35: `format: "zachetka-progress/1"`, `pack`, `exportedAt`, `collections.{items,attempts,meta}` — документы целиком, с `id` и `updatedAt`.
- `parseExchange(value, pack) → ExchangeFile` — проверка zod: формат ровно `zachetka-progress/1`; `pack` совпадает со своим (иначе ошибка «файл другого курса»); у каждого документа `id` по правилу `[A-Za-z0-9_-]{1,128}` (Р-29); `updatedAt` разбирается, если есть (у 29 пунктов, записанных до W5, его нет — найдено 12.11). Ошибка — без частичного применения.
- `planImport(local, incoming) → { writes: {col, doc}[], added, updated, kept }` — **по документу внутри коллекции**:
  - документа нет у себя → добавить;
  - есть у обоих → побеждает больший `Date.parse(updatedAt)`; отметка, которой нет или которая не разбирается, старше любой настоящей; при равенстве или когда отметки нет у обоих — оставить свой;
  - есть только у себя → оставить;
  - **ничего не удаляется**. Попытки тестов (`attempts`) идут по тому же правилу: попытку пишет одно устройство, её дописывание поднимает `updatedAt` — «только добавляются» из Р-35 выполняется само.
- Слияние документа целиком, не по полям: если один документ поменяли на обоих устройствах между обменами, остаётся более поздняя правка (см. [#limits](#limits)).

Свойства (тесты vitest): повторный импорт того же файла ничего не пишет; экспорт → импорт в пустое хранилище → экспорт дают те же документы; импорт старого файла ничего не откатывает; документы, которых нет в файле, не трогаются.

## Р-58. Обмен — отдельная возможность хранилища, не часть `ProgressStore` {#capability}

```ts
interface ExchangeCapable {
  exportFile(): Promise<ExchangeFile>;                 // из источника истины, не из снимка интерфейса
  importFile(file: ExchangeFile): Promise<ImportStats>; // слить, записать как есть, обновить подписчиков
}
```

Есть у `http` и `capacitor`; у `claude-db`, `read-only`, `memory` — нет (кнопка обмена не показывается). Интерфейс `ProgressStore` не меняется.

**ПК, сервер** ([07#api](07-standalone.md#api) дополняется):

| Запрос | Ответ |
|---|---|
| `GET /api/export` | файл Р-35 по папке данных — читается с диска, поэтому в него попадает и `meta/today`, записанный агентом |
| `POST /api/import` | тело — файл Р-35 (до **8 МиБ**); сервер делает `parseExchange` + `planImport` и пишет документы **как есть**, с их `updatedAt` (в отличие от `PATCH`), атомарно и в очереди на документ; ответ `{added, updated, kept}`; чужой пакет или плохой файл → 400 |

Защиты те же (Host, `Content-Type`). Сервер не коммитит; импорт фиксирует агент своим обычным коммитом в начале сессии.

**`HttpStore`**: `exportFile` = `GET /api/export`; `importFile` = `POST /api/import`, затем перезагрузка всех подписанных коллекций.

## Р-59. Адаптер `capacitor` {#adapter}

Хранение — плагин `@capacitor/filesystem`, каталог `Directory.Data` (внутренняя память приложения): `zachetka/<пакет>/<col>.json` — **один файл на коллекцию** (массив документов).

Почему так:
- не localStorage и не IndexedDB WebView: у них свои квоты и правила очистки, и их нельзя посмотреть снаружи. Файл в `Data` — явный, переживает обновление APK, его можно достать `adb run-as` для отладки;
- по коллекции, а не по документу, как на ПК: на телефоне нет git и агента, а один файл — это одно чтение через мост при запуске вместо ~130. Документов немного (сейчас 121 + 2 + 1), перезапись коллекции при отметке укладывается в миллисекунды.

Поведение:
- запуск: прочитать три файла (нет файла = пусто), раздать подписчикам `fromCache:false`; опроса нет — кроме самого приложения, писать некому;
- запись: изменение в памяти сразу (интерфейс не ждёт), затем запись коллекции **атомарно** (временный файл → `rename`; если `rename` поверх существующего файла не удался — удалить старый и повторить; при запуске, если основного файла нет, а `.tmp` есть, берётся `.tmp` — 12.11, поведение `rename` у плагина не документировано), записи в коллекцию — строго по очереди (`KeyedQueue` по коллекции); ошибка диска → `StoreError("unavailable")`;
- `create`: id — `crypto.randomUUID()` без дефисов, первые 20 знаков (как у сервера: id с двух устройств не сталкиваются и проходят правило Р-29); `updatedAt` ставит адаптер (`toISOString()`), как остальные;
- `canWrite()` → `true`;
- `importFile`: перед применением — **резервная копия**: текущий экспорт пишется в `Data/zachetka/<пакет>/backup/before-import-<время>.json`, хранятся 3 последних (на телефоне нет git; решение 11.11).

## Р-60. Обмен в интерфейсе {#ui}

Кнопка `⇅` в верхней строке справа (только если хранилище умеет обмен) → нижняя шторка (`ui/sheet.tsx`) «Обмен прогрессом»:

- **«Сохранить файл»** (ПК) / **«Отправить файл»** (телефон) — экспорт. Имя файла: `zachetka-<пакет>-<ГГГГ-ММ-ДД-ЧЧмм>.json`.
  - ПК: `Blob` + `a[download]` → файл в «Загрузках», пользователь перетаскивает его в «Избранное» Telegram Desktop.
  - Телефон: в WebView скачивание `Blob` не работает → `Filesystem.writeFile` в `Directory.Cache` + `@capacitor/share` с этим файлом → системное «Поделиться» → Telegram → «Избранное».
- **«Загрузить файл»** — `<input type="file" accept=".json,application/json">` на обеих сторонах (в Capacitor 8 выбор файла в WebView работает из коробки — `BridgeWebChromeClient.onShowFileChooser`). На телефоне файл из Telegram сначала сохраняется в «Загрузки» («Сохранить в загрузки» в меню файла).
- После выбора — разбор и **подтверждение внутри страницы**: «Из файла от 11.11 20:15: добавится N, обновится M, без изменений K. Применить?» → «Применить» / «Отмена». Ошибки разбора — текстом в шторке («файл другого курса», «не файл Зачётки»).
- В шторке — время последнего экспорта и импорта на этом устройстве (`ui/prefs`, localStorage — только удобство).

Строки — в `ui/i18n/ru.ts` и `en.ts`.

## Р-61. Сборка `build:apk` {#build}

- Режим Vite **`apk`** → `dist/apk/index.html` — тот же одиночный HTML с полным каркасом, как `build:local` (Р-31). В `main.tsx connect()`: `MODE === "apk"` → `await import("./store/capacitor")`; плагины Capacitor подключаются только динамическим импортом, в сборки `pc` и claude.ai не попадают.
- Зависимости (точные версии в `package.json`): `@capacitor/core`, `@capacitor/android`, `@capacitor/filesystem`, `@capacitor/share` (8.x), `@capacitor/cli` — в dev.
- `capacitor.config.ts` в корне: `appId: "app.zachetka"`, `appName: "Зачётка"`, `webDir: "dist/apk"`. Папка `android/` создаётся `npx cap add android` и **хранится в репо** (свой `.gitignore` шаблона Capacitor отсекает сборочный мусор).
- `npm run build:apk` = `vite build --mode apk` → `cap sync android` → `android/gradlew assembleRelease` с подписью (Р-62) → копия в `dist/apk-out/zachetka-<versionName>.apk` (не в `dist/apk`: это веб-каталог, он уходит внутрь APK). Окружение (JDK, SDK) — из `tools/apk/env.sh` (Р-64).
- Проверка сборки без телефона: `apksigner verify` + `aapt dump badging` (имя пакета, `versionCode`).

## Р-62. Подпись и версии — чтобы обновление было «одним файлом» {#signing}

Android ставит новый APK **поверх** старого, сохраняя данные приложения, только если совпадают `appId` и ключ подписи, а `versionCode` больше прежнего. Иначе — только удалить и поставить заново, а **удаление стирает прогресс на телефоне**.

- Ключ: свой release-keystore, создаётся один раз (`keytool`), лежит **вне репо**: `~/.config/zachetka/release.jks`, пароли — `~/.config/zachetka/keystore.env` (читает `build.gradle` через переменные окружения). Debug-ключ из `~/.android` не используется: он пропадёт при переустановке системы. Резервные копии ключа и `keystore.env` (решение 11.11): в репо данных `../zachetka-data/keys/` (коммит без упоминания ИИ) и в «Избранное» Telegram (через `tg`).
- `versionCode` = минуты с 2026-01-01 по UTC в момент сборки (растёт всегда, в том числе при сборке из ветки; помещается в int на тысячи лет). `versionName` = `<ГГГГ-ММ-ДД>-<короткий sha>`; показывается в шторке обмена.

## Р-63. Доставка и первая установка {#delivery}

- Агент после `build:apk` отправляет APK в «Избранное» пользователя через `tg` CLI (навык `telegram`). На телефоне: открыть файл → «Установить» (Telegram разрешить ставить приложения — один раз).
- **Первый запуск** — пустое хранилище. Перенос: на ПК `⇅` → «Сохранить файл» → в «Избранное» → на телефоне `⇅` → «Загрузить файл». Дальше — так же в обе стороны.
- Новая версия (контент или код) — тот же путь: новый APK в «Избранное», установка поверх, прогресс остаётся.
- Страница claude.ai остаётся замороженной (Р-34); после выпуска APK она больше не нужна.

## Р-64. Инструменты сборки на ПК (без sudo) {#toolchain}

Требования Capacitor 8.6 (проверено по `@capacitor/android@8.6.0`): **JDK 21**, Android Gradle Plugin 8.13, **compileSdk/targetSdk 36**, minSdk 24.

- Всё в `../android/` (sudo нет; на этом диске больше всего свободного места): `jdk-21/` — Temurin 21 (архив с adoptium.net), `sdk/cmdline-tools/latest/` — Android command-line tools (dl.google.com), затем `sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"` и `sdkmanager --licenses`. Gradle — через `gradlew` (кэш `~/.gradle`). Итого ~3–4 ГБ.
- `tools/apk/env.sh` выставляет `JAVA_HOME`, `ANDROID_HOME`, `PATH`; пути не зашиты в `build.gradle`.
- Android Studio не нужна; эмулятор не ставится — проверка на телефоне пользователя.

## Сборка в GitHub Actions форка {#ci}

Решение — [13-classmates.md#ci-apk](13-classmates.md#ci-apk) (Р-73); workflow — `.github/workflows/apk.yml`. Один раз:

1. Свой ключ (пароль запомнить; файл и пароль сохранить у себя — **потерянный ключ = переустановка с потерей прогресса на телефоне**):
   ```sh
   keytool -genkeypair -keystore release.jks -storetype PKCS12 -alias zachetka -keyalg RSA -keysize 4096 -validity 36500
   base64 -w0 release.jks   # → значение секрета ZACH_KEYSTORE_B64
   ```
2. В форке: Settings → Secrets and variables → Actions → Secrets: `ZACH_KEYSTORE_B64`, `ZACH_KEYSTORE_PASSWORD`, `ZACH_KEY_ALIAS` (`zachetka`), `ZACH_KEY_PASSWORD` (для PKCS12 — тот же пароль). Если пакетов в `packs/` несколько — переменная `ZACH_PACK` (вкладка Variables), например `packs/my-pack`.
3. Сборка: `git tag v1.0.0-me.1 && git push origin v1.0.0-me.1` → APK появляется в Releases форка. Вручную (Actions → apk → Run workflow) — APK во вложениях запуска, 14 дней.

Без Secrets workflow останавливается на первом шаге с сообщением, какие секреты добавить. JDK и SDK в CI ставят `setup-java`/`setup-android`; `tools/apk/env.sh` берёт их из окружения, если папки `androidDir` нет.

## Р-65. Ограничения {#limits}

- **Удаления не переносятся** (Р-57: ничего не удаляется). Удалённый на одном устройстве пункт «Сдач» вернётся при импорте с другого, если там он ещё есть (принято 11.11: удаляют редко).
- Один документ, изменённый на обоих устройствах между обменами, — остаётся более поздняя правка, другая теряется (слияние по документу). Правило на практике: перед работой на другом устройстве — обменяться.
- Сравнение по часам устройств: часы телефона и ПК должны быть верны (автоматическое время).
- Удаление приложения или «Очистить данные» стирают прогресс на телефоне — восстанавливается импортом последнего файла с ПК.
