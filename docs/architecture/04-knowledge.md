## Билеты {#tickets}

**Р-12.** Файл `tickets/<предмет>.yaml`: список билетов в порядке программы. Билет — одна теорема или определение (решение 08.11), а не раздел конспекта.

```yaml
provisional: true          # временные (из оглавления конспекта), см. ниже
tickets:
  - { id: matan-t-0201, title: "Определение предела последовательности", src: "matan.tex:452-470" }
  - { id: matan-t-0207, title: "Теорема Вейерштрасса о монотонной последовательности", src: "matan.tex:612-640", key: true }
```

- `src` — файл и строки tex-конспекта (`mipt/экзамен/tex/`); пригодится теории (E-5).
- `key: true` — ключевая теорема (для порога «хор»: должна быть в L2).
- **АиГ и матан (решение 08.11):** программ потоков Штепина и Редкозубова нет. Временные билеты агент выписывает из конспекта: ключевые определения и теоремы каждого подраздела (`provisional: true`). Когда программа появится, билеты заменяются, а старые id переводятся на новые файлом `tickets/<предмет>.remap.yaml` (`старый: новый`), чтобы прогоны тестов не потерялись.
- **ОКТЧ, АиСД, C++** — билеты из настоящих программ (`tex/билеты/`). ОКТЧ: пока список «Инф»; вариант уточняется (вопрос №5).

## Карточки {#cards}

**Р-13.** Файл `cards/<предмет>/<тема>.md`: front-matter + карточки секциями.

```markdown
---
deck: Пределы            # → колода zachetka::матан::Пределы
tickets: [matan-t-0201]   # по умолчанию для всех карточек файла
---
## matan-c-0001
Определение предела последовательности (на языке ε–N).
---
$\lim x_n = a \iff \forall \varepsilon>0\ \exists N\ \forall n>N:\ |x_n-a|<\varepsilon$
```

- Заголовок `## <id>` — постоянный id; id не переиспользуется, удалённая карточка свой id не отдаёт.
- Свой билет у карточки: `## <id> · <билет>[, <билет>]` (иначе — билеты файла). Нужен, чтобы забывания в Anki считались по билету, а «Источник» был точным.
- Над `---` — вопрос, под — ответ. Формулы `$…$` / `$$…$$` переводятся в MathJax Anki `\(…\)` / `\[…\]`.
- В Anki: GUID заметки = хеш(`<pack id>:<card id>`); поля «Вопрос», «Ответ», «Источник» (src билета); теги — id билетов и `L0`.
- Пишет агент по конспекту (ГЗ-2 а), автор правит через Anki (С-3а, ГЗ-12 а).
- **Оценка в Anki — только «Снова» / «Хорошо».** FSRS считает «Трудно» успехом; нажимать его на забытой карточке — частая ошибка, которая раздувает интервалы. Это совет сообщества Anki, не официальное руководство.

**Р-14. Конвейер Anki** (уточняется спайком SP-5, карточка W2-02):
- `tools/anki/` — Python, `genanki` в `tools/anki/.venv` (не в git, не в системе).
- Сборка: пакет → `dist/anki/<pack>.apkg` → импорт в Anki на ПК → AnkiWeb → AnkiDroid.
- Повторный импорт с теми же GUID обновляет текст, история повторений остаётся (**проверить в SP-5**).
- История и флаги: агент читает **копию** `collection.anki2` (sqlite, таблицы `revlog`, `cards`, `notes`). При открытом Anki копировать вместе с `-wal` или через `sqlite3 … .backup` (SP-5). AnkiConnect не используем (порт 8765 занят разметчиком Elixir).
- **Итоги SP-5** ([sp5-anki.md](../spikes/sp5-anki.md)): повторный импорт с тем же GUID обновляет текст, история и интервалы остаются. Импорт — `update_notes: IF_NEWER`, `merge_notetypes: true`; поля «Вопрос/Ответ/Источник» и id типа заметки не меняются. Внутри формул экранировать `<`, `>`, `&`.
- **Правки в Anki не затираются:** genanki ставит заметкам время сборки, поэтому перед каждой сборкой агент сверяет тексты коллекции с пакетом (W2-12), согласует найденные правки с пользователем, переносит их в `.md`, и только потом собирает колоду. В колоду идут только изменившиеся карточки.
- **Убранная из пакета карточка** (решение 08.11): агент приостанавливает её в Anki (suspend), история остаётся. Удаляет пачкой, когда таких накопится много, после просмотра списка пользователем.
- **FSRS** в `.apkg` не переносится: пользователь один раз включает его в настройках Anki на ПК (глобальный флаг), пресет колоды — по умолчанию.

## Тесты {#tests}

**Р-15.** Файл `tests/<предмет>/<тест>.md`:

```markdown
---
id: matan-entry
title: Матан — входной тест
kind: entry              # entry | retest | mock
minutes: 150
reuse: []                # id вопросов из других тестов (для ретеста)
---
## matan-q-001
ticket: matan-t-0201 · level: L0
Дайте определение предела последовательности и его отрицание.
### Эталон
- $\forall \varepsilon>0$ …
- $\exists N$ …
- отрицание: $\exists \varepsilon>0\ \forall N\ \exists n>N: |x_n-a|\ge\varepsilon$
```

- Вопрос: `ticket`, `level` (что проверяет). Устных вопросов отдельно нет: все пишутся на странице, агент потом доспрашивает в разговоре (решение 08.11).
- **Эталон — список ключевых пунктов** (2–6 пунктов, каждый проверяется «есть / нет»). Это основа самооценки (Р-17).
- id вопросов уникальны во всём пакете; ретест собирается из новых вопросов и `reuse`.

**Р-17. Прохождение (`#tests`):** список тестов → прогон: вопрос по одному, поле ответа, «Показать эталон», затем **самооценка по ключевым пунктам**: отмечаешь, какие пункты эталона есть в ответе; кнопка «есть грубая ошибка» обнуляет ответ. Балл ответа = отмеченные / все пункты (0…1).

Почему так: сверка по пунктам эталона заметно снижает переоценку себя по сравнению с оценкой «на глаз» (Dunlosky, Hartwig, Rawson, Lipko 2011; Lipko et al. 2009). Документ прогона в `attempts` создаётся при старте и дополняется после каждого ответа (Н-3), незаконченный прогон можно продолжить. Формулы — KaTeX (Р-8).

Формат ответа в прогоне (уточняет [02#attempts](02-data.md#attempts)):
```ts
{ q: "matan-q-001", text: "…", hits: [0, 2], gross?: true, self: 0.67, agent?: 0.5, agentNote?: "…", at: ISO }
```

## Готовность {#ready}

**Р-16. Расчёт** (`core/ready.ts`, чистая функция), без значков-стикеров — только числа и полосы (решение 08.11):
- **балл ответа** — оценка агента, если есть, иначе самооценка;
- **значение вопроса** — среднее баллов **последних 3 ответов** на него (решение 08.11);
- **ячейка «билет × уровень»** — среднее значений вопросов этого билета и уровня; нет ответов → пусто;
- **«освоено»** — значение ≥ 0,8 **и** последние 3 ответа даны в 3 разных дня, каждый ≥ 0,8. Это критерий successive relearning: по одному верному ответу в трёх разнесённых сессиях удерживается намного лучше, чем три за один раз (Rawson et al. 2018: 68% против 26% через неделю).

Доля по уровню = «освоено» / все билеты предмета. Пороги — в `pack.yaml` (копия методики §1, чтобы движок не зависел от mipt):

```yaml
thresholds:
  ud:  { L0: 0.95, L1: 0.5 }
  hor: { L0: 1.0, L1: 0.85, L2: 0.5, keyL2: true }
```

**Р-18. Страница `#ready`:** по предмету — итог (доли L0/L1/L2, «до уд», «до хор») и таблица билетов: значение числом и полосой, отметка «освоено», дата последнего ответа. `карта.md` в mipt после этого ведётся из страницы (агент переписывает её по сводке), а не руками.
