# 01. Обзор: слои, раскладка, модули

## Слои {#layers}

```
ui (Preact)        модули страницы, маршруты, тема, i18n
  ↓ использует
store              прогресс: интерфейс ProgressStore + адаптеры
content            курс-пакет: схемы, загрузка встроенного JSON
core               чистая логика: даты, «горит», прогресс групп, слияние пакет+прогресс, уровни
```

- **`core`** — только функции и типы. Без DOM, без `window`, без платформы. Всё покрыто тестами (А-5).
- **`content`** — схемы `zod` для пакета (общие для сборки в Node и для страницы) и чтение встроенного пакета.
- **`store`** — интерфейс `ProgressStore` (§адаптеры) и его реализации. UI работает только через интерфейс.
- **`ui`** — Preact-компоненты. Получает пакет и `ProgressStore`, вызывает `core` для расчётов.

## Маршруты {#routes}

Только простой `#имя` (ограничение claude.ai: не `#/path` и не `?query`). Неизвестный или пустой хэш → первый модуль из навигации. Обработка на загрузке и на `hashchange`.

## Адаптеры {#adapters}

```ts
interface ProgressStore {
  subscribe(col: "items" | "attempts" | "meta", cb: (snap: Snapshot) => void, err: (e: StoreError) => void): () => void;
  update(col, id, patch): Promise<void>;   // одна запись за раз на документ
  create(col, data): Promise<string>;      // id
  remove(col, id): Promise<void>;
  canWrite(): Promise<boolean | null>;
}
```

| Адаптер | Где | Когда |
|---|---|---|
| `memory` | тесты, локальная разработка (`npm run dev`) | W1 |
| `claude-db` | страница claude.ai: `await claude.use("db")`, коллекции `items`, `attempts` | W1 |
| `http` | версия для ПК: локальный сервер `tools/serve/server.ts`, сборка `build:local` | W5 ([07](07-standalone.md#api)) |
| `capacitor` | APK: файлы в памяти приложения (`@capacitor/filesystem`), сборка `build:apk` | E-9b, W10 ([11](11-apk.md#adapter)) |

Адаптер выбирается режимом сборки в `main.tsx connect()`: `dev` → `memory`, `pc` → `http`, `apk` → `capacitor` (W10), иначе `claude-db`.

Правила `claude-db` взяты из контракта платформы: подписка один раз на коллекцию; таймер 10 с на первую загрузку; записи в один документ — строго по очереди; `invalid_argument` при записи = нет прав → интерфейс только для чтения.

## Тема и вёрстка {#theme}

Только тёмная тема (Н-1): токены цвета на `:root` с `color-scheme: dark` и явным фоном `body`. Ширина 360–430 px — основной случай; на компьютере колонка до 760 px. Прототип v0 (`mipt/экзамен/подготовка/app/tracker.html`) — образец поведения и вёрстки, его тёмная палитра переносится как основа.

**Взаимодействие (08.11, по итогам пробы, W1-13):**
- Всё нажимаемое выглядит нажимаемым: строка пункта — одна кнопка не ниже 44 px со стрелкой `›` и подсветкой; у групп — стрелка и подсветка.
- Ничего не прыгает: элементы, меняющие подпись (статус), фиксированной ширины; изменения видны сразу, не дожидаясь базы; пункт не исчезает из списка под пальцем.
- Статус меняется через меню у кнопки (любой статус за два нажатия), а не циклом.
- Задачи задания (`дз-задача`) — только галочка «решено» (W1-14); статус — у задания целиком.
- Группа «X · часть» показывается внутри группы «X» (недели внутри задания, W1-16); счётчик задания — по задачам всех недель.
- Подробности пункта — нижняя шторка (`ui/sheet.tsx`), не раскрытие в строке.
- Необратимое — с подтверждением внутри страницы; частое — с «Отменить» во всплывашке.
- Срок — только на сдачу (W1-19): у «сдано»/«принято» срок не показывается и не горит; у «доработки» действует только срок, поставленный вручную.

## Языки {#i18n}

Строки интерфейса — в `ui/i18n/ru.ts` и `en.ts` с одинаковыми ключами (проверка типами). Язык — по `navigator.language` (`ru*` → ru, иначе en). **Контент пакета (названия пунктов, заметки, карточки) не переводится** и показывается как есть.
