## Р-81. Граф тем: `graph/<предмет>.yaml` {#graph}

```yaml
topics:
  - id: matan-g-seq-limit            # id темы, уникален во всём пакете
    title: "Предел последовательности"
    tickets: [matan-t-0201, matan-t-0202, matan-t-0203]   # билеты из tickets/matan.yaml
    requires: []                     # можно не писать
  - id: matan-g-weierstrass
    title: "Монотонные последовательности, число e"
    tickets: [matan-t-0207, matan-t-0208]
    requires: [matan-g-seq-limit]    # id тем; можно и тему другого предмета
    minutes: 30                      # необязательно: сколько минут читать тему
```

- **Тема** — 3–8 соседних билетов, которые учатся за один присест. Id — по общим правилам id, по соглашению `<предмет>-g-<слово>`.
- `tickets` — билеты-теоремы **этого** предмета (`tickets/<предмет>.yaml`), не экзаменационные (`exam/`); не меньше одного. Порядок в списке — порядок изучения внутри темы.
- `requires` — темы, без которых эту не понять. Только прямые зависимости (транзитивные писать не надо). Тема другого предмета допустима.
- `minutes` — оценка времени на чтение; нет поля → 4 минуты на билет (`topicMinutes`).
- **Граф у предмета необязателен.** Предмет без файла работает как раньше (линейный входной тест, колоды по `deck`), в план дня не попадает.

Проверки сборки (`tools/pack/graph.ts`, все — ошибки, `файл:строка: текст`):

| Нарушение | Текст |
|---|---|
| файл для предмета, которого нет в `pack.yaml` | `предмет "x" не описан в pack.yaml…` |
| id темы занят (тема, билет, тест, вопрос…) | `id "…" повторяется — он уже занят (…)` |
| билета нет | `тема "T" содержит неизвестный тикет "t"` |
| билет другого предмета | `тема "T" содержит тикет "t" другого предмета (s)` |
| билет в двух темах (или дважды в одной) | `тема "T": тикет "t" уже входит в тему "U" (один тикет — ровно в одной теме)` |
| билет предмета не вошёл ни в одну тему | `в граф не вошли тикеты предмета (N): … — при графе каждый тикет предмета должен быть ровно в одной теме` |
| в `requires` не тема | `тема "T" требует неизвестную тему "x" (в requires — id тем из graph/, не тикетов)` |
| тема требует себя / повтор в `requires` | `тема "T" требует саму себя` / `тема "T": "x" повторяется в requires` |
| цикл (в том числе через другой предмет) | `цикл в графе тем: a → b → c → a (стрелка — «требует»)…` |
| `::` в названии | `тема "T": в названии нельзя «::» — так Anki разделяет вложенные колоды` |
| схема: пустой `tickets`, лишнее поле, не id | обычные сообщения схемы с пометкой `(тема T)` |

В собранном пакете — поле `graph` (нет папки `graph/` → поля нет):

```ts
graph?: { id: string; subject: string; title: string; tickets: string[]; requires: string[]; minutes?: number }[]
```

## Р-82. Канонический порядок {#order}

Порядок изучения — **устойчивая топологическая сортировка** всего графа пакета: темы выписаны в порядке «предметы как в `pack.yaml`, внутри предмета — как в файле»; на каждом шаге берётся **первая** в этом списке тема, у которой все `requires` уже выписаны (`topoOrder`). Порядок предмета — этот же порядок, из которого оставлены темы предмета.

- `pack.graph` **уже лежит в каноническом порядке** — сборка сортирует. Кто читает пакет (страница, `tools/anki`), порядок не пересчитывает: темы предмета = `graph.filter(subject)`, номер темы `NN` = место в этом списке, с 1.
- Если писать темы в файле в порядке изучения, канонический порядок совпадёт с порядком файла.
- Правка графа (новая тема в середине) сдвигает номера следующих тем — это нормально: id тем не меняются, прогресс привязан к id.

## Р-83. Состояния темы {#states}

`topicStates(pack, graph, { known, marks, attempts })` → для каждой темы одно из четырёх:

| Состояние | Когда |
|---|---|
| `known` «знал» | входной тест показал: на вопрос темы ответил хорошо, либо это предок такой темы (Р-85) |
| `learned` «изучена» | не `known`, и: есть отметка `learned` (мини-проверка плана дня пройдена или отмечено руками), **или** отметки нет, но это видно по ответам |
| `open` «открыта» | не `known` и не `learned`, а **все** темы из её `requires` — `known` или `learned`. Её можно учить сейчас |
| `locked` «закрыта» | остальное: что-то из `requires` ещё не пройдено |

- **«Видно по ответам»** (`topicEvidence`): вопросы темы — все вопросы пакета уровня L0 и L1 про её билеты, из любых тестов (`topicQuestions`). Значение вопроса — как в готовности (Р-16: среднее последних 3 ответов, `questionValue`). Тема изучена, если отвечено не меньше **3** вопросов (или все, если их меньше трёх; хотя бы один) и среднее их значений **≥ 0,7**. Так ответы из обычных тестов по темам и билетам тоже двигают граф.
- **Отметка `unknown`** («на самом деле не знаю») сильнее входного теста и ответов: тема снова `open`/`locked`. Снимается новой отметкой `learned`.
- Отметка `learned` сильнее ответов (в том числе плохих, данных позже): пересдавать не заставляем. «Освоено» карты готовности (Р-16, три дня) — отдельная, более строгая мера; на граф она не влияет.
- Смотрятся только **прямые** `requires`, в том числе темы других предметов. Нет входного теста по предмету → `known` пусто, открыты корни графа.
- Тема без вопросов становится изученной только отметкой.
- `nextTopics(graph, states, subject)` — открытые темы предмета в каноническом порядке; первая — «новая тема» плана дня.

## Р-84. Входной пул вместо входного теста {#entry-pool}

У предмета **с графом** файл `tests/<предмет>/<предмет>-entry.md` (`kind: entry`) — не тест, который проходят подряд, а **пул вопросов** для входного теста по графу (Р-85). Формат файла и вопроса прежний (Р-15):

```markdown
---
id: matan-entry
title: "Матан — входной тест"
kind: entry
---
## matan-q-001
ticket: matan-t-0201 · level: L0
Дайте определение предела последовательности.
### Эталон
- для любого $\varepsilon>0$ найдётся $N$
- при всех $n>N$ выполнено $|x_n-a|<\varepsilon$
```

- **Вопрос относится к теме через билет:** тема вопроса = тема, в `tickets` которой стоит его `ticket`. Отдельного поля нет.
- **`minutes` у `kind: entry` необязательно и ничего не значит** (в собранном пакете — 12). У остальных видов тестов обязательно, как было.
- Правила пула:
  1. на каждую тему — **хотя бы один** вопрос, лучше **два** (второй нужен, чтобы повторный тест был другим);
  2. только **L0 и L1**; L2 во входном тесте не задаётся;
  3. вопрос — на минуту: одно определение, одна формулировка, «верно ли и почему», идея в одну фразу. **Без доказательств**, в том числе «назовите скелет доказательства»;
  4. эталон — **2–3 пункта**;
  5. один вопрос проверяет одно: без довесков «…и сформулируйте отрицание», «…и приведите пример»;
  6. вопрос должен различать «знаю тему» и «не знаю»: спрашивать главное понятие или факт темы, а не мелочь из неё.
- Вопросы, на которые ссылаются `reuse` других тестов, из пакета удалять нельзя (сборка упадёт): если такой вопрос не годится для пула, его переносят в тест, который на него ссылается.
- Проверка сборки — **предупреждения**, не ошибки (пакет собирается, пока пул переписывается); `npm run check:pack` печатает их строками `предупреждение: файл:строка: текст`, код выхода 0:
  - у предмета есть граф, но нет теста `kind: entry`;
  - по теме нет ни одного вопроса L0/L1 в пуле (одной строкой — список тем);
  - вопрос пула уровня L2; в эталоне больше 3 пунктов; вопрос просит ещё и отрицание.
- Предмет **без графа**: `kind: entry` остаётся обычным линейным тестом, как раньше.

## Р-85. Входной тест по графу {#placement}

Чистый автомат `core/placement.ts`; экран только показывает вопрос и передаёт балл. Самооценка — прежняя (Р-17): галочки по пунктам эталона, «грубая ошибка» = 0.

- **Ответ хороший**, если балл ≥ **0,6** (`PLACEMENT_PASS`): 2 пункта из 3 — да, 1 из 2 — нет. «Не знаю» = балл 0.
- **Вывод из ответа.** Хороший ответ по теме → известны она и **все её предки** в предмете. Плохой → неизвестны она и **все её потомки** в предмете. Предки и потомки считаются по всему графу (путь может идти через тему другого предмета), но тест предмета выносит решение только о темах **своего** предмета. Если ответы спорят (после правки графа), побеждает «неизвестна».
- **Следующий вопрос.** Среди ещё не определённых тем, у которых в пуле есть не заданный вопрос, берётся та, что **лучше всего делит остаток**: для темы считаем `up` = 1 + число неопределённых предков, `down` = 1 + число неопределённых потомков; выбираем наибольший `min(up, down)`, при равенстве — наибольший `up + down`, при равенстве — тему раньше в каноническом порядке. Вопрос темы — первый по порядку пула; вопросы из прошлых прохождений (`avoid`) идут последними.
- **Конец:** задано **8** вопросов (`PLACEMENT_MAX_QUESTIONS`), **или** не осталось неопределённых тем с вопросами, **или** пользователь прервал («Хватит» доступно на каждом вопросе). Неопределённые темы считаются неизвестными.
- Результат сохраняется **после каждого ответа** (Р-86), поэтому закрытая вкладка ничего не теряет; незаконченный тест можно продолжить (`resumePlacement`).
- Оценка времени до старта — `placementMinutes(plan)`: 1,5 минуты на вопрос, не больше 12.
- Повторный тест: новый запуск с `avoid` = вопросы прошлого запуска; документ результата заменяется.

## Р-86. Что добавляется в прогресс {#progress}

Коллекция `meta` (она уже входит в файл обмена и синхронизацию), запись через `store.update("meta", id, …)`.

```ts
// meta/placement-<предмет> — результат входного теста (один на предмет)
{ subject: "matan", startedAt: ISO, finishedAt?: ISO,       // finishedAt — когда тест окончен или прерван
  asked: [{ topic: "matan-g-seq-limit", q: "matan-q-001", score: 0.67, ok: true, at?: ISO }],
  known: ["…"], unknown: ["…"],                              // копия вывода для чтения глазами и агентом
  attempt?: "<id документа attempts>" }

// meta/topics — отметки тем
{ marks: { "matan-g-seq-limit": { state: "learned" | "unknown", at: ISO } } }

// meta/day — план дня (Р-88)
{ date: "2026-11-15", subject: "matan", topic?: "matan-g-weierstrass",
  done: { anki?: ISO, theory?: ISO, check?: ISO }, check?: "<id документа attempts>" }
```

- Приложение считает `known` **заново из `asked`** на текущем графе (`placementKnown`), списки `known`/`unknown` в документе — только копия. Поэтому правка графа не оставляет устаревших выводов, а ответы про удалённые темы просто пропускаются.
- **Тексты ответов** входного теста и мини-проверки пишутся в `attempts` обычным документом прогона (Р-5): `test: "placement-<предмет>"` и `test: "check-<id темы>"`. Таких тестов в пакете нет — это метка; ответы при этом попадают в карту готовности (она считает по id вопроса) и в сводку агента (`diff.ts`). Экран `#tests` такие прогоны не показывает.
- `meta/today` (план агента, Р-19) остаётся: из него берётся число карточек к повторению.
- Необязательные поля, добавленные при реализации: `meta/day.finished: string[]` — темы, закрытые сегодня до нажатия «Ещё одна тема»; `meta/placement-<предмет>.avoid: string[]` — вопросы прошлых запусков (нужны, чтобы продолженный тест выбирал те же вопросы). Запись в `meta` — merge-patch, поэтому снятое поле пишется как `null` (`dayPatch`); читающий код считает `null` отсутствием.
- Предмет прогона `placement-…` / `check-…` даёт `attemptSubject(pack, test)` (`core/plan.ts`) — им пользуется `tools/agent/diff.ts`.

## Р-87. Колоды Anki по графу {#anki}

- **Карточка относится к теме через билет:** тема карточки = тема **первого** билета из её `tickets` (свои билеты карточки `## id · билет` главнее билетов файла).
- **Колода** карточки предмета с графом: `zachetka::<имя предмета>::<NN> <название темы>` — `NN` — номер темы в предмете (Р-82), две цифры (три, если тем 100 и больше). То же самое даёт `topicDeck(pack, graph, id)` — страница показывает это имя в шаге «новая тема».
- Поле `deck` в заголовке файла карточек у предмета с графом **не используется** (оставлено обязательным, чтобы не ломать старые файлы). У предмета без графа — колода `zachetka::<имя предмета>::<deck>`, как раньше.
- Карточка без билетов у предмета с графом → `zachetka::<имя предмета>::00 Вне тем`.
- **Порядок новых карточек** (позиция `due` растёт в этом порядке по всему файлу `.apkg`): предметы как в `pack.yaml` → темы в каноническом порядке → место первого билета карточки в `tickets` темы → порядок карточек в пакете (`pack.cards`).
- История Anki не сохраняется (решение 15.11): перед первым импортом пользователь удаляет старую колоду `zachetka` целиком — иначе Anki оставит уже существующие заметки в старых колодах. GUID заметок не меняется (Р-13).
- В Python порядок не пересчитывается — `pack["graph"]` уже отсортирован:

```python
topics = {s["id"]: [t for t in pack.get("graph", []) if t["subject"] == s["id"]] for s in pack["subjects"]}
topic_of = {ticket: t for t in pack.get("graph", []) for ticket in t["tickets"]}
```

## Р-88. «Сегодня» — план дня от приложения {#today}

Экран строится из пакета и прогресса, без агента. Сверху — узкая полоса срочных сроков (`hotList`, не больше трёх строк и «ещё N» → `#sdachi`). Ниже — выбор предмета, очередь шагов с оценкой времени и одна кнопка **«Начать»** (ведёт к первому невыполненному шагу).

**Предмет.** Только предметы с графом. По умолчанию — `meta/day.subject`, если у него есть открытая тема; иначе предмет с ближайшим будущим экзаменом (`pack.exams`), у которого есть открытая тема; иначе первый такой по порядку `pack.yaml`. Смена предмета пишет `meta/day.subject` и сбрасывает `topic`, если шаги темы за сегодня ещё не отмечены.

**День.** `meta/day.date` — дата по Москве (как `core/today.ts`). Документ с другой датой = новый день: `done` пуст, `topic` выбирается заново, `subject` сохраняется.

**Шаги:**

| # | Шаг | Что показывает | Время | Отметка |
|---|---|---|---|---|
| 0 | Входной тест | только если у предмета есть пул и нет `meta/placement-<предмет>`; можно пропустить (пишется документ с пустым `asked` и `finishedAt`) | `placementMinutes` | наличие документа |
| 1 | Повторения | «Повтори карточки в Anki»; число — `meta/today.anki.due`, если `anki.at` — сегодня | `ceil(due × 8 с / 60)`, без числа — 10 мин | галочка → `done.anki` |
| 2 | Новая тема | название, билеты темы со ссылкой на теорию (`pack.theory`; нет теории — `src` билета), колода Anki, которую пора открыть (`topicDeck`) | `topicMinutes` | галочка → `done.theory` |
| 3 | Мини-проверка | 3 вопроса по теме | 2 мин на L0, 4 на L1 (Р-23) | конец прогона → `done.check` |

- **Тема дня** — `meta/day.topic`, если такая тема есть, она этого предмета и не `known`; иначе `nextTopics(…)[0]`, и она записывается в `meta/day`. Так тема не меняется посреди дня после мини-проверки.
- **Нет открытой темы:** все темы пройдены → шаги 2–3 заменяет строка «Темы предмета пройдены»; открытых нет из-за темы другого предмета → назвать её и предложить сменить предмет.
- **Вопросы мини-проверки** (`CHECK_QUESTIONS = 3`): кандидаты — `topicQuestions(pack, graph, topic)`; устойчиво сортируются: сначала без ответов, затем по возрастанию `questionValue`; из них берутся вопросы по одному на билет, пока не наберётся 3; не набралось — добираются следующие по этому порядку. Показываются в порядке `topicQuestions`.
- **Итог мини-проверки:** средний балл ответов ≥ 0,7 (`LEARNED_VALUE`) → отметка `learned` в `meta/topics`; иначе тема остаётся открытой и завтра снова будет темой дня. У темы без вопросов шаг 3 — кнопка «Отметить тему изученной».
- В строке темы — действие «уже знаю» (отметка `learned`) и, у пройденных тем в списке графа, «не знаю» (отметка `unknown`).
- План агента (`meta/today.plan`) и его заметка, если они на сегодня, показываются свёрнутым блоком «От агента» под очередью. Блок «Слабые билеты» с экрана уходит (он есть в `#ready`).
- **Уточнения реализации.** Пока входной тест не пройден, тема показана предварительно и в `meta/day` не пишется, шаги 2–3 отметить нельзя. Сохранённая тема дня заменяется также, если стала `locked`, или стала `learned` без пройденной сегодня мини-проверки («уже знаю», ответы в обычном тесте). «Ещё одна тема» (`oneMoreTopic`) после выполненного дня: тема уходит в `finished`, шаги 2–3 начинаются заново со следующей открытой темой, отметка Anki остаётся. Проваленную мини-проверку можно повторить в тот же день.
- Логика очереди — чистая функция в `core/plan.ts` (вход: пакет, граф, состояния, документы `meta`, дата; выход: шаги с минутами и признаком «сделано»), экран её только рисует.

## Р-89. Экран входного теста {#placement-screen}

В `#tests` у предмета с графом строка входного теста открывает тест по графу (Р-85) вместо линейного прогона: экран «≈ N минут, до 8 вопросов» → вопрос, поле ответа, «Показать эталон», самооценка → следующий; на каждом шаге «Хватит». В конце — итог: сколько тем «знал», какая тема первая к изучению, кнопка «К плану дня». Линейный прогон `kind: entry` остаётся только у предметов без графа.

Уточнения реализации (`ui/modules/graph/placement.tsx`): «Хватит» называется «Прервать и сохранить» — результат засчитывается сразу (`finishedAt`), а на экране итога есть «Продолжить тест», пока вопросов задано меньше 8 и остались неопределённые темы; выход кнопкой «назад» оставляет тест незаконченным, и шаг 0 плана предлагает продолжить. Документ пишется с первого ответа: открыть тест (или пересдачу) и уйти — ничего не меняет. На итоге — список тем с состоянием и кнопкой «уже знаю» / «не знаю» (`markTopic`: отметка хранится, только пока она что-то меняет). Тот же экран открывается из плана дня и из карты тем.

## Карта тем: `#map` {#map}

Отдельный маршрут `#map` (в навигации — «Карта», только если в пакете есть граф), а не раздел `#ready`: готовность — таблица «билет × уровень» по экзаменационным билетам, карта — порядок изучения; на телефоне два длинных списка на одном экране не читаются. Экран `ui/modules/graph/map.tsx`: выбор предмета; сводка (пройдено N из M, полоса и счётчики по состояниям, кнопка входного теста); темы в каноническом порядке — номер, название, состояние, число билетов и минуты, «требует: …» (пройденные зависимости зелёным), первая открытая помечена «следующая». Тема раскрывается: билеты (нажатие — теория в шторке), имя колоды Anki, сколько вопросов отвечено, «Мини-проверка», «Уже знаю» / «Не знаю». Мини-проверка с карты пишет `check-<тема>` и отметку `learned`, но шаги дня не трогает.

## Р-90. Совместимость и перенос {#migration}

- **Пакет без `graph/` собирается и работает как раньше**; графы добавляются по одному предмету. Формат пакета совместим назад: новое необязательное поле `graph`, `minutes` у `kind: entry` стало необязательным (версия MINOR).
- **Добавление графа предмету** одним коммитом требует: все билеты предмета разложены по темам (иначе ошибка). Пул можно переписать следом — до этого сборка даёт предупреждения, а входной тест задаёт только годные вопросы старого файла (L0/L1 с билетом из графа).
- **Старые прогоны** линейных входных тестов (`attempts` с `test: <id entry>`) остаются и считаются в готовности; в граф они попадают через «видно по ответам» (Р-83). Отдельного переноса нет.
- **Id вопросов** при переписывании пула: старый вопрос, который остаётся по смыслу, сохраняет id; новым — новые номера. Удалённые id не переиспользуются.
- **Anki:** старая колода удаляется руками перед импортом (Р-87); файл состояния `private/anki-built.json` сбрасывается, так как имя колоды входит в отпечаток карточки.
- **Ветки:** вся работа — в `task/ux-rework` от `main`, один PR, сливает пользователь (исключение из правила 1 [README](README.md) на эту волну).
