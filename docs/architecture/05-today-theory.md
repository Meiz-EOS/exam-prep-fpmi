## «Сегодня» {#today}

**Р-19.** Маршрут `#today` — первый экран. Блоки сверху вниз:
1. **План дня** — от агента, пункты можно отмечать;
2. **Горит** — как в «Сдачах» (`core/hot.ts`);
3. **Anki** — к повторению сегодня и самые забываемые билеты (сводку пишет агент);
4. **Слабые билеты** — 5 билетов с наименьшим значением из карты готовности (`core/ready.ts`), со ссылкой на тест/теорию.

План и сводка Anki — документ `meta/today` в прогрессе (решение 09.11), без перевыкладки страницы. На ПК (W5) агент пишет файл `<данные>/meta/today.json` (`today.ts --write`, [02#agent](02-data.md#agent)); на claude.ai писал через `ArtifactData update`:

```ts
// collection "meta", doc "today"
{ date: "2026-11-09",                      // на какой день план
  plan: [{ id: "p1", text: "АиГ: тест, вопросы 1–12", href?: "#tests", done?: true }],
  anki?: { at: ISO, due: 42, weak: [{ ticket: "matan-t-0207", lapses: 3 }] },
  note?: "…" }                              // короткая заметка агента
```
- Страница меняет только `plan[i].done` (отметка пункта).
- План не на сегодня показывается приглушённо с подписью «план на 08.11».
- Нет документа → блоки «План» и «Anki» не показываются.

## Теория {#theory}

**Р-20.** Файл `theory/<предмет>/<NN>.md`, секции по билетам:

```markdown
## aig-t-2601
### Формулировка
Ранг системы … (с $формулами$)
### Скелет
1. …
2. …
3. …
### Опирается на
aig-t-2204, aig-t-2602
```
- `Скелет` — 3–5 шагов (уровень L1, ГЗ-5 а); у определений его нет. `Опирается на` — необязательно.
- Источник — строки конспекта из `src` билета; страница показывает `src` текстом («algem.tex:3593–3596»), полный текст конспекта в страницу не встраивается (ГЗ-5 а).
- Проверка в сборке: билет существует и того же предмета, 3–5 шагов, ссылки «опирается на» — существующие билеты.
- Маршрут `#theory`: предмет → список билетов (ключевые сверху помечены) → билет в нижней шторке.
- Порядок контента (решение 09.11): **АиГ, затем матан**; внутри — сначала `key: true`.

## Карточки АиСД и C++ {#cards-programs}

**Р-21.** Конспектов в tex нет; карточки пишутся **по программе экзамена** и общим знаниям (решение 09.11). «Источник» — строка программы. C++-факты с кодом проверяются компилятором (`g++ -std=c++20`), как эталоны теста.

## Экзаменационные билеты: два уровня {#exam}

**Р-22** (решение 09.11). У предмета может быть файл `exam/<предмет>.yaml` — экзаменационные билеты (прогноз или официальная программа):

```yaml
tickets:
  - { id: matan-b-08, title: "Теорема Вейерштрасса о монотонной последовательности. Число e", confidence: sure, includes: [matan-t-0207, matan-t-0208] }
```
- `confidence`: `sure` | `likely` | `ours` | `doubtful` (как в прогнозе: ✔ ≈ ★ ?).
- `includes` — билеты-теоремы того же предмета; каждая теорема входит не больше чем в один экзаменационный билет. Пустой `includes` допустим (теорем ещё нет).
- **Карта готовности и пороги уд/хор** у такого предмета считаются **по экзаменационным билетам**:
  - значение билета на уровне = среднее значений его теорем, у которых есть ответы;
  - «освоено» = `includes` не пуст и все его теоремы освоены на этом уровне;
  - билет ключевой, если ключевая хоть одна его теорема (для `keyL2`).
- Теоремы вне экзаменационных билетов показываются отдельной группой «Вне билетов».
- Предмет без файла `exam/` считается по билетам-теоремам, как раньше.
