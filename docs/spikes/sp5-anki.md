# SP-5. Конвейер Anki: genanki, импорт, повторный импорт, чтение истории

Дата: 2026-11-08 · Карточка: W2-02 · Проверяет Р-14 ([04#cards](../architecture/04-knowledge.md#cards))

Версии: Python 3.12.3, `anki` 26.9.4 (тот же Rust-бэкенд, что в Anki 26.09; импорт — `Collection.import_anki_package`, то есть тот же путь, что у «Файл → Импорт» на ПК), `genanki` 0.13.1, `protobuf` 7.36.2. Всё — во временных коллекциях `$SP5_DIR` (по умолчанию — временная папка системы); профиль пользователя и GUI Anki не трогались. GUI-проверок нет: то, что требует окна Anki (отрисовка MathJax, поведение открытого Anki), выведено из поведения библиотеки и помечено так.

Подготовка: `python3 -m venv tools/anki/.venv && tools/anki/.venv/bin/pip install -r tools/anki/requirements.txt`. Скрипты — `tools/anki/spike/` (временные), запуск из корня репозитория: `tools/anki/.venv/bin/python tools/anki/spike/<имя>.py`.

Тестовый пакет: колода `zachetka::матан::Пределы`, тип заметки «Зачётка: вопрос-ответ» (`model_id` фиксирован), поля Вопрос / Ответ / Источник, GUID = `genanki.guid_for(sha256("matan-spike:<card id>"))`, три заметки, в одной формула `\(\lim x_n=a \iff …\)`. Второй пакет: 0001 — текст правлен, 0002 — удалена, 0004 — добавлена.

## 1. Повторный импорт `.apkg` с теми же GUID

Воспроизвести: `q1_import.py` (варианты `--mode=ALWAYS`, `--mode=NEVER`, `--fsrs`), `q4_edits_notetype.py`.

| Вопрос | Ответ | Цифры |
|---|---|---|
| Первый импорт | создаёт колоды `zachetka`, `zachetka::матан`, `zachetka::матан::Пределы` (родители автоматически), тип заметки с тем же id, 3 заметки и 3 карточки | `new: 3` |
| Тот же `.apkg` импортируется второй раз | **дублей нет**: `duplicate: 3`, заметок 3, тип заметки один (id `1700000000001`), колоды те же | `new: 0` |
| Текст обновляется при реимпорте | **да** (`update_notes` = «если новее», по умолчанию, или «всегда») | v2: `updated: 2, new: 1`; у 0001 Вопрос заканчивается на « [ПРАВКА]» |
| Сохраняются `revlog`, `due`, `ivl`, `reps`, `lapses`, флаг | **да, всё сохраняется** (после 2 ответов у 0001, 2 у 0002, 1 у 0003 + оранжевый флаг у 0003) | `revlog` до/после: 5 → 5 строк, идентичны; `due`/`ivl`/`reps`/`lapses`/`flags` у всех трёх карточек до и после равны |
| FSRS-состояние (`cards.data`: `s`, `d`) | сохраняется | при `--fsrs`: `{"s":2.3065,"d":2.111,…}` на месте после v2 |
| Заметка, удалённая из нового пакета | **остаётся в коллекции нетронутой**: заметка, карточка, `revlog`, `due` | после v2: заметок 4 (3 старых + 1 новая), 0002 с `reps=2` на месте |
| Новая заметка | добавляется как новая карточка (`type=0`) | 0004 появилась |
| `updated: 2`, хотя изменена одна заметка | `genanki` ставит всем заметкам `mod` = время сборки, поэтому «новее» оказываются все пересобранные; обновление без изменений безвредно, но затирает правки из Anki (см. ниже) | 0003 текст не менялся, но в `updated` |
| `update_notes=NEVER` | текст не обновляется (`duplicate: 2`), новая заметка добавляется | |

**Правка в Anki против реимпорта** (`q4`, (a)): при `IF_NEWER` заметка, правленная в Anki **после** сборки `.apkg`, остаётся (`duplicate: 1`, текст «ПРАВКА ИЗ ANKI»); заметка, правленная **до** сборки, перезаписывается пакетом. `ALWAYS` перезаписывает всегда, `NEVER` — никогда. Так как `genanki` штампует время сборки, **любая пересборка пакета затирает правки автора из Anki** (С-3а) для всех заметок, попавших в пакет.

**Параметры импорта** (`ImportAnkiPackageOptions`): `update_notes` (если новее / всегда / никогда) — решает судьбу текста; `update_notetypes` и `merge_notetypes` — судьбу типа заметки; `with_scheduling`, `with_deck_configs` — для пакетов из самого Anki (в `genanki`-пакете расписания нет). Тип заметки (`q4`, (c)), каждая проба в свежей коллекции:

| Изменение типа с тем же id | `merge_notetypes=False` | `merge_notetypes=True` |
|---|---|---|
| только шаблон | тип обновлён при «если новее»; при `NEVER` не обновлён (`afmt` остаётся старым); заметки обновились | то же |
| **добавлено поле** | **создаётся второй тип** «Зачётка: вопрос-ответ+» с новым id, `conflicting: 3`, заметки не обновились | один тип, поля 3→4 при «если новее»; при `NEVER` поля 4, шаблон старый |

Следствие для сборщика: менять набор полей типа заметки нельзя без `merge_notetypes=True` (иначе дубль типа). **Рекомендуется** импортировать с «если новее» + «объединять типы»; поля «Вопрос/Ответ/Источник» не менять.

**Пересечение с Р-14:** строка «повторный импорт с теми же GUID обновляет текст, история остаётся» **подтверждена**. Но две вещи в Р-14 не сказаны:
1. Удалённая из пакета карточка **не исчезает** из Anki (остаётся с историей). Вопрос автору: этого хватит, или нужен шаг «агент по `guid` находит заметки, которых нет в пакете, и предлагает удалить / пометить тегом `zachetka-removed`»? Правило Р-13 «удалённая карточка свой id не отдаёт» сохраняется в любом случае.
2. Пересборка затирает правки из Anki. Вопрос автору: правка текста в Anki (С-3а) должна возвращаться в `cards/*.md` агентом до пересборки (агент читает `notes` из копии, см. п. 2), или правим только в `.md`? Возможное смягчение: в пакет попадают только изменённые карточки.

## 2. Чтение `revlog`, `cards`, `notes`, флагов из копии `collection.anki2`

Воспроизвести: `q2_read_sqlite.py`. SQL (простой `sqlite3`):

```sql
-- история ответов (id = время ответа в мс; ease 1=Снова 2=Трудно 3=Хорошо 4=Легко; ivl<0 — секунды)
select datetime(id/1000,'unixepoch') ts, cid, ease, ivl, lastIvl, factor, time ms, type from revlog order by id;
-- карточки + GUID заметки (GUID связывает с id из Р-13), флаги: 0 нет, 1 красный, 2 оранжевый, 3 зелёный, 4 синий…
select c.id, n.guid, c.did, c.type, c.queue, c.due, c.ivl, c.reps, c.lapses, c.flags, c.data
  from cards c join notes n on n.id=c.nid order by c.id;
-- заметки: поля через разделитель \x1f, теги — строка с пробелами по краям
select n.guid, n.tags, n.flds, n.mod from notes n;
```
Колоды: `select name from decks` — иерархия хранится с разделителем `\x1f`, а не `::`. Первые поля `type`/`queue`: 0 новая, 1 обучение, 2 повторение. При FSRS в `cards.data` лежат `s` (стабильность) и `d` (сложность).

| Состояние | Что видно в копии | Измерено |
|---|---|---|
| Anki закрыт | всё в одном файле `collection.anki2`, `-wal` нет; режим журнала `wal` сохранён в файле, но данные уже внесены | после закрытия: `collection.anki2` 139 264 байт, без `-wal` |
| **Anki открыт** | основная часть файла почти пуста, **данные лежат в `collection.anki2-wal`** | `collection.anki2` 4096 байт, `-wal` 325 512 байт |
| копия только `collection.anki2` при открытом Anki | **таблиц нет**: `no such table: revlog` | ошибка |
| копия `collection.anki2` + `collection.anki2-wal` рядом | читается полностью, последние ответы и флаги видны | `revlog=2`, флаги `[3,0,0]` |
| чтение оригинала `?mode=ro` / `sqlite3.Connection.backup()` | работает, согласованный снимок, писателя не блокирует | то же значение |

Вывод (по поведению библиотеки, GUI не запускался): Р-14 говорит «копия при закрытом Anki». Это **верно, но слишком узко**: при открытом Anki читать можно, если копировать вместе с `-wal` (`-shm` не нужен). Надёжный способ — `sqlite3 file:…collection.anki2?mode=ro` + `Connection.backup(...)` в копию: согласованный снимок при любом состоянии Anki. Копирование трёх файлов командой `cp` во время записи Anki может поймать рваный снимок. Что в копии отсутствует, пока Anki открыт: ничего из подтверждённого, но Anki сбрасывает WAL в основной файл только при закрытии/синхронизации, так что «копия без -wal» тихо отдаст пустую или устаревшую базу. AnkiConnect не нужен — вывод Р-14 подтверждён.

## 3. FSRS и колода/пресет, переносит ли его `.apkg`

Воспроизвести: `q3_fsrs.py`.

| Вопрос | Ответ | Цифры |
|---|---|---|
| Где включается FSRS | **глобально для коллекции**, не на пресет: ключ конфигурации `fsrs` (`col.set_config("fsrs", True)`; в окне — «Параметры колоды → FSRS»). В пресете лежат `desiredRetention` и параметры `fsrsParams6` | до: `None`, после: `True`; в пресете нет ключа-флага |
| Расчёт при FSRS | ответы пишутся в `cards.data` (`s`, `d`, `dr`) и в `revlog` | см. п. 1 |
| `.apkg` от `genanki` несёт настройки | **нет**: в `collection.anki2` один пресет `Default` без FSRS-ключей (`dconf` без `fsrs*`/`desiredRetention`); колоды попадают в `Default` получателя | содержимое: `collection.anki2` + `media`; ключи `dconf` без `fsrs` |
| `.apkg`, экспортированный самим Anki, несёт пресет | **да**, при `with_deck_configs=True`: импорт создал пресет «Зачётка FSRS» с `desiredRetention=0.85` и 21 параметром и назначил его колоде; без этой опции — `Default` | `[('Default',0.9,0),('Зачётка FSRS',0.85,21)]` против `[('Default',0.9,0)]` |
| Переносится ли глобальный флаг `fsrs` | **нет** (после импорта `None`) | |

Вывод: автор включает FSRS и желаемую запоминаемость один раз в Anki вручную (в пакете это не задать). Проверка: Р-14 про это молчит, противоречия нет. Совет Р-13 «только Снова/Хорошо» от FSRS не зависит.

## 4. Имена колод и типов заметок, дубли

Воспроизвести: `q4_edits_notetype.py` (блок (b)), `q5_mathjax.py`.

| Вопрос | Ответ |
|---|---|
| Дубли типа заметки при втором импорте с тем же `model_id` | **нет**: один тип «Зачётка: вопрос-ответ» (id `1700000000001`); дубль с суффиксом «+» появляется только при изменении набора полей и `merge_notetypes=False` (п. 1) |
| Дубли колод | нет: `zachetka`, `zachetka::матан`, `zachetka::матан::Пределы` по одной; пустая `Default` в новой коллекции есть всегда |
| Колоду `zachetka::матан::Пределы` и родителей создаёт сам импорт | да (по имени с `::`; `deck_id` фиксируем, чтобы колода не менялась) |
| GUID | стабилен между сборками (`jic6ew&G1h` для 0001 во всех запусках); оставляем `sha256("pack:cardid")` |
| MathJax `\(…\)` | поле хранится как есть; `render_output()` отдаёт `\(\lim x_n = a …\)` нетронутым в HTML вопроса/ответа, дальше его обрабатывает MathJax Anki (**отрисовка в окне не проверена**, GUI не запускался). Замечание сборщику: в поле лежит сырой `<` (`|x_n-a|<\varepsilon`); редактор Anki сам пишет `&lt;`, поэтому при переводе `$…$` → `\(…\)` экранировать `<`, `>`, `&` в `&lt;`/`&gt;`/`&amp;` |

## Итог для Р-14

- Подтверждено: `genanki` → `.apkg` → импорт; повторный импорт по GUID обновляет текст и **сохраняет** `revlog`, `due`, интервалы, флаги, FSRS-состояние; без AnkiConnect; чтение `revlog`/`cards`/`notes` из копии.
- Уточнить в Р-14: (а) читать копию вместе с `-wal` или через `sqlite3` backup — «при закрытом Anki» не обязательно; (б) импорт с «если новее» + «объединять типы»; (в) FSRS включается вручную один раз и не переносится пакетом.
- Вопросы пользователю: удалённые из пакета карточки остаются в Anki — удалять ли их (и как); пересборка затирает правки из Anki — правим только `.md` или возвращаем правки из Anki в `.md` перед сборкой.
