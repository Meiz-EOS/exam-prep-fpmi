# ADR-0001. Язык и сборка движка

- **Статус:** принято 07.11.2026 (пользователь выбрал A). Уже решено: UI на Preact, контент в Markdown + YAML (07.11).
- **Контекст:** [functional-spec.md](../functional-spec.md) v0.3: Н-7 и Н-8 (MVP на claude.ai, потом своё PWA, переносимость), А-5 (чистая логика с тестами).

## Что требуется от стека

| # | Требование | Откуда |
|---|---|---|
| Т-1 | Собирать **один HTML-файл**. Страница claude.ai надёжно принимает только его, внешние скрипты — лишь с разрешённых CDN | Н-7 |
| Т-2 | Из того же кода собирать **PWA**: service worker, манифест, офлайн | Н-7, E-9 |
| Т-3 | Тесты чистой логики (сроки, уровни, разбор контента) **одной командой** | А-5 |
| Т-4 | Проверять **форматы данных**: курс-пакет, прогресс, адаптеры. Ошибка в поле не должна молча ломать страницу | Н-8, А-3 |
| Т-5 | Собирать **курс-пакет** из Markdown/YAML в JSON с проверкой | решение 07.11 |
| Т-6 | Код правят агенты с ограниченным контекстом. Ошибка должна ловиться до запуска, а не на телефоне | процесс |
| Т-7 | Минимум зависимостей и обслуживания. Проект живёт годами, его копируют другие студенты | цель 5 |

Окружение: Node 26, npm 11. Bun и Deno не установлены.

## Варианты

### A. TypeScript + Vite
Компоненты на Preact в `.tsx`. Сборка: Vite с `@preact/preset-vite`, один HTML через `vite-plugin-singlefile`, PWA через `vite-plugin-pwa`. Тесты: Vitest.

| Плюсы | Минусы |
|---|---|
| Типы ловят ошибки форматов и адаптеров при сборке (Т-4, Т-6) | Около 150–250 пакетов в `node_modules`, их нужно обновлять (Т-7) |
| Vite — стандарт для Preact, самая известная агентам связка, много примеров | Код нельзя запустить, не собрав: даже простую правку нужно собрать |
| Один и тот же код: одна команда — HTML для claude.ai, другая — PWA (Т-1, Т-2) | Синтаксис TS: для тех, кто знает только JS, порог входа чуть выше |
| Vitest использует ту же конфигурацию: тесты логики и компонентов (Т-3) | |
| Горячая перезагрузка при разработке | |

### B. JavaScript + типы в JSDoc + Vite
Тот же Vite, Preact и Vitest, но файлы `.js`/`.jsx`. Типы записываются в комментариях JSDoc и проверяются `tsc --checkJs` отдельной командой.

| Плюсы | Минусы |
|---|---|
| Почти те же проверки, что в A, но код — обычный JS | Типы в комментариях многословнее и хуже читаются; сложные типы писать неудобно |
| Модуль можно запустить в Node без сборки (удобно для логики и скриптов) | Проверка типов — отдельный шаг, её легко пропустить |
| Те же сборка в один HTML и PWA, что в A | Зависимостей столько же, сколько в A |

### C. TypeScript + esbuild, без Vite
Сборка своим коротким скриптом на esbuild: собрать модули, вставить в HTML. PWA — свой service worker. Тесты: `node --test` (Node 26 запускает `.ts` сам).

| Плюсы | Минусы |
|---|---|
| Мало зависимостей: esbuild, preact, typescript и парсер YAML (Т-7) | Сборку в один HTML, PWA и service worker пишем и поддерживаем сами |
| Очень быстрая сборка, весь процесс в одном понятном скрипте | Нет горячей перезагрузки (или своя) |
| Тесты встроены в Node, без отдельного фреймворка | Меньше готовых решений; агенту нужно читать наш скрипт, а не известную конфигурацию |

### D. Чистый JS без сборщика
ES-модули, свой скрипт склеивает их в один HTML, Preact через `htm` (JSX без компиляции). Тесты: `node --test`.

| Плюсы | Минусы |
|---|---|
| Почти без зависимостей, всё видно и запускается сразу | Нет типов: ошибки форматов всплывают только при запуске (против Т-4, Т-6) |
| Самый простой старт, похоже на прототип v0 | Для PWA сборщик всё равно понадобится — переделка на этапе E-9 |
| | Склейку модулей и порядок загрузки поддерживаем сами |

### E. Bun (TypeScript, сборка и тесты в одном)
Bun — среда выполнения, сборщик и тесты в одном инструменте.

| Плюсы | Минусы |
|---|---|
| Один инструмент вместо трёх, быстрый, TypeScript «из коробки» | Не установлен; другим студентам тоже придётся ставить |
| Встроенный `bun test` | Готовых решений для PWA и одного HTML меньше, чем у Vite; путь менее проторён |
| | Моложе Node: выше риск, что что-то сломается при обновлении |

## Сравнение

| | A. TS + Vite | B. JS + JSDoc + Vite | C. TS + esbuild | D. Чистый JS | E. Bun |
|---|---|---|---|---|---|
| Ошибки форматов ловятся до запуска (Т-4, Т-6) | да | да, если не пропустить проверку | да | нет | да |
| Один HTML для claude.ai (Т-1) | плагин | плагин | свой скрипт | свой скрипт | свой скрипт |
| Путь к PWA (Т-2) | плагин | плагин | вручную | переделка | вручную |
| Тесты (Т-3) | Vitest | Vitest | `node --test` | `node --test` | `bun test` |
| Зависимости (Т-7) | много | много | мало | почти нет | мало, но новый инструмент |
| Знакомо агентам | лучше всех | хорошо | хорошо | хорошо | средне |
| Стоимость старта | низкая | низкая | средняя | самая низкая | средняя |

## Рекомендация

**A (TypeScript + Vite).**
- Это единственный вариант, где и один HTML для claude.ai (Т-1), и PWA (Т-2) — готовые плагины, а не наш код.
- Типы закрывают главный риск проекта: агенты правят форматы данных, и ошибка должна ловиться при сборке (Т-4, Т-6).
- Цена — много зависимостей (Т-7). Её снижают зафиксированные версии (`package-lock.json`) и обновления раз в семестр.

**Запасной вариант — C,** если важнее минимум зависимостей, чем готовые плагины.

## Решение

**A: TypeScript + Vite** (`@preact/preset-vite`, `vite-plugin-singlefile` для claude.ai, `vite-plugin-pwa` на этапе E-9, Vitest). Версии фиксируются в `package-lock.json`, обновление — раз в семестр.
